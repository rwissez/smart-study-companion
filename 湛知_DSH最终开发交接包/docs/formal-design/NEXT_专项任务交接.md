## 已确认的 Agent 行为

- 支持个人分析、班级分析、知识定位、计划查询、计划修改、概念辅导、数据质量及学习进展。按有效任务分解复合请求；超范围/含糊时走适当澄清或停止。
- 使用后端会话身份与工具白名单双层校验。学生限本人数据和当前授权课程，不可修改正式方案、读班级或数据质量；教师的查询与修改范围分别验，班级查可用成果不能自动授权批量写。
- 教师明确单人指令可直接提交受控修订；模糊或批量操作先确认具体目标、版本、变更。确认绑定会话、目标和摘要，不能把聊天历史当凭证。撤销用新修订。
- 关键结论有正式证据和版本可点击，部分结果与失败真实呈现。进度来自实际工具阶段；工具仅提供角色允许字段，证据不足不补造，模型不可用不返回伪造回复。
- 工具读取 A/B/C 正式成果。Agent 不另算掌握、策略、选题和审核；动态帮助调用授权的活动上下文，防泄答并写统一事件。落库与导出留存证据和真实操作，不带密钥或内部推理。

## C 新协议对 Agent 的影响

计划查询以正式 CPlan/PlanView 为准，能识别 publication_basis、review_status、局部暂停和旧活动保护。Agent 只能 submit_agent_revision，不能调用正式编辑器的 preview/publish 直发机制；教师直接编辑确认在 Web 实现，显示 human_confirmed。OperationResult 需如实反映异步 job 和实际发布，待审核不能报已发布。教师意图受保护，必要冲突可在响应中引用具体案由和编辑器入口，不自行解除。

micro_lesson 独立活动有 content_ref 与不可变 content_version；Agent 读学生安全视图，不能把 generated lesson 当成教材或正式题、不能把微课堂阅读当掌握。三级预设提示由 C 提供，动态帮助由 Agent 実际提供后记录 agent_help_used，关联学生、计划、活动和尝试。若学生在独立补证动作中请求帮助，遵循 C 的提示门控与 B 独立性判定。避免跨同题重复活动释放答案，访问缓存按权限/活动绑定。
