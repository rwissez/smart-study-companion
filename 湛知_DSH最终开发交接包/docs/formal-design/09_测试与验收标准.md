## 1. 分层与结论记录

| 层 | 方法 | 判定依据 |
|---|---|---|
| 基础技术 | 自动化 | 干净构建、迁移、OpenAPI/TS、事务、任务、权限，预期值逐项一致 |
| 模块算法 | 自动化＋复核 | A 核验来源，B 分子分母精确，C 基于依据与审核，Agent 调用及授权 |
| 真实模型 | 实际调用＋人工抽查 | 区分未配置、受控假输出、真实 DeepSeek；真实运行关注数学正确、引用及输出校验 |
| 业务闭环 | 后端集成＋真实双端运行 | 校验数据从来源、版本、事件、任务、正式发布到成果包的标识及因果 |
| UI | 自动化操作＋实际截图＋人工 | 网页真实 API 状态、三尺寸、07 视觉与键盘，图表、数学、证据 |
| 比赛成果 | 人工核查＋验证脚本＋实机 | 从干净环境，真数据形成正式、可审验的 ZIP，三学生两班、现场演练 |

一条测试允许多种证据，但标记模式 synthetic/rule/mock_model/authorized_real/model_real/visual_review，保留输入版本、Git SHA、环境、命令、时刻、输出和授权限制。结果只取 passed/failed/blocked/not_run/not_applicable；最后一种必须有规范理由，核心用例失败或未执行不能签通过。缺模型或赛料权限标 blocked，保留已完成规则与合成结论。人工核查记录选中样本、审核人、依据与问题；不保存密钥、未授权作答全文或模型隐性推理。

## 2. 执行入口与测试数据

在 DSH 独立工作区，设独立 SQLite、资料目录、输出路径和端口。本地依赖版本来自锁文件。GitHub D 当前 scripts 提供 npm run typecheck/build、vitest、npm run test:e2e，浏览器脚本可设 BROWSER_EXECUTABLE。D 旧脚本偏演示，正式 E2E 必须扩充真实 API 场景。以下命令是执行模板，路径须在 P0 核验；P1 后新增 tests 目录/测试节点须真实注册，以 pytest --collect-only 或测试清单验证。严禁空目录、空套件或缺浏览器返回成功。

Push-Location frontend
npm ci

npm run test:e2e
Pop-Location
~~~

后端用 uv run uvicorn study_companion.main:app --host 127.0.0.1 --port 8000，Web 用 npm run dev 或构建后 npm run preview，真实 Web 以07配置的 VITE_DATA_SOURCE=api 启动。检查 GET /api/v1/health 和 /api/docs；使用现行包络比对响应，不把旧 D schema_version=1.0 当最终。测试中启动三个数据库副本（空、main 旧头、D 旧头），每份使用实际 Alembic 历史产生。部署说明给出目标机版 PowerShell 或等价终端。Python 项目已有单测启动入口，若无 linter 不编造已配置命令，至少执行构建、编译/静态检查及该仓库实际配置的规则。

可复现夹具：

- **S 基础**。合成 F1/F2 两个 family，各含 S01。F1 另含 S02（另一班）与 S03（无记录），两个节点 N01/N02，同一目录登记 Q1/Q2/Q3，满分均5。S01 在 N01 给 Q1=5、Q2=0、Q3 pending，均为不同事件；Q1 有 R1 已评分与 R2 pending 的修订子场景。S03 不造作答。T1 教师仅授权 F1 的一班，T2 授权两班，U1 绑定 S01；所有身份由受控服务建立。
- **K/P 版本**。A1/A2（纯名称兼容与必要关系语义变更两个样本）；B2/B3；C2 源 B2，含学习卡 M、微课堂 L、正式题 Q1 与独立 Q2，固定 group/plan/activity/attempt ID 与一个进行中旧活动。C2 复查 B3 仍适用及不适用两路径。有已发表、待审核、冻结预览以及失效预览。
- **E 假模型**。合法结构、错误引用、额外字段、超时、无工具、无权目标、数学错、泄答风险；使用受控 provider 并记录模型类型；同一输入可复现。不可用网络场景可用替代 transport 验证业务恢复，真实调用另行验证。
- **R 正式赛方**。只在授权范围处理原始公开开发资料，预检实际文件哈希、字段/版本、范围及数据使用条件。公开集预期以赛方资料及实际解析为准（40 人、2 班、2 节点、806 原始作答行含修订）；独立评测按另行文件，不能按公开数据规模硬编码。典型案例由教师/团队择取，禁止随机预设三学生或虚构行为。外发前验授权，未许可不发送赛事原文与学生记录，真实模型可用被允许的合成或本地输入单独举证，真实比赛数据运行仍需验证。

## 8. 严重度、放行与复测

- **S0** 例如越权、泄密、错误统计、跨数据混用、正式记录造假或恢复覆盖原库。阻断一切依赖的正式验收和交付。
- **S1** 核心缺失、流程失败、重要视觉受损、关键接口不一致。阻断受影响阶段出口和最终交付。
- **S2** 局部非核心交互/显示缺陷。评估范围，形成记录及限制，若实质阻断核心则升级。
- **S3** 不影响核心功能的细微问题。保存证据和处理记录。

阶段由08规则自动推进，不逐阶段等待人工授权。视觉最终审美与赛方代表性案例仍需实际产品审查，作为 P7 最终证据，不阻断此前独立开发。每个 S0/S1 给出定位、最小修复与受影响测试重跑。验收提交统一记录自动、真实以及人工三路，全部必需用例通过、无 S0/S1 和未解决的核心契约，具备干净部署与可核对真实成果，才可签交付通过。未测保留真实状态。验收结论应注明范围和 SHA，不能推断无缺陷。
