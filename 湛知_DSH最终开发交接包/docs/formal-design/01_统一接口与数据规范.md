## 0. 执行纪律与阅读方式

先读 00，再读本文件。本文只定义跨模块共享契约、外部 HTTP 接口、状态、兼容规则和校验要求。具体算法、提示词、阈值、数据库迁移及 UI 由 02—09 指定。不要根据本文件一口气改造所有模块；按 08 的任务范围分阶段执行。算法未定时可以实现契约与合成测试夹具，但不能填入伪造算法、固定诊断或未批准默认参数。若专项设计需改变共享契约，先提交接口变更说明并同步更新消费者与测试。

文中 `T?` 表示 `T | None`，`[T]` 表示 `list[T]`，`enum(a,b)` 表示封闭字符串枚举。字段默认必填；写明 `=null`/`=[]` 才表示允许缺省，数组用 default_factory。ID 类型统一非空字符串。所有 JSON 对象均应落实为 Pydantic v2 模型；表中省略的已有字段必须保留，不能据此删字段。业务对象不允许额外字段；原始行、受控供应商消息、明确的扩展元数据是有限例外。新增目标对象名称可按现有目录拆文件，但对外导入路径应兼容；不能在多个模块复制定义。

## 2. 共用基本类型、身份、版本与唯一来源（I-02、03、05、07、09）

### 2.1 基本约定

- UTF-8（CSV 接受 UTF-8 BOM），snake_case，ID 字符串不转 int、不按已知前缀限制；空值 `null`，无集合 `[]`，比例 0—1，分数整数（当前官方口径），时间 ISO 8601 含偏移，日期 YYYY-MM-DD。入库时间 UTC，可展示用户/原数据时区。不得据提交时间推断答题耗时。
- 所有生成 ID 服务端生成 UUID 字符串；已存在 ID 原样保留。外部学生、题目、课程编号保留原值；必要校验仅非空、长度及安全编码，不能强行匹配 D01/Q001。路径和 SQL 通过参数绑定，不拼接。ID 不作为用户可见标签，学生原始编号可显示；班级用名称或明确映射标签，题目以展示顺序/题干摘要识别。详细证据可显示有用的教材页码，但不堆叠内部编号。
- `dataset_id` 是不可变输入快照标识。新增 `dataset_family_id` 是经明确确认的同一持续数据集身份空间。学生身份键 `(dataset_family_id, student_id)`；数据库可给稳定 `student_uid` 内部键；同一系列 D01 永远是同一名学生，跨测验、补充数据、练习及版本贯通。独立评测创建新 family，即使 D01 相同也不合并。无法判断来源先待教师确认，不自动猜测。原 `(dataset_id,student_id)` 外键仍用于快照成员记录；迁移详见 06。班级成员关系按快照留存，不能用当前班级覆盖历史；材料/节点/指标等编号也按所属数据集/目录解析。
- `RunContext` 保留 run_id,dataset_id,catalog_version,rule_version；新增 `dataset_family_id`（新记录必填，旧记录经映射补齐）、`knowledge_version: ID?=null`。`catalog_version` 表示题库/课程目录快照，`knowledge_version` 表示 A 的正式知识体系，不强求相同。`run_id` 标识一次 B 计算批次，不等于学生版本。
- `StudentResult` 与 `ClassResult` 加 `analysis_version: ID`（旧记录可确定性迁移生成）、`analysis_input: AnalysisInputRef`、`publication_status`。`AnalysisInputRef`：dataset_id, catalog_version, knowledge_version?, rule_version, config_hash, `event_cutoff: int>=0`（全局单调账本 offset 上界，消费必须限定实际数据系列及对象）, `included_event_ids:[ID]`（06 可将物理清单独立存储，但共享 DTO 保留此字段及原语义），`created_at`。原有 run_id 和 node_id 保留；新增 `scope_kind=enum(assessment,learning_current)`；测验使用现有 node_id，当前综合画像使用已存在、服务端登记的教学上下文 node_id 并标明 scope_kind，不能伪装成某次测验原始分数。每条证据保留自身历史节点。
- `RecommendationBundle` 增加 `plan_version: ID`, `analysis_version: ID`, `knowledge_version: ID?`, `parent_plan_version: ID?`, `revision:int>=1`, `publication_status`, `created_at`。教师调整基于明确的 base_revision 和 plan_version；旧 run_id 字段不被替换。
- 正式状态：JobStatus=queued/running/succeeded/failed/cancelled，其中 cancelled 用于支持安全取消的任务；ReviewStatus 保留 draft/validated/needs_review 并增加 rejected（候选不可使用）；PublicationStatus=unpublished/published/superseded。正式读取须有当前明确发布指针及相应发布资格。A/B 保留原有规则，C 自动与 Agent 修订要求 validated，教师编辑器直发采用 human_confirmed。历史曾发布版本可在授权历史查询显示，绝不能当作当前新方案。新的 job 成功不代表发布成功。失败保留仍适用的历史，显式提示过时及原因。

### 2.2 版本依赖和单一业务来源

A 输出不可变正式知识版本与材料关联；B 保存实际采用的 A/目录、数据快照、作答清单、算法版本和配置；C 保存实际依赖的 A、B 个人版本以及活动历史截点。不得将新 A 版本强行标到旧 B 结果上。局部更新只产生受影响个人/班级版本；旧结果保留。班级汇总记录 `member_analysis_versions:[{student_id,analysis_version}]` 及统计范围，不等于所有学生需要重新计算。正式查询返回 `freshness=enum(current,compatible_history,stale)` 和 `limitations:[str]`，依赖不适用时不得继续自动生成/发布 C。对仅改名称等无语义变化，保留原依赖，记录兼容性判断，UI 可读取经过核对的展示名称映射。依赖检查与发布事务见 06 §§2—4。Plan 读取可附 applicability:PlanApplicabilityView 与当前未复核 limitation；现有 freshness 枚举保持，已证明旧版适用为 compatible_history，待核验/局部暂停为 stale 并精确标范围。PlanApplicabilityView={applicability_id,plan_version,origin_analysis_version,current_analysis_version,knowledge_version,catalog_version,checked_at,event_cutoff,result:applicable/limited/incompatible,activity_ids:[ID],evidence_refs:[EvidenceRef],limitations:[str]}。原计划生成依赖从计划读取，复查不得改写它。

所有正式数字由 B 生成；前端只显示和格式化，C/Agent/导出读取正式结果；不是要求每个核心函数自行连 SQLite。仓储/服务读取一次并装配成共享对象，纯业务函数使用显式输入，不直接操作 HTTP/数据库。严禁在 React、Agent、导出中重算另一份得分率或另存学生画像。缓存键包含 session、dataset/family、run、对象、node、正式版本及访问阶段；切换范围清除旧请求结果。

## 3. 上传、原始表与标准化契约（I-01、02、09、10）

### 3.1 六表字段映射（真实表头已核对）

保留 RawTables 六个列表。RawRow 字段是原始字符串或 null，附 source_row_number（数据行从1开始，不含标题；物理文件行号另存，CSV 多行字段不能以换行数代替）。RawTables 不把原始字符串转数字；转换在 B prepare 或 A 目录构建进行。原始文件按上传批次保存内容哈希、原名、相对路径、来源格式、sheet/行号；原始单元格不被清洗覆盖。标准化空值在可选字段统一为 null，必填缺失按质量规则处理。文件名非唯一识别条件，按工作表/表头分类，未知映射待教师确认。

### 3.2 统一上传接口与去重

新入口 POST `/api/v1/imports` multipart：`files` 多文件，`metadata` 为 JSON 文本，模型 ImportRequest={intent:enum(new_family,append_to_family,auto_detect),dataset_family_id:ID?=null,expected_parent_dataset_id:ID?=null}。接收六 CSV 或一份 XLSX（仅对应六工作表，额外说明表保留为说明），可同时上传课标/教材 PDF；允许分批。识别状态 `classification_status=enum(confirmed,needs_confirmation)`，完整性 `input_status=enum(incomplete,ready,blocked)`；只有已确认且依赖满足才执行相应业务。返回 ImportReceipt={import_id,dataset_family_id?,dataset_id?,classification_status,input_status,files:[ImportFile],missing_inputs:[str],quality_summary:dict[str,int],job_id?,warnings:[Warning]}；ImportFile={file_id,original_name,sha256,byte_size:int,format:enum(csv,xlsx,pdf),role:enum(requirements,materials,students,nodes,records,dictionary,standard,textbook,unknown),sheet_name?,status:enum(accepted,duplicate,needs_confirmation,rejected),reason?}。XLSX 一个物理 file_id 可对应多 sheet 映射（每项 role/sheet 唯一）。确认请求 POST `/imports/{import_id}/confirm` {file_mappings:[{file_id,sheet_name?,role}],intent,dataset_family_id?,expected_parent_dataset_id?}，返回同 Receipt；GET `/imports/{import_id}` 返回状态。重复确认幂等。未知/不完整上传可以待处理，不伪造已完成数据集。

保留 D 的 POST `/datasets` 六 multipart 字段及返回 dataset_id/catalog_version/node_ids，内部调用同一导入服务，不能绕过新分类/权限/原始数据留存；旧调用者如缺 PDF 可完成数据快照/基础目录构建，不能将未构建 A 正式知识标为已完成。旧前端适配状态提示。禁止文件路径由客户端传任意磁盘绝对地址。PDF 仅本地受控读，不自动远传；XLSX 不执行公式/宏/外链，关键字段公式或不可靠缓存拒绝或报错。设文件大小/数量限制、页数与解压安全限制，具体可配置值由部署设计确定，越限 413；不接受可执行或任意压缩文件。

去重分两层：物理 SHA-256 检测同文件；六表标准化内容哈希检测 Excel/CSV 同一逻辑批次。逻辑哈希用固定表顺序、固定映射列名、稳定 JSON UTF-8、记录按稳定主键与内容排序（保留重复行次数），忽略文件名/行号/格式差异但保留业务文本与有效值；仅对经过确定性解析的类型归一化，无法解析的原值也进入哈希，不能误合并冲突行。哈希不代替身份判断；同 family 同批次重复提交返回已有 dataset_id，不重复计算；不同 family 可以有相同内容，仍隔离。追加新快照指向父快照，新增/修订记录按 event_id 与 revision 处理；旧数据不可覆盖，行来源可追踪。并发同父提交以 expected_parent 做冲突检查。

### 3.3 数据质量与作答记录

### 7.2 触发规则与状态

提交服务先持久化答案和待评分状态，再调用评分（可返回 job_id）；重试用同 attempt/idempotency，不重复写分。评分通过生成正式学习证据，活动/组状态由服务端判断。组完成或满足 03/04 已定义异常规则时，调度 B 当前学生重分析及班级汇总，再调度 C，依赖审核发布。新学生事件不触发 A。以 `(family,student,event_cutoff,job_kind,dependency_version)` 去重，较旧任务不可覆盖较新发布指针；重复、乱序及并发测试必需。提前触发及任务组完成阈值按 03 与 04 §7。保留原任务版本及进行中题目；旧方案切换时未开始活动拒绝新作答，进行中受控完成；禁止把旧答卷记到新 activity_id。失败可重试并保留成功部分，不回滚已经合法提交的作答。

### 9.5 Agent 对话契约

保留 main 的 messages（历史最多40条、每条最多8000字符作为兼容输入上限）、run_id?,student_id?,node_id?,target:{type:student/class,id}?,task_type?；D analysis_context:{run_id,node_id,subject_type,subject_id} 只在服务端转为 target/run/node；如果同时提供不一致拒绝400。新 ChatRequest 增 conversation_id?,message:str?（新客户端单条，history由服务器装配）,activity_id?,plan_version?。messages 与 message 二选一；旧 messages 只能 user/assistant，system 角色拒绝，所有角色权限和系统提示由后端创建。旧 assistant 文本不是正式业务事实，不能当授权确认；新会话从持久化历史读取。新请求的 task_type 只作为路由提示，必须重新验证。服务端根据 SessionScope 解析目标、node、run、正式版本、活动归属，拒绝不一致和越权。

TaskType 公共类别：student_analysis,class_analysis,knowledge_lookup,plan_query,plan_modify,concept_tutoring,data_quality,learning_progress；内部映射依 05。class_strategy 退役，不注册任务、工具、提示或接口；class_analysis 保留正式读和比较，批量个人修改属 plan_modify。out_of_scope/unclear 的相关步骤不执行业务工具。学生只允许本人及授权课程，不允许 plan_modify/class_analysis/data_quality；复合任务子任务逐次验证。ChatResponse={conversation_id,message_id,text,task_type?,route_source?,status:enum(completed,partial,needs_confirmation,failed,out_of_scope),tool_trace:[ToolTraceView],evidence_refs:[EvidenceRef],stopped_reason?,prompt_version?,confirmation?:ConfirmationView,operation_results:[OperationResult],job_id?,segments?:[AnswerSegmentView],clarification?:str,assisted_confirmation?:AssistedConfirmationView}。ToolTraceView={call_id,stage,tool_name,status,message,evidence_refs:[EvidenceRef]}，前端映射中文进度，不提供完整 args、内部推理、密钥。OperationResult={operation_id,target_student_id,status,previous_plan_version?,new_plan_version?,review_status?,publication_status?,error?}；只报告真实执行，审核中不称发布成功。

ConfirmationView={confirmation_id,summary,targets:[{student_id,base_plan_version:ID|null,changes_summary}],expires_at}。后台保存待确认变更、授权会话、对象及内容摘要、版本、有效期；确认接口不得接受用户重新传入任意新修改对象；每次确认时重新检查权限、版本与操作范围。明确单人操作可直接执行；模糊/批量先确认；不允许将对话历史文本视为确认令牌。Agent 的计划写操作只调用 04 §9.3 冻结提交，后台 AgentRevisionSubmission={proposal_id,draft_hash,authorization_ref}，公共 HTTP 请求及模型均不得直接指定 authorization_ref。授权记录绑定会话、教师身份、目标、版本和具体差异。既有编辑/修订 HTTP 继续沿各自的 C 路径，不能将审核请求转成 teacher_direct。

Agent 的 JobDetail 增 steps:[StepView]、result_ref?:ID、result?:ChatResponse；C job 可附 review_status?/publication_status?/plan_version?。StepView={step_key,label,status:pending/running/succeeded/failed/skipped/needs_confirmation/cancelled,message?,evidence_refs:[EvidenceRef],started_at?,ended_at?}。状态取真实持久化进度；本轮等待交互时可结束 job 并返回 needs_confirmation，后续交互创建关联 job。部分成功用 ChatResponse.partial。报告已发布要求 publication_status=published 且能读当时正式指针。05 定义行为、工具与任务循环。

## 10. 错误、幂等、权限及运行模式（I-11、12、13）

### 10.1 包络

```json
{"schema_version":"1.1","request_id":"req-example","data":{},"warnings":[]}
```

```json
{"schema_version":"1.1","request_id":"req-example","error":{"code":"VALIDATION_ERROR","message":"输入字段不符合要求","details":[{"field":"node_id","reason":"缺少有效节点"}]}}
```

Warning={code,message,issue_id?}；DomainErrorData={code,message,details:[{field,reason}]}。统一 `api/envelope.py` 与 `api/errors.py`；保留 DomainError。客户端不得依赖 message 字符串判断状态，按 code；未知 code 进入可解释通用错误。JSON 解析/Pydantic 参数错误400 VALIDATION_ERROR；无会话401 UNAUTHORIZED（旧无效会话403兼容识别）；越权403 FORBIDDEN/CONTEXT_MISMATCH；对象不存在404 NOT_FOUND/KB_NOT_FOUND（不能通过差异泄露他人对象）；状态/版本/幂等冲突409 CONFLICT/REVISION_CONFLICT/RESULT_NOT_READY；业务不满足422 UNPROCESSABLE/KB_NOT_PUBLISHED/TASK_UNCLEAR/TASK_NOT_AVAILABLE；文件超限413 UPLOAD_TOO_LARGE；模型未配置/服务不可用503 MODEL_NOT_CONFIGURED/SERVICE_UNAVAILABLE/MODEL_TIMEOUT；内部500 INTERNAL_ERROR；新增代码集中映射，不能漏映射成500。请求 ID 可供排错，错误详情不得含密钥、堆栈、绝对路径、他人作答、模型内部推理。待评分属于正常可追踪业务状态，不视为学生答错。规则降级成功返回 warning 与 generation_method，而非假模型成功。

### 10.2 幂等和并发

复用 D api/idempotency.py，键范围 `(session_id,endpoint,key)`，存规范化请求摘要与结果/job 引用；文件请求摘要包括文件内容哈希、逻辑映射和目标 family；同键同请求返回同 ID 与相同语义结果，不重复创建；同键不同请求409；并发同键用事务唯一约束，不能先查后写无锁重复。失败重试是否复用键由是否已提交业务效果决定：已提交返回原对象并允许专门重试 job，未提交可安全重试；不能重复作答/评分/确认/发布。除传输幂等还有业务唯一约束（快照内容、事件 ID/attempt、revision、任务高水位）；切换会话不应重复产生同一业务事件。修改采用 base_revision/base_plan_version 乐观并发，旧任务不得覆盖新正式版本；06 确定具体事务和迁移。

### 10.3 服务端授权与数据裁剪

继承 SessionScope 和 token hash 存储、12小时会话基线。Scope 扩 `dataset_family_id?`,`allowed_class_ids:[ID]`、`capabilities:[str]`；dataset_id 仍为当前选中快照，跨历史版本访问必须同 family 且在授权范围。教师 bootstrap 仅列数据集/导入/选择已有数据集；上传任务可报告自己的批次，但查看学生分析必须绑定数据集；本地教师绑定授权班级，默认比赛受控环境可选全部当前数据集的模拟班，实际按名册动态取得，不能硬编码班级编号。学生必须绑定真实快照成员与本人；角色切换创建新会话，不能由消息或 body 自行声明角色。模拟身份仅 localhost、受控比赛环境，非生产认证。新 `allowed_class_ids` 由服务端基于本地身份选择策略验证，不把浏览器提供列表当可信授权。每次查询/工具/写操作、证据 resolver、导出、任务轮询检查 dataset/family、班级、学生、版本；批量操作逐目标校验。学生不访问其他学生、班级汇总、教师质量/审核/导出、模型配置，禁止直接改画像和正式方案。答案保护覆盖 HTTP、Agent 上下文、工具返回、引用、评分细则和缓存；不只删除前端几个字段。对已完成且当前授权的活动可以返回详细讲解；共享材料若另有进行中同题，必须按具体活动保护，无法区分时保守裁剪。教师查看本班真实原记录及答案；跨班未经授权不得读取。禁止外部模型获得超范围对象。

### 10.4 两个独立运行维度

保留 D `VITE_DATA_SOURCE=api|demo`，正式默认 api；非法值明确报错，不回退 demo。`demo` 只使用前端预设合成数据，清晰标记，不请求正式写入接口、不触发 ABC、不产生正式导出；如测试需要后端合成数据，单独 DATABASE_URL/DATA_ROOT 并标 synthetic，不混正式库。`DEMO_MODE=true` 保留原义：在 localhost 允许模拟身份选择，真实 api 模式也可使用。禁止用 DEMO_MODE 选择真实/预设数据。两个维度切换时清空会话与查询缓存；真实 api 失败展示真实错误，不自动换数据。模型配置统一由后端 Settings/provider 管理，保留原环境变量和 D 设置入口适配；不得记录密钥，URL 仅允许经验证的 HTTP(S) 模型端点、受控本地配置，不由学生任意修改；生产级认证和云部署不在本范围。
