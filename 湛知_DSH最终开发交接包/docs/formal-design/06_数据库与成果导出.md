## 2. 身份与版本模型

| 身份 | 生成及边界 |
|---|---|
| dataset_family_id | 单个连续资料系列。教师明确 new_family 或 append；自动识别只作待确认建议。不同 family 不因学号/哈希相同合并。 |
| dataset_id / import_id | 前者不可变完整快照（父版本可追），后者为一次上传/确认业务实例。批次可无 ready dataset；同家族完全相同变更可复用快照。 |
| student_uid / student_id / class_id | uid 服务端创建，按 (family,原始student_id) 唯一；student_id保留原字符串。class_uid 服务端稳定标识，class_id 在 family 内识别，班级归属以指定 dataset 快照 members 为准。 |
| node_id / scope_kind / run_id | node 源测验或正式登记在线范围，原 ID 与范围枚举沿 01；run 为绑定 dataset 和节点集合的批次或局部更新执行范围，不作学生或正式结果版本。所有同 run 内输出按实际 node 读，禁止将不同节点结果当同一证据。 |
| catalog_version / knowledge_version | 目录与 A 快照独立，包含同一可追踪 family/快照依赖。知识名称变化产生新 A，但可登记兼容性。 |
| analysis_version / plan_version / content_version | 分别为个人/班级各自版本、学生计划版本、微课堂正文版本；不比较编号大小；组/活动/尝试永久身份按04，内容改变时新内容版本，正式绑定只引用精确版本。 |
| event_id / event_cutoff | 事件为 append-only，对外用 ID；DB 全局单调 offset 供高水位，活动序号另用；有严格 scope 过滤，不用 occurred_at 当高水位。 |
| build 输入与动作 | rule_version、config_hash、prompt_version/model 实际版本单独记；review_id、candidate/proposal_id+revision、authorization_ref、operation_id、job_id、export_id 各自唯一，不混作正式版本。 |

服务端 FormalKey=(family_id,dataset_id,kind,run_key,node_key,target_key)。SQL 各 key 非空：不适用用保留空串，禁止作为用户 ID。A 目录/知识按 dataset 不绑 run，不适用 target/node；B/C 按 run、node、student_uid 或 class_uid；面向 dataset 的个人画像/计划入口先读显式 active_run 指针后解析。相同 family 新快照绝不隐式读父 run 当前结果；可通过有范围证明的兼容复用生成新快照作用域引用（origin 依赖原版本、身份和内容不重写）。旧进行中尝试按原活动+原 plan 访问与提交，无须随 active_run 切换。新增在线节点与原始节点的归属遵循 01 的 scope 字段和真实材料范围。

A、B、C 每个不可变成果统一对象 versions，依赖有角色的 edge。读 current 必须通过 formal_heads，显式历史通过曾发布记录、版本 scope、角色以及旧活动访问授权。禁止取最大版本 ID/时间，不能以 succeeded job 担当指针。未来发布状态可由发布记录投影，旧曾发布实体仍是有效历史。失效分为 pending_recheck、stale_usable（有可证的适用范围）、suspended、unavailable；状态属于仓储投影，按照01外发 current/compatible_history/stale。current 对应精确当前依赖，stale_usable 经复查可投影 compatible_history，pending_recheck、suspended 使用 stale 和明确限制作说明，unavailable 返回 RESULT_NOT_READY。冻结导出持久化选择理由。

## 3. 可执行依赖与版本选择

### 3.1 登记和解析

build_start 在短事务读取 head/generation、选定 scope 内的 event_cutoff、输入修订、规则、配置，固定 input_digest；长过程使用冻结引用。成品发布前同事务写 versions、artifact_edges、artifact_use、evidence_index 与审核，校验必需角色并去重。A 记录 source_file/locator、catalog、parent；B 学生记录实际选入 raw/answer/attempt/grade/learning_event 版本及 cutoff，coverage 独立记录排除/不适用原因；班级对每个快照成员记录 class_members 对应 uid、analysis_version 或未处理/明确无数据（名册分母不能丢）。无记录学生仍生成正式诊断的限制结果。C 记录 catalog/knowledge/analysis/base_plan/intents、历史事件 cutoff、素材/内容、活动绑定、审核与发布。C 先冻结输入再构建，C review 绑定 draft_hash，不补写未来版本。依赖关系与实际请求上下文不一致拒绝提交。

artifact_edges 是从派生版本指向实际依赖版本的 DAG，roles 如 catalog/knowledge/student_analysis/parent_plan/content/member_analysis/origin。程序插入前检查 kind、scope/授权、引用曾发布资格（同事务新发布内容可被引用）、有向无环。edges 只纳入“需要解析”的边，parent 版本关联用于历史与审计，导出可以输出 provenance stub 而非完整历史链，但生成所用 A/B、活动、评分一律导出实际可解析内容。对象级 use 记录稳定 lookup_key 与确切 revision/version。反向按 dep_version_id 或 (family,input_kind,input_key) 查受影响版本，从发布指针及活跃任务交集选择失效目标；历史指针只读，安全撤回独立处理。对象 resolver 以 kind+id+必要 version 字段定位并检查 family、目标身份、角色，不能将原引用重定向最新。未知引用返回安全不可用状态。元数据 hash 或证据定位变更都可追溯。

### 3.2 影响计算与事务控制

| 变化 | 种子及处理 |
|---|---|
| 新教材 | A 更新实际覆盖章节和映射。仅新增覆盖时通知 C 新候选池；无 B 实际关联、范围变化不重算 B。 |
| 新题 | 新 Catalog、A 标注并按节点加入候选；过去作答未涉及不重算 B。新增作答由 B 任务处理。 |
| 课标新增/修订 | A 按来源与章节定位核心要求，差异集向主题/指标及相关已用证据扩展；语义变化触发相关 B 和 C，未知影响在所属范围保守重查。 |
| 题目或评分点关联修正 | use 索引取对应材料/评分点相关学生、范围和历史有效证据；重新 B 聚合及 C 复查，已有正式答题和评分保留。评分规则确有变更且 B 要求重评才追加 grade 修订。 |
| 必要前置关系变更 | 按 A 边源/目标及受影响图闭包定位 C 队列/计划；未改证据定义不触发 B。 |
| 仅名称 | 比较语义 hash、scope/支持关系/来源与安全差异；登记批准的 directional compatibility，仅显示可选最新别名；历史出处存原版。 |
| 新学习事件、迟到事件、评分修订 | 仅本人受影响节点/知识、其分析所在快照班级及 C 计划。事件到账一次，先选择截止前最高已登记评分修订，只有 graded 且 validated 才贡献有效分，禁止回退旧分。未获授权的历史转移不跨节点传播。 |
| 教师改计划 | 仅该学生 C 和必要审计/提醒；不重跑 A/B。 |
| 班级归属更正 | 新数据快照；旧名册冻结。新旧归属班重新聚合各自实际成员；个人证据没变则写 origin 兼容关系。 |
| 规则/配置升级 | 按 kind 与 scope 查实际配置/规则使用及计算口径，先负责模块再下游；变化未影响兼容时只作版本检查。 |

使用 A KnowledgeChangeSet + B/C 业务规则映射影响范围。新资源无 reverse hit 时查询适用新节点/主题及因缺材料被阻塞的候补，不能把“没使用过”当无需处理。同 family 身份关系模糊时暂停确认。算法：

~~~text
delta = typed_semantic_diff(old, new)
targets = reverse_use(delta.keys) + coverage_matches_for_additions(delta)
for target in stable_unique_scope(targets):
    action = module_policy(delta, target, exact_dependency_closure(target))
    transaction:
        mark_or_preserve_current(target, action)
        if action.requires_work:
            CAS advance required dependency generation for that FormalKey
            put outbox once for (kind, target, input_digest, dependency_generation)
dispatch A prerequisite work -> impacted B student -> class aggregation and C
~~~

学生变更时班级可滞后但必须真实显示成员版本；正式导出前需互相一致。A 变化不要求所有刚好同版，按精确依赖+兼容证明。例：N01 只改节点内一个评分点，使用该点的两名学生重算，班级刷新两成员版本，其他人旧有效版本不变；完全新增 T03 题不碰 N01。

### 3.3 原方案仍适用

plan_applicability 按 §4.3 的组合键唯一，包含 plan_version、目标 B/A/目录、policy_hash、event_cutoff 和当前活动摘要，并固定目标 scope、checked_event_cutoff、checked_at、结果 applicable/limited/incompatible、活动子集和理由证据、job。C2 原依赖 B2 不变。B3 变更触发04重新评判，输入真实 B3 及 C2、教师意图、当前活动；判断仍适用时事务只写检查记录（CAS 目标 B/head 未变），current 仍 C2。B4/A新语义/素材撤销/保护边界变化使原检查对当前失效；对已验证 compatible 的名称变更登记兼容 proof。面对 pending，页面显示 C2 生成基线 B2 和当前 B3、复查状态；未证明部分仅历史读或局部暂停，不能报告已适用。导出同时保留 B2/B3、适用性记录、A兼容证据及 C2 的实际生成依赖。不能把适用性记录当作审核替代。适用性水位使用该学生与受影响节点在全局 offset 中的最大相关值，冻结包另存全局读取截点；无关学生追加不能使已复查方案再次过期。目标比较使用 checked_cutoff 所含的最新已生效 grade 和实际活动摘要。活动状态、素材或安全约束改变即使未出新 B，也按 §3.2 生成相应的 C 重查。示例：B2 出现弱项，C2 已排纠错；B3 可比证据部分改善，剩余仍适合，写 applicable 而不造 C3。B4 发现后续题受保护暴露，暂停该题并按04重评。

### 3.4 发布事务

一次写事务使用 SQLAlchemy Core update CAS，检查 rowcount=1；首次 scope 预建唯一空 head 或 INSERT ON CONFLICT 后重读，空基线 CAS 只匹配 NULL。以短连接取得写锁后读 current、权限、活动、取消及 generation，核对冻结输入 digest、审核 hash/path、当前指针和发布资格。C 三路校验限定 system_auto/agent_revision validated，teacher_direct 必须 edit capability、确认令牌及硬门 human_confirmed。对冻结候选的实质审核修复重新预览授权。A 指针指向已原子就位的文件；B 每个学生独立发布，班级用成员清单竞争校验。成功同事务写版本与证据、历史、指针、适用性或活动状态、操作记录和 outbox，CAS 零行全部回滚返回409。对不同目标批量每个单独 CAS；固定名单内部分成功可交付，但接口逐人报告。取消与发布共用写序列，先提交者胜出：已正式发布取消不撤销；尚未发布的 job 见 cancel_requested 后保持旧结果。晚完成或依赖更新的旧任务无权切指针。文件操作不放在写事务，不声称 SQLite 能原子控制外部文件/模型。

发布 CAS 参考与下游事件同一 SQLAlchemy transaction helper。Identity 由 FormalKey 六字段等值过滤，依赖变化与竞争发布分别由 required_generation 和 generation 门控。

~~~sql
UPDATE formal_heads
SET version_id = :new_version,
    generation = generation + 1,
    freshness = 'current',
    updated_at = :server_now
WHERE family_id = :family AND dataset_id = :dataset
  AND kind = :kind AND run_key = :run_key
  AND node_key = :node_key AND target_key = :target_key
  AND version_id IS :expected_version
  AND generation = :expected_generation
  AND required_generation = :expected_required_generation;
~~~

Job 需在同连接先锁存 lease_token 和 cancel_requested，应用层验证所有冻结依赖指针/活动状态；最终写 outbox 后一次 commit。适用性事务用同样的竞争条件，只插检查记录并更新 freshness 需要的投影，不改 version_id 或生成依赖。


## 4. 物理模型及访问权限

### 4.1 通用数据字典

字段 DSL：id=SQLAlchemy String(128) / SQLite TEXT 亲和，应用校验合法 ID；key=String(256)，S=Text，H=String(64) 校验小写 SHA-256，J=JSON/TEXT（闭合 DTO，SQL NULL 与 JSON null 显式区分），I=Integer（非负，若业务从1起则约束>0），B=Boolean（0/1），T=String(27) 固定 UTC ISO8601 毫秒，由服务器写。文件尺寸/全局 offset 用 SQLite INTEGER 64 位。未标 ? 的列 NOT NULL；无等号的必填项无默认，? 的默认 SQL NULL。id 主键服务端生成；FK 默认 ON DELETE RESTRICT，批次写入使用明确顺序，所有表主键/唯一索引由迁移创建。U(...) 唯一，IX(...) 非唯一，字段后 → 为 FK；跨对象 family/run/node/分支语义由同事务应用层再验。以下 JSON 均按对应 01—05 DTO schema 验证并保存 schema_version（若该 DTO 无字段，则写在外层元数据）。除状态、指针、租约和跟踪表明确允许更新外均不可变；业务撤回用状态日志，赛事合规清理见§11。全表服务端访问，用户仅通过01投影，scope 缺失按拒绝处理。所有 FK 关联路径需由 PK/U/IX 索引覆盖，以最左前缀查询。

## 6. 任务调度与恢复

Job 系统复用单机数据库与进程内 worker，启动后恢复，默认1个执行 worker，数据规模允许后再配置扩展。任务 DAG 与 01 JobDetail/StepView 一致。写操作粒度为一个可重复领取的步骤，外部模型不在事务。建 job 时锁定输入摘要、所需依赖，记录阶段初始快照；复用的子 job 必须同 scope/version。任务不直接以当前最新记录替换冻结输入。

| 触发事务 | outbox 与后续 |
|---|---|
| import ready | 确认 datasets/材料/节点，目录与 A 必要构建节点；按正式可用范围投 B 人/班级，足够正式结果再安排 C。不因无关 A 待审核阻断可用范围。 |
| answer_submitted | 派评分 (attempt,submission_no,grading_policy)，评分失败记录 pending 并重试，不当 0 分。 |
| group_completed，可信 B 异常/迟到评分或帮助 | 局部 B 以确切 cutoff 运行，触发同学生影响的历史/画像、实际成员班级和 C 适用性；防止评分先后乱序改变已合法完成记录。 |
| A publish + change_set | 同事务入依赖差异工作，按§3只触发受影响范围。 |
| 触发 C 或 Agent 执行 | C 输出 preserve/applicability、draft、publish/needs_review。Agent 查候选、确认生成 C 独立子任务；读操作失败仍可部分返回。异常介入使用04去重对象。 |
| 正式发布/输出 | 下游通知和应用更新出站，不依赖 Web 在线，消费者重放仍幂等。 |

~~~text
transaction dispatch_tick:
    take due outbox ordered by (available_at,outbox_id) by atomic claim under short writer
    INSERT job ON CONFLICT(kind,scope,input_digest,dependency_generation) DO NOTHING
    bind dependencies and mark outbox dispatched with real job_id
transaction claim_tick:
    pick queued due job whose dependencies succeeded and result prerequisites available
    CAS queued->running with random lease_token, lease_until, attempt_count+1
    append started stage; return exact scope and snapshot
outside transaction:
    run service step against immutable input; renew lease separately
    persist safe checkpoints only if lease_token still matches
transaction finalize:
    verify ownership, cancel flag, authorization, required_generation, current heads
    write business effect once + audit + outbox + final job state atomically
~~~

依赖失败标相应步骤 skipped，受阻结果带已完成效应与可重试范围。租约默认90秒、心跳20秒，恢复扫描默认15秒（均可配），过期 lease CAS 到 queued 或 failed；租约过期后旧 worker 不能写正式结果。处理中 cancel_requested 原子检查，发布后取消返回既有状态。队列独立恢复 pending confirmations expiry、未知 disclosure、遗留 running jobs；客户端关闭不默认取消。模型短故障按02—05的预算和超时，统一任务默认至多2次执行尝试，指数等待3/15秒（超过预算不续）；模型调用本身跨故障可能重复，持久化模型任务元信息、checkpoints 与输入 hash 支持查重，最终业务唯一键避免重复效果。未保存输出不能假定已获得模型结果。事务局部失败不动原正式结果，重试仅当前失败 scope，不要求重新上传或重新运行无关模块。必须区分 task succeeded 与成果审核/发布。

## 7. SQLite 与迁移

复用 engine/session 单例工厂，HTTP 请求与各 worker 使用独立 Session、不跨线程共享对象。文件库启用 foreign_keys=ON、WAL、busy_timeout=5000ms、synchronous=FULL（比赛本地磁盘默认，记录配置）；初始化 WAL 检查成功，内存 fixture 不强求 WAL。用独立短写事务，关键竞争采用 BEGIN IMMEDIATE 后 CAS；连接已隐式事务时禁止二次 BEGIN。工程入口用 connection.exec_driver_sql 开始并包 transaction helper，结束 commit/rollback，一次作用域。查询导出冻结用一致读取事务，保存冻结行和 job 时在短事务使用同一连接（避免 WAL 读转写竞争）；序列化、模型、压缩在提交后。SQLITE_BUSY 只对无已提交效应事务有限退避重跑（默认2次 50/150ms），保留幂等和 lock 错误可重试。运行期定期 checkpoint 由维护任务在低负荷执行，不强制阻塞读者。

## 9. 逐文件契约与序列化

### 9.1 公共契约

除 manifest、README、CSV 外，JSON 采用 {schema_version:"1.1",items:[记录]}，examples 使用 {schema_version,items} 同型。记录 schema 是下表字段及命名的原共享 DTO 投影，闭合，? 可省略，显式 null 表来源已知缺值；空列表表示确无记录，并由 limitations 解释缺数据或未发生。所有跨文件链接使用同级 key 字符串或 EvidenceRef；key 可由 kind+对象ID+精确版本编码（分隔符 percent 编码，不解析成 OS 路径），重复 key 拒绝。同名对象在不同版本必须不同 key。数据集信息取 manifest，记录可给 scope/node。历史项目显式 current=false。读取 sorted keys：逐 JSON item 按 key 的 UTF-8 字节序；其中实际教学活动顺序/推导步骤随原数组，不能排序改变业务。JSON 键排序、ensure_ascii=false、UTF-8 无 BOM/LF、禁止 NaN/Infinity，LaTeX/MathString 仅为字符串。JSON 的 metric decimal 与 CSV 同一个已验证序列化值，通过 Decimal 固定最多6位（half-even）仅作为包表示，保持原单位与原比较口径，分子分母原类型，未计算为 null/CSV 空。0 分和 null 不同。纪录数包含历史依赖且按文件核对。CSV UTF-8 BOM、RFC4180 引号/CRLF，字符串列仅规范 ID/枚举/单位，非法公式型、控制字符或路径类值阻断并要求标签/编码受控；不损害 JSON 原记录。不导出秘密、隐藏提示、原始堆栈、内部日志、同族范围之外对象、未发布草稿、全量原始资料。参考答案和未释放提示按 01/04 安全投影，样例只提供经授权且必要的证据，不导出仍受保护题标准解。所有字段均列入 field_dictionary（包括嵌套 DTO 逐字段展开），规范例在§9.3。

### 9.2 Manifest 与 ZIP 发布

Manifest={schema_version,run_id,dataset_id,dataset_family_id,catalog_version,rule_version,created_at,generation_method,data_origin,snapshot_id,selection_hash,event_cutoff,node_ids,versions:{catalog:[ID],knowledge:[ID],student:[ID],class:[ID],plans:[ID],content:[ID]},dependency_edges:[{from,to,role}],applicability_ids:[ID],compatibility_refs:[ID 或规范 proof key],evidence_index:{file,record_count},coverage:{students,classes,cases,limitations},files:[{path,sha256,bytes,record_count?}],validation:{preflight:"passed",payload:"passed"},limitations:[str]}。generation_method 给真实方法集合；rule_version 主 run 规则，其他版本逐对象。如无需混合也保留版本清单。files 只含其他文件、自身不参与递归，ZIP 整体 archive_hash 只存 export DB 与下载 ETag。回读通过后写 export.check_report.validation，避免将尚未执行 ZIP 检查写入 manifest。固定路径 allowlist，拒绝绝对路径、..、符号链接、重复成员、超限压缩比/大小。ZIP 构建按路径稳定排序、文件时间取冻结时间，工具/压缩版本记录以复核。先 staging 用原子 rename 发布内容地址，再事务 CAS export ready，失败/重启从已核验 hash 核对后复用或重建。回读校对 CRC、每项 SHA-256、byte/record count、反序列化严格 schema、引用安全及三案例映射；跨文件 metric 对账、总数/分母检查是校验，不能另做分析或调用模型。

### 9.4 API 与错误

POST /api/v1/runs/{run_id}/exports，Idempotency-Key，{format:"zip",node_ids?:[ID],case_student_ids?:[ID]}。新请求冻结后正常202 {export_id,snapshot_id,job_id,status:"queued"}，若同冻结快照已有可合法复用 ready，可返回201/200 {export_id,download_url,manifest}。统一 GET /jobs/{job_id} 得进度和结果引用，GET /exports/{export_id}/download 只流式读 ready 文件，按当前教师权限、冻结授权范围、发行策略与 hash 校验，404 不泄露其他对象。API 发回对外下载名 ASCII safe 固定模板，真实 storage_key 私有且必须 root containment。失败 422 EXPORT_INCOMPLETE 附 check_report 问题；未就绪409 RESULT_NOT_READY，版本冲突409 DEPENDENCY_STALE；文件损坏503 EXPORT_ARTIFACT_INVALID，标记历史问题不发损坏流。

旧 D GET /runs/{run_id}/exports 可只读返回已冻结正式包 manifest 或预检（不写）；旧 GET /runs/{run_id}/exports/download 查同 scope 的最近匹配 ready 导出记录（不临时重算），无则409 引导 POST。published_only=false 不放行：省略兼容，显式 false 返回422 EXPORT_SCOPE_INVALID。签出下载时不信任客户端 class_ids 或 scope。校验型查找按 export_id 及请求授权，导出运行不持写锁。

## 11. 本地备份与恢复

拟 CLI study-companion backup --out <local-backup> / verify-backup <local-backup> / restore <local-backup> --target <local-root>。默认停写维护窗口：停止写入、让在途步骤提交或进入恢复条件，保留 DAG 状态；不用复制正在写的主文件。执行 sqlite3 Connection.backup（取得数据库一致快照，覆盖 WAL 中已提交页），再从该备份 DB 的 file_objects 权威引用枚举需原始/知识/微课堂附属内容，导出文件及版本索引按实际可用备份。在线模式若文件仅追加且能 pin 全部快照对象，可先逻辑 pin 保持对象不被安全清理，完成快照及文件复制再释放。未实现 pin 时只用停写。数据库文件快照、编码和签出内容使用内容 hash 对账。

清单 {backup_id,created_at,app_version,alembic_heads,db_path,files:[{path,bytes,sha256}],counts,mode}，除自身外核对所有文件；备份保管和访问沿同一受控本地授权。密钥、.env、供应商配置秘密和无关恢复日志不备份，备份也不是正式交付包。验证打开副本以只读方式查 integrity_check/foreign_key_check，再核查文件路径、字节 hash、scope/版本 FK、正式头、存在的附件，版本不支持时先在 staging 中运行兼容迁移；不能丢弃未知新版数据或盲降级。恢复前创建当前环境保护备份，停应用和 worker，目标 staging 与 DB 文件同卷，先完整验证，原安装根保留，原子切换新根或指针，再启动、回读正式头、重跑待恢复任务。失败保持/恢复原根，检查原因，不部分覆盖业务资料。赛事要求赛后按组委会规定清理原件、派生和备份，先确认授权、列出实际关联副本和保管期限，按范围执行，不借清理删掉其他 family。

### 补充核查：教师手动重试的持久化与恢复

jobs 增 retry_of_job_id?:id→jobs、root_job_id?:id→jobs（原任务可空并以自身为根，重试子任务必填）、manual_retry_no:I=0（子任务=1）、retry_eligible:B=0、retry_block_reason?:key；IX(retry_of_job_id)，partial UNIQUE(root_job_id) WHERE manual_retry_no=1，CHECK manual_retry_no IN (0,1)，且 manual_retry_no=1 时 root_job_id 与 retry_of_job_id 必须均非空并指向同一失败根链。根任务额度通过子任务唯一索引派生 manual_retry_count，避免覆盖旧任务。原状态、失败原因、自动尝试次数、步骤及历史事件保留；子任务 attempt_count=0，沿06运行时同一安全策略。第4.5节任务键 U(kind,scope_key,input_digest,dependency_generation) 对初始任务采用 WHERE manual_retry_no=0，保留 outbox 自动去重；教师重试只由根唯一约束和请求幂等建立，不能把新重试误返回旧失败 job。

POST retry 在同一短写事务先查授权状态和原失败 job/根，重验依赖、失败类别、是否存在正式效果和原有效授权，检查 Idempotency-Key，然后插入关联子 job、真实 queued 事件、操作审计及请求回执；队列可直接领取已提交子 job。服务重启通过同一 jobs 表恢复。失败记录不可覆盖；同键回放返回原子任务，竞争或对重试子任务再次重试拒绝409。已取消、待确认、仅审核未通过或授权失效不等同可重试执行失败。系统审计保存 actor、原 job、根/子 job、作用域摘要、原失败码、请求键摘要、时间及结果，不记录密钥或完整模型输入。
