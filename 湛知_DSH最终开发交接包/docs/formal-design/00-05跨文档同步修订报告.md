## 已解决的契约差异

- 将 05 的候选动作落到 04 的 C 应用服务。候选不占正式指针；一次优化须复用 C 原预算和合法素材。冻结提交绑定 scope、版本、proposal、hash 和授权；越权、过期或依赖变更阻断。首次明确请求生成且无当前计划使用空基线 CAS。审核的实质变更必须重新获得对应授权。
- 对齐 C-30。自动与 Agent 使用完整审核；正式编辑器只强制硬门，教师确认发布标 human_confirmed。模型和公共请求均不能伪造后台授权，修订和编辑器保留各自入口。
- 统一聊天、确认、任务和发布状态。JobDetail 复用同一查询路径，执行完成、审核通过、正式发布各有独立状态。教师确认、学生受助确认、无写授权的澄清是三种互斥视图。
- 三级提示与动态引导共用课程保护集合和累积披露历史。确认受助、实际出站、无法确认暴露分别处理，只有可信实际帮助进入帮助统计；B 按尝试和提交时序判定，微课堂阅读不贡献评分或掌握证据。
- AG-14 退役 class_strategy 任务及专用算法、工具、提示词和接口。B 的班级学情、共性、证据、进展和合法比较保留。批量个人修改采用固定名单、预览确认及逐人审核。
