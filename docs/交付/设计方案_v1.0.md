## 摘要

湛知把赛方提供的课程要求、题库与模拟学情，加工成三层可核对的成果：结构化课程知识体系、有证据的学情诊断、可执行且可调整的个性化学习方案。系统的核心工程取舍是让规则承担一切可复现的计算与判定，让模型只承担语义理解与表达，并对模型产物另做一次独立复核。2026-11-28 的干净库回归用赛方六张 CSV 加一份教材切片跑通导入、知识构建、学情分析、方案生成四步链路，产出 37 个知识点、80 份学情、80 份学习方案、159 组任务组与 160 份微课堂，全程 22 分 03 秒。第一次导出被方案质量门拦下，修复生成逻辑后重新生成并通过预检，最终 ZIP 在第 4.6 节给出实测数据。

## 1 需求分析

### 1.1 三项任务与交付边界

赛题给出七年级数学的课程要求、题目与材料、两个测验节点、四十名模拟学生的作答记录，要求系统回答三个层层递进的问题。湛知按这三个问题划分三个业务模块，每个模块都有独立可核对的产出。

| 赛题任务 | 要回答的问题 | 承接模块 | 可核对产出 |
|---|---|---|---|
| 理解学科 | 这门课要教什么；知识点之间是什么关系；每道题、每个评分点在考哪一条 | A 课程知识 | 知识点、五类关系、题目与评分点标注、教材出处 |
| 理解学生 | 每个学生、每个班掌握到什么程度；证据够不够；薄弱点在哪 | B 学情分析 | 指标分子分母、四级掌握状态、错因诊断、班级分布 |
| 理解教学 | 下一步练什么；按什么顺序；用什么材料；什么时候换策略 | C 学习方案 | 任务组、活动、三级提示、个性化微课堂 |

比赛要求提交不超过 20 页的设计方案 PDF、不超过 5 分钟的视频、答辩 PPT 与正式成果 ZIP，代码可选但输入输出样例必需〔D00〕§8。本文只覆盖设计方案 PDF，其余交付物的进度见第 7 章。

系统边界同样明确：不开发正式注册与账号体系，不做分布式云部署，不做模型训练，不把模拟学情包装成真实教学成效。赛题模拟数据只能证明系统结果、证据与建议的合理性，不能证明教学效果。

### 1.2 师生场景

教师的一天由四个入口串起来，每个入口对应一类判断，不要求教师理解系统内部结构。

| 场景 | 教师动作 | 系统行为 | 硬约束 |
|---|---|---|---|
| 早读前看班 | 打开班级总览，切到 N01，看雷达、共性薄弱项、掌握分布、重点关注名单 | 只读 B 的正式班级分析；名册分母含无记录学生 | 不按得分自行设关注阈值，不生成班级教学策略 |
| 追一名学生 | 从名册点进学生画像，展开某条诊断，看它引用的原题、作答、评分点 | 统一证据解析器按版本定位，抽屉内展示，可继续展开嵌套引用 | 只读本班授权范围；引用带精确版本，不自动取最新 |
| 处理异常 | 在课程体系页查看 23 条待复核候选点，逐条通过、拒绝或编辑 | 候选与正式图分开存储，教师操作走白名单字段与版本校验 | 不伪造审核人，不因点击通过就跳过证据存在检查 |
| 调一次计划 | 在 AI 对话里说“把 D01 下一组练习减到 3 题”，看候选差异后确认 | Agent 只生成候选，C 重新校验、审核、发布，返回真实版本差异 | 含糊或批量请求先列名单再确认，聊天里的“好的”不算确认 |

学生的路径更短，围绕“我现在该做什么”展开。

| 场景 | 学生动作 | 系统行为 | 硬约束 |
|---|---|---|---|
| 看自己 | 打开个人画像，看本人指标、文字诊断、学习进展 | 只投影本人正式结果，安全裁剪教师专有字段 | 不做班级排名，不给心理标签 |
| 开始学 | 进学习计划，按任务组顺序做微课堂、学习卡、题目 | 任务组顺序来自 C 的必要前置与负担控制 | 未满足依赖的活动锁定，不按题型机械重排 |
| 卡住了 | 逐级请求三级提示；或点“询问湛知” | 一次只释放下一层；Agent 引导经答案保护校验后发送 | 不预载未释放提示，不跳层取答案 |
| 交作业 | 提交答案与过程，看逐题反馈 | 选择题规则判分，填空规则加等价表达，解答题模型初评加独立复核 | 待评分不显示 0 分，评分失败保存提交并重试 |
| 学完一组 | 等待反馈更新 | 组完成触发该学生局部 B 分析，再触发 C 复查 | 个人版本局部更新，其他学生版本不变 |

### 1.3 为什么采用规则与模型协作

只靠规则会退化成关键词匹配。知识点合并、题目与评分点的语义对齐、学生解题步骤的错因、教学语言的组织，这几件事无法用有限规则穷举；硬写规则会产出看起来精确、实际错误的结论。只靠模型则失去可复现性：同一份作答两次评分可能不同，指标分子分母对不上，审核失去稳定基准，评委也无法核对。

湛知把两者切开，并规定交界处的数据形态。

| 环节 | 规则负责 | 模型负责 | 模型不可用时 |
|---|---|---|---|
| 数据清洗 | 重复、冲突、修订、待评分、超范围分数的判定与处置 | 不参与 | 完全不受影响 |
| 指标统计 | 分子分母、排除项、证据充分性 | 不参与 | 完全不受影响 |
| 掌握状态 | 四类状态与阈值判定 | 不参与 | 完全不受影响 |
| 知识构建 | 结构校验、关系方向与源数、前置环检测、引用存在性 | 知识点提取、关系判断、题目与评分点对齐 | 保留已有正式知识版本，未完成部分标记待处理 |
| 评分 | 选择题与填空题规则判分、分数范围与分项合计校验 | 解答题按评分细则分点评分 | 保存提交，状态置待评分，不给假分数 |
| 策略与选题 | 六类策略判定、候选资格、优先级、负担与顺序 | 在合法候选内优化组合、写教学语言与微课堂 | 使用已审核的规则模板发布，或暂缓发布并标降级 |
| 审核 | 硬门：身份、版本、材料、历史、结构、数学、答案保护 | 语义复核：依据是否成立、目标是否匹配、顺序是否合理 | 无法完成完整审核时停止自动发布 |

交界处的约束是三条。模型只输出结构化草稿，程序做 schema、引用、范围、数学与答案保护校验；模型不能改数字、不能写正式状态、不能直接发布；模型失败必须显式记录，降级结果要标出真实生成方式。这套分工在真实数据上得到过一次反向验证：D14 两个节点的方案被模型复核判为不通过，系统没有放行，导出因此被阻断（第 4.4 节）。

## 2 方案设计

### 2.1 总体架构

系统采用模块化单体。一个 Python/FastAPI 后端、一个 SQLite 数据库、一套 React/TypeScript 前端，单机启动；A/B/C 的业务逻辑是纯函数，服务层负责装配上下文、事务与持久化；Agent 是受控的消费者，只经业务服务读写；Web 只做展示与提交。这条边界的好处是评委可以只读一个模块就核对一类结论，而不必追整条链路。

```text
教师端 / 学生端（React + TypeScript，只展示与提交）
      │  HTTP /api/v1：统一包络、Bearer 会话、幂等键、角色投影
      ▼
FastAPI 路由层（鉴权、参数校验、错误映射、任务回执）
      │
      ├─ A 课程知识     ├─ B 学情与评分    ├─ C 策略与方案
      │  纯函数 + 服务    │  纯函数 + 服务     │  纯函数 + 服务
      │
      ├─ Agent：受控工具循环，写操作只生成候选
      ├─ 公共模型服务：统一供应商适配、结构化输出、失败上报
      └─ 调度：outbox → job → step，单机 worker，租约与恢复
      │
      ▼
SQLite：唯一正式状态
versions / formal_heads / publications / artifact_edges / evidence_index
原始行与目录 / 学习事件账本 / 任务与审计
      │
      └─ 导出服务：冻结快照 → 组装 ZIP → manifest 回读校验
```

### 2.2 分层职责

| 层 | 输入 | 输出与行为 | 禁止 |
|---|---|---|---|
| A 课程知识 | 课程要求、教材切片、题库、评分点 | 正式知识版本：知识点、关系、标注、出处 | 推断学生掌握程度；生成题目或难度值 |
| B 学情与评分 | A 正式版本、有效作答、学习事件 | 指标、诊断、评分、进展、班级分析 | 自建推荐策略；改写课程知识 |
| C 策略与方案 | A、B 正式版本、学习历史、教师意图 | 策略、任务组、活动、提示、微课堂、方案版本 | 创造未登记题目；改写 B 结论 |
| Agent | 授权会话、业务工具 | 任务拆解、解释、授权修改候选、引用 | 绕过 C 审核、绕过权限、直接写库 |
| 数据库/仓储 | 各模块结构化成果 | 原始与正式数据、版本、依赖边、日志 | 覆盖历史；混合不同范围的数据 |
| Web | HTTP 接口 | 展示、交互、格式化、真实状态映射 | 重算得分或诊断；仅靠前端鉴权 |
| 导出 | 冻结的正式成果与证据 | 可核对的 ZIP 与 manifest | 重算另一份业务结果 |

### 2.3 一次导入到成果的主链路

真实回归的实际耗时说明这条链路的成本结构：知识构建占了大头，方案生成次之，纯数据装配几乎不花时间。

| 步骤 | 做什么 | 本轮实测耗时 |
|---|---|---|
| load | 读取六张 CSV 与教材切片的原始行，建立快照与目录 | 0.62 秒 |
| knowledge | 范围计划、分块提取、去重、关系、题目与评分点对齐、独立复核、发布 | 12 分 59.94 秒 |
| analysis | 清洗、指标、掌握状态、错因诊断、班级汇总，逐生发布 | 1 分 41.88 秒 |
| plans | 需求聚合、策略、选题、任务组、微课堂、审核、发布 | 7 分 21.05 秒 |

调度顺序由依赖决定，不由教师手点。上传确认后先建目录与知识构建任务；知识正式发布后按可用范围投递个人与班级分析；分析正式后有方案任务。任何一个环节失败只影响依赖它的下游，已完成且仍适用的旧正式版本继续可读，并标记为待更新〔D06〕§6。

状态被拆成三个互不替代的维度：执行状态（等待、运行、成功、失败、取消）、审核状态（草稿、待复核、通过、拒绝）、发布状态（未发布、已发布、被取代）。四步链路“成功”只说明任务跑完了，不说明内容通过审核，更不说明学生能看到。页面上的“已发布”必须对应一条真实的发布记录与一个可读的正式指针，三者任一缺失都只能显示为未完成。这条规则在回归里被验证过一次：任务 `succeeded`、审核 `validated`、`publications` 有记录，而 payload 里的发布字段仍写着 unpublished，页面按发布记录显示，导出按发布记录判断，源码状态的不一致被单独记成缺陷，没有掩盖。

### 2.4 一次学习事件的闭环

静态成果只是链路的一半，另一半是学生真实作答带来的更新。这条闭环的每一步都有明确的作用范围，避免“一个新答案重算全库”。

| 触发 | 系统动作 | 影响范围 |
|---|---|---|
| 学生开始活动 | 服务端建尝试、写开始事件，返回题目安全视图 | 本人当前活动 |
| 提交答案 | 先落库并置待评分，再调评分；选择题规则判、填空题规则加等价表达、解答题模型初评加独立复核 | 本次尝试 |
| 评分完成 | 写评分修订事件；不可靠评分隔离，不给有效分 | 本次尝试 |
| 完成一组 | 服务端按必需活动判定组完成，写事件并入队 | 本人该节点 |
| 局部学情更新 | 只重算受影响节点与该学生，班级汇总刷新对应成员版本 | 本人 + 所在班级 |
| 方案复查 | 读新学情判断原方案是否仍适用；适用则只写检查记录，不造新版本 | 本人方案 |
| 成果读取 | 页面、Agent、导出读同一正式版本，数字一致 | 授权范围 |

三个细节决定了这条闭环的可信度。事件账本只追加、不修改，帮助事件与作答事件在同一个账本里，B 判断独立性时读账本，不读前端声明。评分失败保存提交并置为待评分，不会把空分当零分。方案复查没有变化时保持原版本，只在适用性记录里追加一行，避免每次作答都产生一串没有实质差异的新方案。

### 2.5 版本与证据链

系统的可核对性来自一条规则：每个正式结论都能追到它当时用的输入版本，且版本之间不靠“最新”猜测。七类标识各管一段，互不替代。

| 标识 | 含义 | 不承担 |
|---|---|---|
| `dataset_family_id` | 同一批持续资料的系列身份 | 不代表某一次快照 |
| `dataset_id` | 不可变输入快照 | 不代表分析批次 |
| `catalog_version` | 题库与课程目录快照 | 不代表知识体系 |
| `knowledge_version` | A 的正式知识版本 | 不代表学生结果 |
| `analysis_version` | 单个学生或班级的分析版本 | 不代表方案 |
| `plan_version` | 学生方案版本 | 不代表微课堂正文 |
| `content_version` | 微课堂正文版本 | 不代表活动状态 |

依赖落在数据库里，是一组带角色的有向无环边。回归库里的实际边数可以说明链路的形状〔C〕：

| 边角色 | 条数 | 说明 |
|---|---|---|
| knowledge | 391 | 学情、方案、微课堂、班级对知识版本的依赖 |
| student_analysis | 311 | 派生成果对学情版本的依赖 |
| content | 160 | 活动对微课堂正文版本的依赖 |
| catalog | 85 | 知识、学情、方案对目录版本的依赖 |
| member_analysis | 80 | 班级版本对成员学情版本的依赖 |
| parent_plan | 77 | 方案修订对父版本的依赖 |

发布用条件更新（CAS）切换正式指针：版本号、代次与所需代次三者同时匹配才写入，零行即回滚并返回冲突。这样两个任务同时想发布同一学生的新方案时，晚到的那个不会覆盖先到的正式结果〔D06〕§3.4。历史版本不删除，读取时按精确版本解析；旧方案在新学情下是否仍适用，由一张独立的适用性记录回答，记录里保存当时的 B 版本、知识版本、目录版本、事件截点与活动摘要。适用、部分适用、不适用是三个不同结果，不能相互替代。

## 3 功能说明

### 3.1 教师端

教师端四个一级页面，加两个跨页面的公共能力（统一提醒入口、证据抽屉）。

| 页面 | 回答的问题 | 关键交互 | 数据来源 |
|---|---|---|---|
| 班级总览 | 这个班整体怎么样，谁需要关注 | 班级与节点切换、雷达、共性薄弱项、掌握分布、名册、班级对比 | B 正式班级与个人结果，不可比时只并列不画差值 |
| 学生画像 | 这名学生具体卡在哪，依据是什么 | 四页签（概览、进展、作答记录、方案）、诊断展开、证据抽屉、方案审核 | B 正式结果 + 统一证据解析器 |
| 课程体系 | 知识图谱长什么样，哪些候选待处理 | 主题分页、主题内网络布局、关系图例、候选审核、质量报告 | A 正式快照与候选队列 |
| 数据管理 | 这批数据质量如何，成果能否导出 | 上传与分类确认、任务链进度、质量报告、导出预检与下载 | 导入回执、任务事件、质量报告、导出清单 |

两个公共能力值得单独说明。统一提醒入口把 A 的候选异常、C 的方案审核、B 的教师介入汇总成三类待办，点进去定位到具体对象；已读不等于已处理，结案需要教师填写原因并带上证据截点。证据抽屉按引用类型分五种渲染：作答记录、指标、课程与知识、派生结论、学习事件；每种都显示精确版本、限制与可继续展开的关联引用，不显示整份 JSON。

方案有三条发布路径，教师需要知道自己在走哪一条。自动生成走完整审核后自动发布；Agent 发起的修改走同一套完整审核，只多一条真实授权记录；教师在编辑器里直接改，只需通过身份、版本、数据、材料、历史、组件与答案保护这些硬检查，教学合理性警告可以知悉后继续，发布标记为人工确认〔D04〕§8。三条路径都留版本、原因、历史与恢复记录。

### 3.2 学生端

学生端三个一级页面：个人画像、学习计划、AI 对话。

个人画像只读本人正式结果，展示指标、文字诊断、学习进展与本人依据，明确区分“优势”“需要加强”“暂需更多证据”。没有足够证据的知识点不会被打上薄弱标签，这一条直接对应 B 的证据充分性设计。

学习计划按任务组组织。每组有目标、主策略、预计时长、预期结果与必需活动；活动状态由服务端根据真实事件维护，前端只算“已完成必需活动数/总数”，不自行判定组完成。作答支持选择、填空、解答三种题型，解答题保留原始换行与数学符号，中文输入法组词期间不触发提交。

三级提示按层释放：第一层给知识点线索，第二层给方法方向，第三层给尚未完成的关键动作。学生每请求一层，服务端记录一条真实事件，重读同一层不重复计数。独立补证或迁移检查的题目多一道门：先明确告知“获取帮助后本题不再作为独立完成的证据”，学生选择继续才释放内容，这条选择本身也入账本。

提交后反馈分两级。逐题反馈显示得分、评分点与安全提示；整组反馈要等 B 完成局部重分析、C 完成复查之后才出现，且只显示真实发生的变化。待评分与待复核期间页面显示“已提交，待评分”，不给 0 分。

### 3.3 Agent 对话

Agent 承担八类任务，权限按角色切开。

| 任务类别 | 教师 | 学生 | 主要工具 |
|---|---|---|---|
| 学情查询与解释 | 授权班级 | 本人 | 学生分析、作答证据、证据解析 |
| 班级学情分析 | 授权班级 | 禁止 | 班级分析、班级对比 |
| 课程知识与关系查询 | 允许 | 授权资料 | 知识定位、详情、关系、候选 |
| 学习方案查询与解释 | 允许 | 本人 | 方案、历史、理由、介入 |
| 学习方案修改 | 明确授权范围 | 禁止 | 准备候选、优化、提交、状态 |
| 知识讲解与解题引导 | 允许 | 允许，受答案保护 | 活动上下文、微课堂、回复校验 |
| 数据质量查询 | 允许 | 禁止 | 质量问题、质量报告 |
| 学习进展分析 | 允许 | 本人 | 进展比较、学习事件 |

Agent 的能力边界写进了执行循环：任务路由最多六个子任务、依赖无环；工具白名单按任务与角色下发，参数由程序校验目标、版本与范围；模型提出的写请求只生成候选，提交由服务端调度层按授权记录触发；每次工具调用留轨迹，前端显示中文阶段与状态，不显示参数、内部推理或密钥。多轮对话可以承接上一轮的对象，但每次实际修改都重新校验授权，切换对象不沿用旧授权。

学生端另有一条受助通道。学生请求解题帮助时，若当前处于独立检查，先弹受助确认；确认后服务端写入受助选择事件，再释放引导；实际释放成功才追加帮助事件，用于 B 判断本次是否独立完成。

一次典型的改写流程如下（示意）：教师说“把 D01 下一组练习减到 3 题”，系统先读该生当前正式方案（假设为 V7），C 在规则基线上给出 5 题减到 3 题的候选，Agent 核对候选差异是否落在教师明确授权范围内；确认后提交，任务经完整审核通过并发布为 V8，回复里显示真实版本差异，不写“已为您调整”这类没有依据的话。如果确认时该生方案已被另一次操作改成 V9，提交返回 409，原候选不执行，系统提示重新预览；这种情况下没有“部分成功”可讲，也不允许把旧候选硬套到新版本上。

反过来，教师说“帮他调整一下”这类含糊请求不会直接执行。系统先按授权范围列出对象与拟改内容，等教师在确认卡上选择；批量请求先固定名单，逐人准备候选、逐人审核、逐人提交，其中一人失败不影响其他人，失败的学生保留原方案并单独列出。

### 3.4 微课堂

微课堂是学习计划里的独立活动，不算题目、不占题库编号、不产生分数。正文由六类封闭组件组成，服务端定 schema、前端按类型渲染。

| 组件 | 作用 | 数学与安全检查 |
|---|---|---|
| text | 段落讲解 | 纯文本转义，不解析 HTML |
| formula | 单个公式 | 受限表达式解析后生成排版，非法退回修复 |
| derivation | 分步推导 | 相邻步骤按多项式系数或解集比较，拒绝增根、丢根、翻号错误 |
| contrast | 正误对照 | 校验正确式与原始式等价、错误式不等价 |
| number_line | 数轴与区间 | 有理数精确比较端点与开闭，交集结果独立验算 |
| citation | 引用 | 索引必须存在且授权，学生看不到教师专有证据 |

生成走 fail-closed。模型产出先过结构与长度校验，再过八项内容复核（数学、每步推导、证据、出处、结构、后续题答案、步骤相似、顺序与诊断污染）；任一项不通过先做一次最小修复，仍不通过就退回已审核的规则模板，绝不把未经验证的内容发给学生。

本轮回归里 160 份微课堂中 154 份由规则模板生成、6 份由真实模型生成并通过八项复核；引用组件 160 条全部可解析到知识点与知识版本〔R〕§4.3。这同时暴露一个限制：教材原文来源一条都没有登记，所以微课堂只有知识点依据、没有教材引用（第 7 章）。

导出先冻结一份选择，再按选择组装，不做整库搬运。冻结时锁定每个对象的精确版本、事件截点、政策哈希与范围，然后做依赖闭包：方案要带上它生成时用的 B 版本，班级要带上全部名册成员的个人版本，微课堂要带上正文版本。任何一环缺失或未发布，导出直接拒绝，不做降级拼装。

### 4.4 质量门与真实失败

这一轮最重要的验证不是一次“全绿”，而是一次失败被质量门拦住，随后通过修复生成逻辑解决。

第一次导出时：

| 对象 | 问题 | 处置 |
|---|---|---|
| D14 / N01 方案 | 得分率 0.91 却描述为“存在具体错误”，证据与策略不一致 | 判 needs_review，不发布 |
| D14 / N02 方案 | 活动标题与受保护题干完全一致；部分活动顺序缺少独立检查 | 判 needs_review，不发布 |
| 全库预检 | `ready=false`，阻塞项 `PLAN_UNPUBLISHED / D14` | 导出返回 422 `EXPORT_INCOMPLETE`，未生成半包 |
| D17 / N02 方案 | 0 组 0 推荐却已按旧规则发布 | 后续增加空方案发布门，强制重新生成 |

这条失败链证明了三件事。模型复核确实独立于生成，能拦下生成侧没发现的问题；审核状态与发布状态确实分离，任务成功不等于发布成功；导出质量门确实在组装之前生效，没有为了出包而放宽范围。

修复方式不是改发布状态，而是改生成逻辑：

1. 规划器按证据选策略，高分迁移类信号不再安排“具体错误纠错”。
2. 活动标题不再使用题目正文，统一用“练习题 Qxxx”。
3. 空方案禁止正式发布；无观察学生生成“补观察”方案。
4. 学生重新分析每次创建新任务，不被旧幂等结果复用。
5. D14、D17 重新生成后，全库预检 `ready=true`，才生成最终 ZIP。

## 5 创新点

### 5.1 规则定值，模型释义

系统把“算”和“说”分开：所有进入结论的数字由规则算出，模型只负责把结论讲清楚，且不允许改动数字、诊断依据或引用。B 的指标、掌握状态、评分校验如此；C 的策略判定、候选资格、优先级与负担控制也如此，模型只在合法候选集合内调整组合与表达。这条分工让同一份输入在任何时候重放都能得到同一组数字，也让评委可以把模型关掉再跑一遍，检查结论是否还成立。

以一次作业的三种题型为例，边界看得很清楚。选择题由规则直接比对，模型完全不参与；填空题先做规则匹配，再比对等价表达，仍由规则定分；解答题才交给模型，模型给出分项得分与理由，程序随后校验得分是否落在 0 到满分之间、分项之和是否等于总分、每个分项是否引用了本次真实作答。任一项不成立，这次评分不进入正式证据，学生看到的状态是待复核。三条路径不同，最后都落到同一张评分修订表上，谁也不能绕过校验。

### 5.2 生成与审核分离

每个模型产物都另起一次独立调用做复核，复核方只拿待审对象与原始依据，不拿生成方的理由或自评。去重需要两次独立判断都为“同一”才合并；关系、映射、方案与微课堂各有自己的检查清单，缺项、重复、伪造依据一律判失败。真实数据上这套机制拦下了 D14 的答案保护与证据不符问题，说明复核确实能发现生成侧漏掉的问题。

这套机制的代价是模型调用量大约翻倍：一轮方案生成要跑优化、内容、独立审核、修复、复审五类任务，预算按每个方案八次请求封顶，超出即暂停并保留上一份可靠方案。我们接受这个成本，理由是错误内容一旦发到学生端就无法撤回，而多一次复核只是多花几十秒。

### 5.3 版本依赖可执行

版本在库里是一组依赖边加条件更新，版本号只是它的对外名字。每份方案记录它用的学情、知识、目录版本与事件截点；每份班级结果记录成员的个人版本；依赖边带角色并检查无环；发布用 CAS 切换指针，晚到的任务不能覆盖新版本；旧方案在新学情下是否仍适用，单独记录适用性与限制，不靠“最新”推断。于是“这份建议当时依据什么”这个问题，任何一个对象都能在库里回答。

### 5.4 答案保护贯穿通道

同一套保护集合在六个通道上复用：题目接口、提示接口、Agent 引导、微课堂引用、证据解析、缓存键。三级提示按层释放，累计内容也要检查；引导回复先做结构比对（同题、轻微改数字的克隆、连起来等价于完整解答），再做独立语义复核；独立检查下的帮助必须先取得学生确认并写入账本。帮助事件只有一个账本，B 判断独立性时读它，不读前端声明。

### 5.5 默认关闭的失败策略

系统在四个位置选择 fail-closed：模型未配置或超时，保留确定性结果并标注降级，不生成假内容；审核缺项或依据不可解析，停止自动发布；微课堂复核不过，退回已审核模板，不放行未验证内容；导出缺必需版本，返回 422 并列出缺项，不打不完整的包。这一取舍会让某些轮次看起来“没做完”，但它保证已经交出去的东西都能被核对。

### 6.2 完成方式

系统以本地双端 Web 应用形态完成：后端一套服务同时供教师端与学生端；身份用本地模拟身份选择，服务端会话绑定角色与范围，不依赖生产级认证；数据、成果与证据全部落在本机，不依赖云服务。

开发按依赖分阶段推进，每个阶段单独留证据。先是共享契约与数据模型：字段取并集、保留旧接口兼容、迁移可重复执行；再按 A、B、C 的依赖顺序实现业务并各自独立测试，A 的产出是 B 的输入，B 的产出是 C 的输入，任何一段没通过不向下游放行；然后接 Agent 的受控工具循环，最后接 Web 闭环。每一阶段的测试命令、实际输出、通过数与未通过项都记在仓库的验收对照里，计划中的测试不写成已通过。

这套做法有一个直接后果：进展不均匀。业务链路跑得比交互层远，后端比前端完整，数据比文档细致。第 7 章的限制清单就是这种不均匀的清单，读者不必从文字里猜哪些做了、哪些没做。

### 6.3 数据使用范围

赛方提供的六张模拟学情 CSV、八份教材切片与课程标准 PDF 仅在本机授权范围内使用。系统不使用真实学生个人信息；赛方原始数据不进入公开样例，不作为前端演示数据；演示模式只用明确标记的合成数据，且与真实模式共用页面但不共用数据源。模型调用只发送完成任务所需的最小文本片段，外发授权默认关闭，本轮由本机配置显式开启；页面图像与扫描件不在外发范围（视觉识别能力本轮未实现）。赛后按赛事要求删除本地赛料副本。
