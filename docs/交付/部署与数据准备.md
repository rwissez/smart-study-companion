# 湛知部署与数据准备

- 更新时间：2026-11-28
- 适用对象：第一次克隆仓库、需要在本机把湛知跑起来并导入独立评测数据的人
- 范围：安装、配置、数据库迁移、六张 CSV 的字段口径、导入流程、独立评测数据准备清单、导出预检、常见失败
- 边界：本文只描述当前代码的行为。真实模型与赛方数据下的验收仍为 `not_run`，见文末「本轮验证范围」

最短路径：

```text
1. uv sync --locked
2. cd frontend; npm install
3. Copy-Item .env.example .env（需要模型时填写三要素与密钥）
4. uv run alembic upgrade head
5. 启动后端 8000 与前端 5173
6. 教师身份进入「数据管理」导入六张 CSV
7. 「成果导出」预检通过后生成正式包
```

## 1 前置条件

| 组件 | 要求 | 检查命令 |
|---|---|---|
| Python | 3.12.x（`pyproject.toml` 限定 `>=3.12,<3.13`） | `uv run python --version` |
| uv | 用于安装依赖与运行命令 | `uv --version` |
| Node.js | 22.12 及以上（`frontend/package.json` 的 `engines` 要求） | `node --version` |
| npm | 随 Node.js 安装 | `npm --version` |
| 操作系统 | Windows 10/11、Linux；macOS 同理。`启动湛知.bat` 只在 Windows 可用 | — |
| 端口 | 后端 8000、前端 5173 未被占用 | `Get-NetTCPConnection -LocalPort 8000` |

系统 PATH 里的 `python` 可能不是 3.12，这不影响使用：`uv sync` 会按项目要求选择 3.12。如果本机没有 3.12，先执行：

```powershell
uv python install 3.12
```

Linux 下把下文 PowerShell 命令换成等价 bash 命令即可，`uv`、`npm`、`curl` 的用法相同。

## 2 安装

在仓库根目录执行：

```powershell
uv sync --locked
cd frontend
npm install
```

说明：

- `uv sync --locked` 严格按 `uv.lock` 安装依赖，会创建 `.venv`。锁文件与 `pyproject.toml` 不一致时命令会失败，这时不要绕过 `--locked`，先确认拿到的提交与锁文件是否配套。
- `npm install` 按 `package-lock.json` 安装前端依赖。需要可复现安装时可以用 `npm ci`。
- `.venv/`、`node_modules/` 都不进 Git，每个克隆都要各自安装一次。
- 前端默认连接 `http://127.0.0.1:8000/api/v1`，一般不需要 `frontend/.env.local`。要改后端地址或端口时，复制 `frontend/.env.example` 为 `frontend/.env.local`，设置 `VITE_API_BASE_URL`。`VITE_DATA_SOURCE` 默认是 `api`，只有显式写 `demo` 才用演示数据。

安装完成后回到仓库根目录，后续命令都在根目录执行。

## 3 配置 `.env`

### 3.1 必须复制模板

```powershell
Copy-Item .env.example .env
```

```bash
cp .env.example .env
```

`.env` 已被 `.gitignore` 排除。交付与评测环境必须复制并逐项检查；只靠代码默认值可以空跑，但模型、外发授权、路径都没有显式配置，不能算完成部署。

`.env` 是后端进程启动时读取的初始配置，改完要重启后端。教师界面里的「模型与外发授权」写在 `data/model-settings.json`，会覆盖 `.env` 的同名字段，不需要重启。

### 3.2 关键配置项

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `APP_ENV` | `development` | 运行环境标识 |
| `DEMO_MODE` | `true` | 本地模拟身份入口。关掉后 `/demo-sessions` 返回 404，前端无法选身份 |
| `DATABASE_URL` | `sqlite:///./data/app.sqlite3` | 相对路径按仓库根解析 |
| `DATA_ROOT` | `./data` | 原始文件、快照、模型设置、数据库所在目录 |
| `OUTPUT_ROOT` | `./outputs` | 导出 ZIP 所在目录 |
| `JOBS_WORKER_ENABLED` | `1` | 进程内启动单线程 worker；设为 0 时不自动跑任务 |
| `MODEL_PROVIDER` | 空 | 必须精确填 `openai_compatible`，其他值按未配置处理 |
| `MODEL_BASE_URL` | 空 | OpenAI 兼容接口根地址，填到 `/v1` 这一层，例如 `https://api.example.com/v1`；程序会自己拼 `/chat/completions` 和 `/models` |
| `MODEL_NAME` | 空 | 模型编号，例如 `deepseek-chat` |
| `MODEL_API_KEY` | 空 | 只保存在本机，不进日志、不进导出、不进 Git |
| `ALLOW_EXTERNAL_MODEL_INPUT` | `false` | 远端模型外发授权。`127.0.0.1`、`localhost` 视为本地，不需要打开 |

模型三要素指 `MODEL_PROVIDER`、`MODEL_BASE_URL`、`MODEL_NAME`。要用模型能力，三要素与 `MODEL_API_KEY` 四项都必须填写。三项齐全时 `GET /api/v1/health` 的 `model_configured` 为 `true`；再填 `MODEL_API_KEY` 才能完成真实调用。只填三要素、不填密钥时健康检查仍显示已配置，但调用会返回 `MODEL_NOT_CONFIGURED`（模型凭据不可用）。

`MODEL_PROVIDER` 必须是 `openai_compatible`。填成 `openai`、`deepseek` 等值时，即使地址与模型编号正确，系统也会使用未配置适配器并返回 `MODEL_NOT_CONFIGURED`。健康检查只判断三要素是否非空，不校验提供方名称与密钥，所以 `model_configured=true` 不代表调用一定成功。

### 3.3 两种配置方式

- 启动前写 `.env`：适合交付、评测、无人值守环境。改完重启后端生效。
- 启动后由教师配置：教师进入「数据管理」→ 右上角「模型与外发授权」，填写提供方、接口地址、模型编号、API 密钥，勾选外发授权，保存后可点「测试连接」。密钥只提交给本机后端，读取接口只返回 `has_api_key`。「测试连接」只请求 `/models` 判断地址可达，不校验密钥是否有效，也不代表教学输出通过验收。

远端模型必须显式授权外发，否则调用返回 `MODEL_EXTERNAL_NOT_ALLOWED`。授权前确认赛方与学校允许把题目、作答、教材片段发送给该服务商；未获授权时不要打开。

### 3.4 不配置模型时哪些功能降级

| 功能 | 未配置模型时的行为 | 是否可用 |
|---|---|---|
| 安装、迁移、导入、数据集列表、名册 | 不涉及模型 | 可用 |
| A 课程知识体系（课程要求 → 主题、指标、知识点、关系、覆盖） | 走规则路径；教材页面语义提取、公式核对、关系判断不执行 | 可用，结果标注规则来源 |
| B 学情统计、选择/填空规则评分、进展、班级画像、诊断 | 走规则路径；解答题按评分点逐项评分不执行 | 可用；解答题保持「待复核」，不给分 |
| C 方案生成、负担、策略、审核、发布 | 规则路径完整，自动审核后发布 | 可用 |
| C 方案模型独立复核 | 不调用模型，保留规则审核结果 | 不可用，不阻断发布 |
| 微课堂 | 规则模板生成，来源标注「规则模板生成，已审核」 | 可用 |
| Agent 对话与教学解释 | 需要模型；语义回答返回 503 `MODEL_NOT_CONFIGURED`，部分对象可给规则摘要 | 语义对话不可用，正式页面可读 |
| 模型连接测试 | 返回 503 `MODEL_NOT_CONFIGURED` | 不可用 |
| 正式成果导出 | 只打包已发布的正式版本，不调用模型 | 可用，前提是方案已发布 |

导入时没有配置模型，之后补配不会自动重算已经生成的方案与微课堂。知识体系可以单独重建（`POST /api/v1/datasets/{dataset_id}/knowledge/rebuild`），单个学生的学情可以重跑（`POST /api/v1/datasets/{dataset_id}/students/{student_id}/analysis/rerun`）。需要让模型参与整条链路时，先配好模型再导入，或用同一份六表作为新数据集重新导入。

## 4 数据库：必须先迁移

```powershell
uv run alembic upgrade head
uv run alembic heads
```

预期 `alembic heads` 输出单头：

```text
0006_delivery_backfill (head)
```

要点：

- 应用启动时不会自动建表。空库直接访问业务接口会因缺表失败，通常表现为 500 `INTERNAL_ERROR`，后端日志里有 `no such table`。
- 默认配置下，迁移会创建 `data/app.sqlite3` 及父目录。首次部署、每次升级代码后都要执行。
- 已有数据库升级前先备份，再执行迁移；不要删除 `data/app.sqlite3` 重来，历史版本、正式指针与评分修订都会丢。
- 启动器 `启动湛知.bat` 在需要启动后端时会先执行 `python -m alembic upgrade head`，迁移失败则不启动后端，日志在 `_local/launcher/backend.err.log`。

备份与恢复：

```powershell
uv run study-companion backup --out .\backup\2026-11-28
uv run study-companion verify-backup .\backup\2026-11-28
uv run study-companion restore .\backup\2026-11-28 --target .\restored
```

## 5 哪些内容不随仓库下载

| 路径或内容 | 是否随 Git | 说明与准备方式 |
|---|---|---|
| `.env` | 否 | 从 `.env.example` 复制，填写本机配置 |
| `data/` | 否 | 克隆后不存在，首次迁移与运行时创建；含 `app.sqlite3`、`blobs/`、`snapshots/`。历史数据要另行备份恢复 |
| `outputs/` | 否 | 导出 ZIP 的输出目录，首次导出时创建 |
| `data/model-settings.json` | 否 | 教师界面保存模型设置时创建；密钥只在本机 |
| 赛题数据、教材与课标原件 | 否 | 放在本机授权目录，按本文第 6、7 节导入；不要提交到 Git |
| `tests/fixtures/six_tables/` | 是 | 合成样例，只用于验证机制，不证明真实教学效果 |
| `.venv/`、`node_modules/` | 否 | 每个克隆自行安装 |

只克隆仓库，得到的是代码、文档与合成样例。要复现交付里的数据集、导出包或模型效果，需要自己准备原始数据、模型凭据与备份。

通过 `/imports` 导入的合成样例在数据集摘要里会显示为「正式导入数据」，因为服务端只按导入入口记录来源。`tests/fixtures/` 的内容仍是合成样例，不能当作真实教学证据。

## 6 六张 CSV 的字段口径

### 6.1 通用规则

- 六张逻辑表分别是课程要求、题目与材料、模拟学生、测验节点、作答记录、字段说明。文件名不参与识别，程序按表头判断角色。
- 每个 CSV 必须是 UTF-8 编码（可带 BOM）。不是合法 UTF-8 时整包拒收。
- 表头不能为空、不能重复，不能出现保留列名 `source_row_number`。
- 每个文件至少有一行数据。空文件会让整次导入失败。
- 单文件上限 32 MB，一次最多 12 个文件（可用 `MAX_UPLOAD_BYTES`、`MAX_UPLOAD_FILES` 调整）。
- 一张 XLSX 工作簿可以包含六个工作表，程序按每个工作表的表头识别角色；多出来的说明表会被标为待确认，确认时给六张表指定角色即可。首次导入建议直接用六个 CSV。

各逻辑表的识别列（表头必须同时包含这些列，缺一列就无法自动识别）：

| 逻辑表 | 官方文件名 | 识别列 | 结构必填列 |
|---|---|---|---|
| 课程要求 | `课程要求.csv` | 主题编号、指标编号、观察指标 | 同识别列（未通过识别就没有目录） |
| 题目与材料 | `题目与材料.csv` | 材料编号、材料类型、题干或内容 | 材料编号 |
| 模拟学生 | `模拟学生.csv` | 学生编号、模拟班级编号 | 学生编号、模拟班级编号 |
| 测验节点 | `测验节点.csv` | 节点编号、模拟测验日期 | 节点编号 |
| 作答记录 | `作答记录.csv` | 记录编号、学生编号、材料编号、节点编号 | 记录编号、学生编号、材料编号、节点编号 |
| 字段说明 | `字段说明.csv` | 数据表、字段名 | 至少一行数据 |

### 6.2 课程要求

字段：`主题编号`、`主题`、`主题目标`、`指标编号`、`观察指标`、`课标整理编号`、`课标文件页／正文页`、`教材正文页`。

- 一个指标一行。同一主题下可以有多条指标。
- `主题目标` 与 `观察指标` 是 B 生成学情指标与 A 生成知识点的文字依据，尽量写完整句子。
- `课标整理编号`、`课标文件页／正文页`、`教材正文页` 用于来源定位，可以留空。页码按原文填写，印刷页码与 PDF 页码不是一回事，定位结果需要人工核对。
- 多值字段用顿号分隔，例如主题下挂多个课标编号。

### 6.3 题目与材料

字段：`材料编号`、`主题编号`、`材料类型`、`题型`、`题干或内容`、`选项`、`参考答案`、`参考解析`、`满分`、`评分点`、`指标编号`、`来源或资料文件`。

- `材料类型` 取值：`题目`、`学习卡`、`教材`。
- `题型` 取值：`选择题`、`填空题`、`解答题`。学习卡可以不填题型。
- `选项` 每行一个，以 `A.`—`D.` 起始。
- `满分` 填整数。`评分点` 每行一个，格式为「编号 内容 分值」，例如 `Q001P1 答案正确 1分`。解答题建议填写评分点，B 才能按点复核。
- `指标编号` 可以有多个，用顿号分隔；每个编号都要在课程要求里存在。
- `来源或资料文件` 是来源标签（例如「赛事新编」「教材上册」），程序不按它读取磁盘文件。

### 6.4 模拟学生

字段：`学生编号`、`模拟班级编号`、`年级`。

- 学生编号在数据集内唯一；重复编号只保留第一条。
- 班级编号用于班级画像与班级比较。一个班至少一名学生。
- `年级` 保留为字符串，可写「七年级」或「7」。

### 6.5 测验节点

字段：`节点编号`、`模拟测验日期`、`已教及测量主题`、`说明`、`可用题目编号`。

- 一个节点代表一次测验或一次观察。
- `可用题目编号` 列出该节点允许作答的材料，多个用顿号分隔。记录里的材料不在该节点可用集合时，系统保留分数并标记「材料与节点不匹配，待复核」，不改分。
- `已教及测量主题` 用于教学范围说明，可以留空。

### 6.6 作答记录

字段：`记录编号`、`学生编号`、`材料编号`、`主题编号`、`节点编号`、`作答事件编号`、`修订版本`、`模拟提交时间`、`评分状态`、`得分`、`满分`、`学生最终作答`、`解答过程`、`评分点得分`。

- `评分状态` 取值：`已评分`、`待评分`、`未作答`。缺失时按得分与作答内容推导。
- `得分` 为整数。`0` 是有效零分；留空表示没有有效分数，不当作零分。
- `满分` 与得分同时出现；已评分但缺满分时，该分数不进入得分率统计。
- 同一 `作答事件编号` 可以有多条 `修订版本`。系统只取最高版本，旧版本保留并记一条提示；最高版本内容冲突时整条事件隔离，不猜分。
- `评分点得分` 格式为 `Q001P1=1；Q001P2=0`。评分点之和与得分不一致时，保留官方得分并标记待复核，不重判。
- `解答过程` 保留原始换行，不要按中文标点拆开数学式。
- 没有作答事件编号时程序按学生、节点、材料生成事件键；正式数据建议填写，便于追踪修订。

### 6.7 字段说明

字段：`数据表`、`字段名`、`类型`、`含义`、`取值或格式`、`示例`、`为空时`。

- 至少一行数据，否则整个导入失败。
- 内容随原始批次存档，供追溯与人工核对；当前不参与评分、统计与导出字段字典的生成。
- 可以只写关键字段，不要求覆盖全部列。

### 6.8 课标与教材 PDF

- 课标、教材 PDF 与六张表一起上传时会先标为待确认；在界面点「确认文件角色并继续」即可继续，PDF 默认按 `standard` 确认。要把教材标成 `textbook`，用 API 的 `file_mappings` 指定。知识抽取会读取该数据集导入的全部 PDF，不依赖这个用途标签。
- PDF 可选。没有 PDF 时，知识体系只依据课程要求、指标与材料生成，导入、统计、方案、导出都能完成。
- 有教材 PDF 时，知识体系会多出定义句候选、章节与页面统计、页面级来源；配置模型后还会执行页面语义提取。导出里的知识点定义、来源引用与映射缺口会更完整。
- 课标常是扫描件，文本层不可靠；教材公式提取也可能出错。页码与公式需要人工核对，不能把自动抽取当作已核验。

## 7 导入流程

### 7.1 界面导入（推荐）

1. 启动后端与前端，打开 `http://127.0.0.1:5173`。
2. 身份页选择「教师」。还没有数据集时，按钮显示「以教师身份进入（先导入数据）」。
3. 左侧进入「数据管理」→「数据集」页签。
4. 「上传数据」里，导入方式选「新建独立数据系列」。
5. 选择六张 CSV（需要时再加课标或教材 PDF），点「上传并开始处理」。
6. 看「导入回执」：数据集显示「已创建」，后台任务显示「已排入处理队列」，缺失输入为空。
7. 切到「任务进度」，任务链会依次执行 `load`（读取快照与目录）、`knowledge`（构建课程知识体系）、`analysis`（生成学情分析）、`plans`（生成学习方案）。四步都 `succeeded` 才算跑完。
8. 在「质量」页签查看数据质量、知识体系质量、学情质量与方案质量。空列表只表示没有质量问题记录，不表示数据完美。
9. 在「成果导出」页签预检，通过后生成正式包。

### 7.2 API 导入

导入必须先有教师会话。裸教师会话（没有绑定数据集）只能建会话、列数据集、导入和选择数据集；导出预检需要绑定数据集的教师会话。

Windows PowerShell 5.1 在调用原生程序时会去掉参数里的双引号，内联 JSON 的 curl 写法容易变成非法 JSON。下面的示例用 `Invoke-RestMethod` 建会话、用 `curl.exe` 只传文件字段，避开了这个问题。

```powershell
# 1. 教师 bootstrap 会话
```

### 7.3 新数据集与新 family 的覆盖规则

- 导入时选「新建独立数据系列」，或 API 不传 `dataset_family_id`：每次都会创建新的 family 与新的 dataset，旧数据集原样保留。
- 同一份六表连续导入两次会得到两个数据集、两个 family。这是当前行为，不是去重失败。导入前先确认要新建还是补充，避免页面里出现两份同名数据。
- 要往已有系列追加新快照，必须同时传 `intent: "append_to_family"`、`dataset_family_id` 和 `expected_parent_dataset_id`。服务端会校验父快照属于该系列，新快照记录 `parent_id`，旧快照不被覆盖。
- 界面的「补充到现有系列」目前只提交 `intent`，不会自动带 family 与父快照，会被服务端拒绝（「追加导入必须指定数据集系列」）。独立评测数据请用「新建独立数据系列」。
- 不同 family 的编号互不相通。把 A 数据集的编号写进 B 数据集的六表，导入阶段不会因为编号对不上而拒收，也不会自动合并：编号相同会被当成同一实体，编号不同则归不到任何学生，两种都会让统计口径失真。

### 7.4 独立评测数据准备清单

独立评测数据建议按下面的规模与口径准备。10—20 名学生、100—400 条记录是建议区间，系统不按人数或记录数拦截；规模太小会让班级统计与证据阈值长期不足，规模太大则本机 SQLite 与首次全链路等待变长。

| 项目 | 要求 | 检查方法 |
|---|---|---|
| 规模 | 学生 10—20，记录 100—400，班级 1—2，节点 2—4，材料 30—60 | 回执 `quality_summary` 的 students/nodes/materials 与源表对照；records 是选中事件数，可能少于记录行数 |
| 六表齐全 | 课程要求、题目与材料、模拟学生、测验节点、作答记录、字段说明，每张至少一行 | 回执 `missing_inputs` 为空 |
| 学生编号闭环 | 每条记录的 `学生编号` 都在模拟学生表里 | 用表格软件做一次去重比对 |
| 材料编号闭环 | 每条记录的 `材料编号` 都在题目与材料表里 | 同上 |
| 节点编号闭环 | 每条记录的 `节点编号` 都在测验节点表里 | 同上 |
| 指标与主题闭环 | 每道题的指标编号、每个节点的主题编号都在课程要求表里 | 同上；缺失时学情指标没有定义 |
| 节点可用题 | 记录用到的材料出现在该节点的 `可用题目编号` 里 | 否则会收到「材料与节点不匹配」提示，分数仍保留 |
| 主题一致 | 记录的主题编号与材料、节点声明的主题一致 | 不一致会让指标聚合错位 |
| 评分状态 | `已评分` 记录同时有得分与满分；解答题有评分点 | 缺满分会被排除出得分率 |
| 修订版本 | 同一作答事件只保留一个最高版本，内容不要冲突 | 冲突事件会被隔离，不参与统计 |
| 字段说明 | 六表齐全即可，内容供人工核对 | 不影响导入、评分与导出流程 |
| 模型配置 | 导入前配好三要素与密钥；远端模型先授权外发 | `GET /api/v1/health` 的 `model_configured`，再发一次对话或模型测试 |
| 教材 PDF | 可选；有教材时知识定义与页码引用更完整，没有也能完成导入、统计、方案与导出 | 「课程体系」页看知识点定义与来源 |
| 数据合规 | 学生编号去标识，内容已获授权；未授权时不要开远端外发 | 检查 `.env` 与界面外发开关 |

一条记录的编号对应关系示例：

```text
课程要求：T01 / T01I1
题目与材料：Q001（主题 T01，指标 T01I1）
模拟学生：D01（班级 DC01）
测验节点：N01（可用题目包含 Q001）
作答记录：DR0001 → 学生 D01、材料 Q001、节点 N01、事件 D01-N01-Q001、版本 1
```

独立评测数据的导入顺序：

1. 需要模型能力时，先在 `.env` 或教师界面配好三要素与密钥，再开始导入。
2. 按上面的清单整理六张 CSV，需要时加上教材或课标 PDF。
3. 教师进入「数据管理」→「数据集」，导入方式选「新建独立数据系列」，上传整包。
4. 回执 `input_status=ready` 且拿到 `dataset_id`；若为 `needs_confirmation`，先确认角色。
5. 等 `load → knowledge → analysis → plans` 四步全部 `succeeded`。
6. 在「成果导出」预检，`ready=true` 后生成正式包。

这样导入的是一份新的 family，与官方 40 学生数据、其他评测批次并存，不会覆盖旧数据。

导入后按顺序核对：

1. 回执 `input_status` 为 `ready`，`dataset_id` 不为空。
2. 任务四步全部 `succeeded`。
3. 数据集摘要里的学生数、班级数、六表行数与源文件一致。
4. 「班级总览」有名册与有效观测；「学生画像」能看到指标、证据与限制。
5. 导出预检 `ready: true`，覆盖学生数与班级数符合预期。

## 8 导出预检

正式导出只打包已发布的正式成果。预检与冻结共用同一套检查，预检本身只读，不写导出记录、不入队。

```powershell
# 绑定数据集的教师会话
$body = @{ role = 'teacher'; dataset_id = 'ds-xxxxxxxx' } | ConvertTo-Json
$bound = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/v1/demo-sessions `
  -ContentType 'application/json' -Body $body
$headers = @{ Authorization = "Bearer $($bound.data.session_token)" }

# 先取运行 id
$runs = Invoke-RestMethod `
  -Uri http://127.0.0.1:8000/api/v1/datasets/ds-xxxxxxxx/runs `
  -Headers $headers

# 预检
Invoke-RestMethod `
  -Uri "http://127.0.0.1:8000/api/v1/runs/$($runs.data.items[0].run_id)/exports/preflight" `
  -Headers $headers
```

通过时返回：

```json
{
  "ready": true,
  "blocking": [],
  "warnings": [{"code": "CASE_AUTO_SELECTED", "object_key": "S01,S02,S03"}],
  "coverage": {"students": 3, "classes": 2, "cases": 3}
}
```

常见阻断项：

| 代码 | 含义 | 处理 |
|---|---|---|
| `ROSTER_EMPTY` | 数据集没有学生名册 | 检查模拟学生表并重新导入 |
| `NODE_SCOPE_EMPTY` | 运行没有节点范围 | 等学情分析完成，或检查测验节点表 |
| `STUDENT_ANALYSIS_MISSING` / `UNPUBLISHED` | 学生学情缺失或未发布 | 等任务完成；检查正式指针与发布记录 |
| `CLASS_ANALYSIS_MISSING` / `UNPUBLISHED` | 班级学情缺失或未发布 | 同上 |
| `PLAN_MISSING` / `PLAN_UNPUBLISHED` | 方案缺失或未发布 | 在方案审核里发布，或重新生成后再预检 |
| `KNOWLEDGE_UNPUBLISHED` | 知识体系未正式发布 | 处理知识审核项后重建 |
| `DEPENDENCY_CROSS_FAMILY` | 依赖版本跨 family | 确认导出范围与数据集是否同一系列 |
| `APPLICABILITY_INCOMPATIBLE` | 方案对当前学情不再适用 | 重新生成方案 |

方案未发布是常见的阻断之一。模型复核给出阻断问题、或方案内容为空时，方案会停在 `needs_review`。这时不能绕过预检直接导出，只能发布方案或重新生成后再预检。

预检通过后生成：

```powershell
$body = @{ format = 'zip' } | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:8000/api/v1/runs/$($runs.data.items[0].run_id)/exports" `
  -Headers $headers -ContentType 'application/json' -Body $body
```

导出任务完成后从 `GET /api/v1/exports/{export_id}/download` 下载 ZIP。

## 9 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 对话返回 503 `MODEL_NOT_CONFIGURED` | 三要素没填、`MODEL_PROVIDER` 不是 `openai_compatible`、密钥无效（401/403 也会映射成这个码） | 补齐三要素与密钥；`.env` 改完重启后端；界面改完可直接重试 |
| 返回 500，错误码 `MODEL_EXTERNAL_NOT_ALLOWED` | 模型地址不是 loopback，且没有授权外发 | 确认合规后打开 `ALLOW_EXTERNAL_MODEL_INPUT` 或界面勾选 |
| 空库启动后接口 500，日志 `no such table` | 没有执行迁移，应用不会自动建表 | `uv run alembic upgrade head` |
| 查询另一个数据集返回 403 `FORBIDDEN` | 教师会话已绑定数据集，跨数据集访问被拒 | 在身份页重新选择数据集，或新建绑定该数据集的会话 |
| 导出返回 422 `EXPORT_INCOMPLETE`，明细含 `PLAN_UNPUBLISHED` | 方案未发布 | 发布方案或重新生成，再预检 |
| 导入返回 `input_status: incomplete` | 缺少某张逻辑表 | 按 `missing_inputs` 补齐六表后整包重传 |
| 导入返回 `needs_confirmation` | CSV 表头无法识别、XLSX 有多余工作表，或 PDF 角色未定 | 用 `POST /imports/{id}/confirm` 指定角色 |
| 追加导入报「必须指定数据集系列」 | `append_to_family` 没带 `dataset_family_id` 与父快照 | 补两个 ID；独立数据请改用 `new_family` |
| 前端页面能开但数据全报错 | 后端没启动、端口不对、`VITE_API_BASE_URL` 指向错误 | 先看 `GET /api/v1/health`；前端不会回退演示数据 |
| 启动器提示 8000 或 5173 被占用 | 其他进程占用端口，或上一轮服务没停 | 双击 `停止湛知.bat`，或换端口手动启动 |
| 迁移报多 head 或版本不匹配 | 代码与数据库版本不一致 | `uv run alembic heads` 看单头；先备份再处理，不要删库 |

## 10 最短验证

按顺序执行四条，全部通过说明最小链路可用。以下命令在仓库根目录执行。

```powershell
# 1. 后端健康检查：database_ok=true；配置了模型时 model_configured=true
curl.exe -s http://127.0.0.1:8000/api/v1/health

# 2. 前端 5173：返回 200
curl.exe -s -o NUL -w "%{http_code}" http://127.0.0.1:5173/

# 3. 导入合成六表：返回 dataset_id 与 job_id，input_status=ready
$session = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/v1/demo-sessions `
  -ContentType 'application/json' `
  -Body (@{ role = 'teacher' } | ConvertTo-Json)
$token = $session.data.session_token
$form = @()
Get-ChildItem tests\fixtures\six_tables\*.csv | ForEach-Object {
  $form += @('-F', "files=@$($_.FullName)")
}
$receipt = curl.exe -s -X POST http://127.0.0.1:8000/api/v1/imports `
  -H "Authorization: Bearer $token" @form | ConvertFrom-Json
$receipt.data | Select-Object dataset_id, job_id, input_status

# 4. 导出预检：ready=true
$ds = $receipt.data.dataset_id
$bound = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/v1/demo-sessions `
  -ContentType 'application/json' `
  -Body (@{ role = 'teacher'; dataset_id = $ds } | ConvertTo-Json)
$headers = @{ Authorization = "Bearer $($bound.data.session_token)" }
$runs = Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/datasets/$ds/runs" -Headers $headers
$runId = $runs.data.items[0].run_id
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/runs/$runId/exports/preflight" -Headers $headers
```

第 3 步后等任务四步都 `succeeded` 再执行第 4 步。合成样例通常几秒完成，真实评测数据可能几分钟；预检要求学情与方案已经落库并发布。

Linux 下把第 1、2 步换成：

```bash
curl -s http://127.0.0.1:8000/api/v1/health
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:5173/
```
