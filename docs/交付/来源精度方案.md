# 材料来源精度方案

版本 v1.0｜2026-11-28｜只读审计与核验模块

## 1. 现状

正式目录共 65 项材料：54 道题（Q001—Q054）、3 张学习卡（L01—L03）、8 项教材（B01—B08）。

正式导出 `materials_index.json` 的现状是：

- 65 项材料的 `source_refs` 全部为 `verification_status=unverified`，`locator_level=label_only`。
- 题目和学习卡的 `source_file` 是“赛事新编”，没有 `source_row_number`，也没有可逐字核对的 `quote`。
- 8 项教材的目录 `source_locator` 只登记了 PDF 路径，没有 `file_id`、`pdf_page`、`printed_page`。
- 58 项材料有正式知识点关联，7 项教材没有：B01、B03、B04、B05、B06、B07、B08。

外部报告 FINAL-04 的统计与上述数字一致：

- `materials=65`
- `materials_with_source_refs=65`，但全部 unverified
- `materials_with_kp_refs=58`
- `materials_without_kp_refs=7`

对应证据在 `docs/交付/_build/explore/exports.json` 的 `content_checks` 中。

本次改动只回答一个问题：在不伪造教材页码的前提下，实际能核验多少条材料，不能核验的原因分别是什么。数据库和正式导出都不改。

## 2. 设计原则

1. **精确匹配**：题目和学习卡只认材料编号或题干原文的逐字相同；教材只认 PDF 页面文本中逐字相同的题干或定义句。
2. **唯一匹配**：同编号、同题干、同句多页命中都算无法唯一定位，保持 unverified，不挑其中一条。
3. **页码零推断**：教材页码只从真正命中的页面对象读取。找不到、命中多页、文件未登记时，`pdf_page` 一律为空。
4. **知识点只投影**：只使用正式 annotations 和正式 source_locators。默认不启用指标回退，不新增没有依据的材料—知识点关联。
5. **只读审计**：审计用 SQLite `mode=ro` 连接，只输出结论，不写数据库、不写正式导出 ZIP。

## 3. 模块与接口

包位置：`src/study_companion/sources/`。

### 3.1 输入对象

| 对象 | 字段 | 说明 |
| --- | --- | --- |
| `MaterialInput` | `material_id`、`material_type`、`content`、`source_locator`、`source_label`、`indicator_ids` | 待核验材料。`source_locator` 保留目录已有字段。 |
| `RawMaterialRow` | `row_number`、`payload`、`file_id`、`source_file`、`dataset_id`、`table_name` | 原始材料表逻辑行，`table_name` 固定为 `materials`。`row_number` 从 1 开始。 |
| `TextbookPage` | `file_id`、`pdf_page`、`text`、`printed_page`、`source_file` | 教材 PDF 一页文本。`pdf_page` 是 PDF 阅读器页序，从 1 开始，不是印刷页码。 |

材料出处的原始行取 `source_rows.table_name='materials'` 的 65 行，也就是“题目与材料”表；`source_rows.table_name='records'` 是 806 行作答记录，用于作答证据，不承担材料出处。两者不混用。`RawMaterialRow.from_source_row(source_row)` 可直接从 `SourceRow` 构造。

### 3.2 输出对象

`EnrichedSource` 是逐条结论，关键字段如下：

| 字段 | 说明 |
| --- | --- |
| `material_id` | 材料编号 |
| `verification_status` | `verified`、`unverified`、`not_applicable` |
| `source_status` | 派生标签：没有任何出处信息时为 `unknown`，其余与 `verification_status` 一致 |
| `reason` | 稳定原因码，审计按它分组 |
| `reason_detail` | 中文原因说明 |
| `source_file` | 出处文件或受控来源标记 |
| `source_row_number` | 原始材料表逻辑行号，1 起 |
| `file_id` | 已登记文件 ID |
| `quote` | 命中的原文片段 |
| `pdf_page` | 命中的 PDF 页序，未命中时为空 |
| `printed_page` | 仅当页面对象自带可靠印刷页码时填写 |
| `previous_status` | 调用前的核验状态 |

`EnrichedSource.source_ref()` 返回可直接放进导出 `source_refs` 的扁平字典，包含 `source_file`、`source_row_number`、`material_id`、`quote`、`verification_status`、`locator_level` 等字段。

`pdf_page` 是页码字段，`page` 是它的同义只读属性；导出字段名沿用 `pdf_page`，与正式 `SourceLocator` 一致。

`verification_status` 沿用正式契约的 `verified`、`unverified`、`not_applicable`。另有一个派生的 `source_status`：当材料连 `source_file`、`file_id`、行号、页码、引文都没有时返回 `unknown`，表示来源未知；其余情况与 `verification_status` 一致。这样既保留契约枚举，也能在审计里明确区分“有来源但未核验”和“根本没有来源”。

`EnrichmentReport` 提供 `by_status()`、`by_reason()`、`reasons()`、`by_material_type()`、`by_material_id()`、`source_refs_by_material_id()` 和 `to_dict()`。

## 4. 匹配规则

### 4.1 题目与学习卡

匹配顺序：

1. 按 `材料编号` 找原始材料行。命中多行，返回 `material_row_ambiguous`。
2. 编号唯一命中时，检查材料类型与题干。类型不一致返回 `material_type_mismatch`；题干不是逐字相同返回 `material_content_mismatch`。
3. 编号没有命中时，按题干原文找。命中多行，返回 `material_row_ambiguous`；唯一命中才核验。
4. 编号和题干都没有命中，返回 `material_row_not_found`。
5. 原始行自带的 `source_row_number` 与逻辑行号冲突，返回 `row_number_inconsistent`。

核验通过时写入：

- `source_file`：原始材料表的来源标记，当前为“题目与材料”。
- `source_row_number`：原始材料表逻辑行号。
- `material_id`：材料编号。
- `quote`：原始材料行中的题干原文。
- `verification_status=verified`。
- `file_id`：原始材料表已登记文件 ID（如果调用方提供）。

题干比较只做 Unicode NFC、换行统一和首尾空白清理。内部空白、标点、全半角差异都算不同，不做近似匹配。

### 4.2 教材

教材不走“材料编号唯一命中就核验”的路径，因为教材材料行只登记章节名，不能证明正文页码。

核验顺序：

1. 从已有 `source_locator.file_id` 或 `file_ids` 映射取已登记文件 ID。
2. 取该文件的页面文本。没有 `file_id` 返回 `textbook_file_not_registered`；有 `file_id` 但没有页面文本返回 `textbook_text_unavailable`。
3. 在页面文本中找与材料内容逐字相同的片段。允许忽略排版空白，因为 PDF 抽取会在字间和标点后插入空格；非空白字符必须完全一致。
4. 材料内容如果是章节标题或章节组合，先判定为不可引用，返回 `textbook_content_not_quotable`。这类内容不是题干/定义句，即使页面逐字命中也不写页码。
5. 唯一页面命中才写 `file_id`、`pdf_page`、`quote`、`verification_status=verified`。
6. 零页命中返回 `textbook_quote_not_found`，多页命中返回 `textbook_quote_ambiguous`。两种情况都不写页码。
7. 调用方明确标记为目录、封面等非正文材料时，返回 `not_applicable`，也不写页码。

`printed_page` 只在 `TextbookPage` 自带可靠值时原样传递，不从页脚 OCR 结果推算，也不根据 PDF 页序偏移估算。

### 4.3 知识点

`project_knowledge_refs` 只投影正式 annotations：

- 只接受 `source_type=material`、`target_type=knowledge_point` 的标注。
- 目标知识点必须存在于当前正式知识版本，找不到的目标放入 `unresolved_kp_ids`，不新增关联。
- `rejected` 标注跳过。
- 同一个材料的同一知识点去重，保留第一条正式标注。
- `include_indicator_fallback` 默认关闭。打开后才用材料已有的正式 `indicator_ids` 生成 `kp-{indicator_id}`，并标记 `source=indicator_mapping`。

缺失的 7 项教材关联保持 `unknown`，不补造。

`project_knowledge_sources` 逐点搬运已有 `source_locators`，过滤 rejected，不新增定位。

### 5.1 结论

- 可验证材料 57 项：54 道题和 3 张学习卡。每项都按材料编号唯一命中原始材料行，题干逐字一致，可以补 `source_file`、`source_row_number`、`material_id`、`quote`、`verification_status=verified`。

- 不适用材料 0 项：当前目录里没有明确标记为目录/封面的教材材料。

### 5.2 教材 8 项为什么没有页码

B02 的 PDF 已经登记，`file_id=file-80ef0f770ea54c149dbb`，有 26 页可检索文本。但 B02 的材料内容是“七年级下册 第十一章 不等式与不等式组”，属于章节标题，不是题干或定义句。本次另用 pypdf 对 8 份 PDF 逐页核对，完整材料内容均 0 命中；章节标题本身又出现在多页页眉，无法唯一对应一页。按规则不写页码，原因记为 `textbook_content_not_quotable`。

B01、B03—B08 在正式库中没有登记 PDF `file_id`，无法做页码核验。即使补登记，这 7 项的材料内容仍是章节标题或章节组合，按同一规则也不会被当成题干/定义句来写页码。

- 7 项教材没有正式 annotation，状态 unknown：B01、B03、B04、B05、B06、B07、B08。
- 知识点共 37 个，37 个有 source_locators，其中 28 个至少有一个 verified 定位，9 个只有 unverified 定位。
- 本次没有新增任何材料—知识点关联。

## 6. 接入 exports 的位置

本次不改 `src/study_companion/exports/service.py`。后续接入只需要改一处材料循环。

当前导出在 `exports/service.py` 的 `materials` 组装段：

- 约 1601—1648 行：遍历 `catalog_materials`，用 `material.source_locator` 生成 `source_refs`，再判断 `locator_level` 和 `source_status`。
- `_source_locator_ref()` 约 1203—1234 行：只搬运 `SourceLocator` 已有字段，无法携带 `source_row_number` 和 `quote`。

接入步骤：

1. 在材料循环前读取 `source_rows` 中 `table_name="materials"` 的逻辑行，组装 `RawMaterialRow`；读取已登记教材 PDF 的页面文本，组装 `TextbookPage`；构造 `file_ids` 映射。
2. 调用 `report = enrich_sources(catalog_materials, material_rows=..., textbook_pages=..., file_ids=...)`。
3. 在材料循环里用 `report.by_material_id()[material_id].source_ref(catalog_version=...)` 替换当前的 `_source_locator_ref(...)` 结果。
4. `source_status` 优先取该条结论的 `source_status`（没有任何出处时为 `unknown`）；如果导出字段只允许 `verified`/`unverified`，则取 `verification_status`。`source_note` 取 `reason_detail`。
5. 不要把 `source_row_number` 或 `quote` 写回 `Material.source_locator`。正式 `SourceLocator` 契约是 `extra="forbid"`，这两个字段只能放在导出 `source_refs` 里。

接入后的单条题目 `source_refs` 形如：

## 8. 局限与后续

1. **7 份教材 PDF 未登记**：需要在授权范围内补导入并登记 `file_id`，之后重跑审计。补登记本身不会自动产生页码，仍要逐句命中。
2. **B02 的内容是章节标题**：如果业务希望为教材补页码，需要先把材料内容改成可逐字引用的定义句，或由人工建立“材料—定义句”的受控映射。模块不会自动挑一句定义充当材料内容。
3. **not_applicable 只用于明确非正文材料**：目录、封面等需要调用方显式传入 `not_applicable_material_ids`，模块不根据标题猜测。
4. **本次只新增本方案文件**：`src/study_companion/sources/`、`tests/sources/` 和本文件；`exports/service.py`、`pipeline.py`、`contracts/`、`db/`、`api/`、`frontend/`、`analysis/`、`recommendation/` 不在本次改动范围内。接入点见第 6 节。
