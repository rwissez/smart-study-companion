# 湛知｜智慧学伴设计方案

| 项目 | 内容 |
|---|---|
| 参赛赛题 | 智慧学伴：理解学科、理解学生、理解教学 |
| 作品名称 | 湛知（本地双端智慧学伴） |
| 系统形态 | 单机部署的教师端 + 学生端 Web 应用 |
| 文档版本 | v2.0（2026-11-28），配套成果包 803,771 字节 |

## 摘要

湛知把赛方提供的课程要求、题库和模拟作答加工成三类结果：结构化课程知识、带证据的学情诊断、可调整的学习方案。数字由规则计算，模型负责语义理解和表达，模型产物再由另一次调用独立复核。2026-11-28 的干净库回归使用赛方六张 CSV 和八份教材切片跑通全链路，产出 40 名学生、2 个班、237 个候选知识点（19 个 validated、218 个 needs_review）、12 条关系、80 份学情、80 份方案、159 个任务组和 159 份微课堂，知识构建约 55 分钟，全流程约 72 分钟。首次导出被质量门拦截，修复生成逻辑后重新导出；最终成果包 803,771 字节，799 条证据的引用全部可解析。

配套交付物为本文档、正式成果包（16 个文件，803,771 字节）、答辩 PPT 和五分钟演示视频。第 4 章给出实测数据，第 2 章说明这些数据的产生过程。

## 1 需求分析

### 1.1 赛题要求与处理链

赛题提供七年级数学的课程要求、65 份题目与材料、2 个测验节点，以及 40 名模拟学生的作答记录。对应三个问题：这门课教什么，学生学到什么程度，下一步怎么教。

湛知把三个问题做成一条处理链。A 模块读取课程要求与教材，整理知识点、关系和题目标注；B 模块读取 A 的正式版本和有效作答，计算个人与班级学情；C 模块读取 A、B 的正式版本，生成任务组、活动和微课堂。教师端、学生端、Agent 和导出读取同一套正式结果，不另存副本。

| 赛题要求 | 系统交出什么 | 评委怎么核 |
|---|---|---|
| 理解学科 | 237 个候选知识点（19 个 validated、218 个 needs_review）、12 条关系、57 条题目与评分点标注，每条都带出处 | 课程体系页点开任一知识点；包内 `knowledge_graph.json` 与 `materials_index.json` |
| 理解学生 | 40 名学生、2 个班、2 个节点的 80 份学情，指标带分子分母，诊断带原题与作答 | 班级总览看分布与共性，学生画像展开诊断；包内 `student_analysis.json` |
| 理解教学 | 80 份方案、159 个任务组、159 份微课堂，按证据选策略、定顺序 | 学生端直接按任务组学习；包内 `recommendations.json` 与 `micro_lessons.json` |

系统范围有明确边界：不做注册与账号体系，不做分布式云部署，不做模型训练，也不把模拟学情当作真实教学成效。模拟数据只能说明系统给出的结果、证据和建议合理，不能说明教学效果。

### 1.2 教师端与学生端

教师端的使用从班级总览开始。选择班级和节点后，页面显示雷达图、共性薄弱项、掌握分布和重点关注名单；名册的分母包含未作答学生。从名册进入学生画像，可以展开某条诊断引用的原题、作答和评分点。课程体系页面列出 218 条 needs_review 候选点，教师逐条通过、拒绝或修改，点“通过”不会跳过证据检查。调整计划时，教师在对话中提出修改要求，例如把 D01 下一组练习减到 3 题，系统给出候选差异，教师确认后发布。

学生端有三个页面：个人画像、学习计划、AI 对话。个人画像显示指标、文字诊断和近期进展，区分“优势”“需要加强”“暂需更多证据”三类状态，证据不足的知识点不标记为薄弱。学习计划按任务组排列，未满足前置条件的活动处于锁定状态。作答时按层申请提示，选择题和填空题提交后立即出分，解答题显示“已提交，待评分”，模型初评和独立复核完成后给分。

两端共用一条要求：页面上的每个数字都能展开查看依据，没有依据的数字不显示。

### 1.3 规则与模型的分工

知识点合并、题目与评分点的语义对齐、错因分析、教学语言组织，这些任务难以用有限规则穷举，只用规则会退化为关键词匹配。只用模型则缺少可复现性：同一份作答两次评分可能不同，指标的分子分母可能对不上，审核缺少稳定基准。

湛知把计算与语义处理分开，并规定交界处的数据形态。规则负责进入结论的计算与判定，模型负责语义理解与表达，交界处只接受结构化草稿。

| 环节 | 谁定值 | 谁释义 |
|---|---|---|
| 数据清洗、指标统计、掌握状态 | 规则 | 不参与 |
| 知识提取与关系判断 | 结构校验、环检测、引用检查 | 知识点、关系、题目对齐 |
| 选择题与填空题评分 | 规则判分与等价表达 | 不参与 |
| 解答题评分 | 分数范围、分项合计、作答依据校验 | 按评分细则分点评分 |
| 策略、选题、负担与顺序 | 六类策略、候选资格、优先级 | 在合法候选内组合并写教学语言 |
| 审核 | 身份、版本、材料、结构、数学、答案保护 | 依据是否成立、顺序是否合理 |

交界处有三条约束：模型只输出结构化草稿，程序再做结构、引用、范围和答案保护校验；模型不能改数字、不能写正式状态、不能直接发布；模型失败必须记录，降级结果标注真实生成方式。2026-11-28 回归中，D14 两个节点的方案被复核判为不通过，系统未放行，导出被阻断，详见 4.3。

## 2 方案设计

### 2.1 系统结构

系统是模块化单体：一个 Python/FastAPI 后端、一个 SQLite 数据库、一套 React/TypeScript 前端，单机启动。A、B、C 的业务逻辑写成纯函数，服务层负责装配上下文和持久化；Agent 只能经受控工具读写业务服务；Web 只做展示与提交。核对一类结论只需要读一个模块。

```text
教师端 / 学生端（React + TypeScript，只做展示与提交）
      │  HTTP /api/v1：统一包络、会话鉴权、幂等键、按角色裁剪          ▼
FastAPI 路由层（鉴权、参数校验、错误映射、任务回执）
      ├─ A 课程知识      ├─ B 学情与评分      ├─ C 策略与方案
      ├─ Agent：受控工具循环，写操作只生成候选
      ├─ 模型服务：统一适配、结构化输出、失败上报
      └─ 调度：outbox → job → step，单机 worker，租约与恢复            ▼
SQLite：唯一正式状态（版本、正式指针、发布记录、依赖边、证据索引、事件账本）
      └─ 导出：冻结快照 → 依赖闭包 → 组装 ZIP → 回读校验
```

模块之间的禁止项写进设计：A 不推断学生掌握程度，不生成题目和难度值；B 不自建推荐策略，不改写课程知识；C 不创造未登记题目，不改写 B 的结论；Agent 不绕过 C 的审核和权限，不直接写库；导出只打包冻结的正式成果，不重算业务结果。

### 2.2 从导入到导出

教师上传六个 CSV 后确认文件分类，系统建立数据快照与目录，按依赖顺序执行四步。知识正式发布后，按可用范围投递个人与班级分析；分析发布后执行方案任务。某一步失败只影响下游，已发布且仍适用的旧版本继续可读，页面标记为待更新。

| 步骤 | 做什么 | 40 人数据实测 |
|---|---|---|
| load | 读原始行，建快照与目录 | 0.62 秒 |
| knowledge | 范围计划、分块提取、去重、关系、题目对齐、独立复核、发布 | 55 分 05.95 秒 |
| analysis | 清洗、指标、掌握状态、错因诊断、班级汇总 | 3 分 35.62 秒 |
| plans | 需求聚合、策略、选题、任务组、微课堂、审核、发布 | 12 分 58.03 秒 |

耗时集中在知识构建：这一步需要读取教材页面、调用模型提取并判断关系。方案生成次之，每份方案都要经过审核。纯数据装配耗时极少。四步合计 71 分 40 秒。

状态分三个维度：执行状态（等待、运行、成功、失败、取消）、审核状态（草稿、待复核、通过、拒绝）、发布状态（未发布、已发布、被取代）。任务成功只表示执行完成，不表示内容通过审核，也不表示学生可见。页面显示“已发布”时，必须存在对应的发布记录和可读的正式指针。

### 2.3 作答后的回流

学生开始活动时，服务端创建尝试、写入开始事件，返回题目的安全视图。提交答案后先落库并置为待评分，再调用评分；评分完成写入评分修订事件，不可靠的评分被隔离，不计有效分。任务组完成后，服务端按必需活动判定组完成，写入事件并入队。系统只重算该学生受影响的知识点，刷新班级汇总中的对应成员版本；C 读取新学情判断原方案是否适用，适用时只写一条检查记录，不生成新版本。

三个机制保证这条链路可核对。事件账本只追加、不修改，帮助事件和作答事件记在同一账本，B 判断是否独立完成时读账本。评分失败时保留提交并置为待评分，不以空分计零分。方案复查无实质变化时保留原版本，只在适用性记录中追加一条。

### 2.4 版本与证据的关联

系统使用七类标识：输入快照、题库目录、知识版本、个人分析版本、班级分析版本、方案版本、微课堂正文版本。每份成果记录上游版本和事件截点，读取时可按版本追溯。依赖以带角色的有向无环边写入数据库：回归库中知识依赖 391 条、学情依赖 311 条、正文依赖 159 条、目录依赖 85 条、班级对成员 80 条、方案对父版本 77 条。

发布通过条件更新切换正式指针，版本号、代次和所需代次同时匹配才写入，零行即回滚并返回冲突。两个任务同时发布同一名学生的新方案时，后到的写入不会覆盖先到的正式结果。历史版本不删除，读取时按精确版本解析。

| 评委会问 | 系统怎么回答 | 在哪能核 |
|---|---|---|
| 这份建议当时依据哪次学情 | 方案里记着分析版本、知识版本和事件截点 | 方案版本信息、包内版本清单 |
| 学情后来又变了，旧方案还算数吗 | 单独一条适用性记录，结论是适用、部分适用或不适用 | 方案详情、包内 `basis_warnings` |
| 两个任务同时发布会不会互相覆盖 | 发布走条件更新，版本或代次对不上就回滚报冲突 | 发布记录与冲突返回 |
| 页面的数、Agent 说的数、包里的数为什么一致 | 三处都读同一个正式指针，不各自重算 | 同一版本号与同一份证据 |

## 3 功能说明

### 3.1 教师端

教师端包含四个主页面，以及统一提醒和证据抽屉两项公共能力。页面按教师任务组织，不按系统模块组织。

| 页面 | 回答什么问题 | 打开后看到什么 |
|---|---|---|
| 班级总览 | 这个班整体怎么样，谁需要关注 | 班级与节点切换、雷达、共性薄弱项、掌握分布、名册、班级对比 |
| 学生画像 | 这名学生卡在哪，依据是什么 | 概览、进展、作答记录、方案四个页签，诊断可展开到证据抽屉 |
| 课程体系 | 知识图谱长什么样，哪些候选待处理 | 主题分页、关系图、图例、候选审核、质量报告 |
| 数据管理 | 这批数据质量如何，成果能不能导出 | 上传与分类确认、任务链进度、质量报告、导出预检与下载 |

统一提醒入口汇总 A 的候选异常、C 的方案审核、B 的教师介入，形成三类待办，点击进入具体对象；已读不等于已处理，结案需填写原因并附证据截点。证据抽屉按引用类型分五种渲染：作答记录、指标、课程与知识、派生结论、学习事件。每种显示精确版本、适用范围和可展开的关联引用，不直接展示 JSON 原文。

方案有三条发布路径。自动生成经完整审核后自动发布；Agent 发起的修改走同一套审核，另加一条授权记录；教师在编辑器中直接修改时，需通过身份、版本、数据、材料、历史和答案保护检查，教学合理性警告确认后可继续，发布标记为人工确认。三条路径都保留版本、原因、历史和恢复记录。

### 3.2 学生端

学生端有三个页面：个人画像、学习计划、AI 对话。个人画像只读本人的正式结果，展示指标、文字诊断、学习进展和依据，区分“优势”“需要加强”“暂需更多证据”。学习计划按任务组组织，每组包含目标、主策略、预计时长、预期结果和必需活动；活动状态由服务端按真实事件维护，前端只计算已完成必需活动数与总数。

作答支持选择、填空、解答三种题型。解答题保留原始换行和数学符号，中文输入法组词期间不触发提交。

三级提示按层释放，每请求一层，服务端记录一条事件，重读同一层不重复计数。用于独立补证或迁移检查的题目增加一道确认：系统先提示“获取帮助后本题不再作为独立完成的证据”，学生确认后才释放内容，确认记录写入账本。

提交后的反馈分两级。逐题反馈显示得分、评分点和安全提示；整组反馈在 B 完成局部重分析、C 完成复查后出现，只显示实际发生的变化。待评分和待复核期间，页面显示“已提交，待评分”，不显示 0 分。

### 3.3 Agent 对话

Agent 是对话入口，承担八类任务，权限按角色划分，事实均从业务工具查询。

| 能做什么 | 教师 | 学生 |
|---|---|---|
| 学情查询与解释 | 授权班级 | 本人 |
| 班级学情分析 | 授权班级 | 禁止 |
| 课程知识与关系查询 | 允许 | 授权资料 |
| 方案查询与解释 | 允许 | 本人 |
| 方案修改 | 明确授权范围 | 禁止 |
| 知识讲解与解题引导 | 允许 | 允许，受答案保护 |
| 数据质量查询 | 允许 | 禁止 |
| 学习进展分析 | 允许 | 本人 |

执行循环限制能力边界：任务路由最多六个子任务，依赖无环；工具白名单按任务与角色下发，参数由程序校验目标、版本和范围；模型提出的写请求只生成候选，提交由服务端按授权记录触发；每次工具调用留轨迹，前端显示中文阶段和状态，不显示参数、内部推理或密钥。

修改方案的完整流程如下。教师要求把 D01 下一组练习减到 3 题，系统读取该生当前正式方案（V7），C 在规则基线上生成 5 题减到 3 题的候选，Agent 核对候选差异是否在教师授权范围内；教师确认后提交，任务经完整审核发布为 V8，回复给出实际版本差异。确认时若该生方案已被改成 V9，提交返回 409，候选不执行，系统要求重新预览。

含糊请求不直接执行。教师说“帮他调整一下”时，系统按授权范围列出对象和拟改内容，等待教师在确认卡上选择。批量请求先固定名单，逐人准备候选、审核、提交，单个失败不影响其他人，失败学生保留原方案并单独列出。

### 3.4 微课堂

微课堂是学习计划中的独立活动，不计入题目，不占题库编号，不产生分数，用于知识点讲解和练习不足的场景。

正文由六类封闭组件组成，服务端定义 schema，前端按类型渲染。组件数量少且封闭，便于实现数学检查。

| 组件 | 做什么 | 检查什么 |
|---|---|---|
| text | 段落讲解 | 纯文本转义，不解析 HTML |
| formula | 单个公式 | 受限表达式解析后排版，非法退回修复 |
| derivation | 分步推导 | 相邻步骤按系数或解集比较，拒绝增根、丢根、翻号 |
| contrast | 正误对照 | 正确式与原始式等价，错误式确实不等价 |
| number_line | 数轴与区间 | 有理数精确比较端点与开闭，交集独立验算 |
| citation | 引用 | 索引存在且已授权，学生看不到教师专有证据 |

生成采用 fail-closed。模型输出先通过结构与长度校验，再通过八项内容复核：数学、推导步骤、证据、出处、结构、后续题答案、步骤相似、顺序与诊断污染。任一项不通过时先做一次最小修复，仍不通过则退回已审核的规则模板。本轮 159 份微课堂中，153 份由规则模板生成，6 份由模型生成并通过八项复核，159 条引用组件全部解析到知识点和知识版本。

### 3.5 成果导出

导出先冻结一份选择，再按选择组装，不搬运整库。

冻结时锁定每个对象的精确版本、事件截点、政策哈希和范围，然后计算依赖闭包：方案携带生成时使用的学情版本，班级携带全部名册成员的个人版本，微课堂携带正文版本。任一环缺失或未发布，导出直接拒绝，不做降级拼装。

#### 4.7.1 D01：部分得分，两个具体动作不稳

**答题分析。** D01 在 N01 有 12 条作答记录。T01I1 得分率 0.20（1/5），3 道有效题；T02I1 得分率 0.56（5/9），5 道有效题。Q014（DR0005）0/3，学生把“女生人数比男生的 2 倍少 3 人”写成 `2(x-3)`，先减 3 再乘 2，正确关系应为 `2x-3`；Q022（DR0007）1/3，学生把 `-6` 移到右边时写成 `5-6`，应写 `5+6`，得到 `x=-1` 而不是 `x=11`。T01I2 只有 1 道有效题，过程 `4a-7b` 与答案 `4a+7b` 不一致；T01I3 只有 2 道题，只写到 `3n`；T02I3 只有 1 题全对。后三项证据不足。

**学情诊断。** 主要问题不是整章薄弱，而是两个动作：文字关系转代数式、移项变号。前者在 Q014 的起点就错，后者说明等式性质还没有稳定执行。T01I2、T01I3、T02I3 暂不下结论，需要更多同类型题和口头解释，区分“没理解”与“写错、漏写”。

**教学建议。** 先用 Q006、Q007 练“先写对 `2x-3`，再代入”，再用 Q023、Q026 练“移项变号并验算”，两组各配一份微课堂。提示分三层：先找“谁比谁多、谁比谁少”；再让学生自己写关系式；仍错时用同类小题比较两种写法，不直接给最终式子。下一次看 Q006、Q007 的过程是否先出现 `2x-3`，Q023、Q026 是否主动把 `-6` 写成 `+6`；如果仍然先写 `2(x-3)`，下一轮退回前置支持，而不是继续加题量。

#### 4.7.2 D14：表现较好，用变式和迁移

**答题分析。** D14 的 T01I2 为 5/5，T02I1 为 10/11，均有足够题量和 observed_strength。Q011（DR0298）3/3，学生把 `(n-1)+n+(n+1)` 化简到 `3n`，并补充“因为 n 是整数，所以 3n 是 3 的倍数”；Q022（DR0297）3/3，过程 `3x-6=2x+5`、`3x-2x=5+6`、`x=11`，并有验算。Q026（DR0294）0/1 是少量失分；T01I1、T01I3 各只有 1 道题，不能因为全对就判掌握。

**答题分析。** D03 的 T01I2 为 3/5，有 3 道有效题；T01I1 为 0/4，但只有 2 道有效题；T01I3 为 0/3，只有 1 道；T02I1 为 1/6，只有 2 道。Q009（DR0052）3/3，过程 `6x-2-x-4`、`(6x-x)+(-2-4)`、`5x-6`，合并同类项正确；Q025（DR0058）1/3，去括号时写成 `3x-1+2x+1`，最终 `x=24/5`；Q014（DR0057）0/3，与 D01 类似，把“少 3”放进了括号。

## 5 创新点

### 5.1 规则定值，模型释义，再加一次独立复核

所有进入结论的数字由规则计算。模型只负责表达结论，不得修改数字、诊断依据和引用。B 的指标、掌握状态和评分校验如此，C 的策略判定、候选资格、优先级和负担控制也如此，模型只在合法候选集合内调整组合和表达。同一输入重放得到同一组数字；关闭模型后规则结论不变，4.5 的干跑即按此方式执行。

独立复核保证该分工有效。每个模型产物另起一次调用复核，复核方只拿待审对象和原始依据，不拿生成方的理由或自评。去重需要两次独立判断都判“同一”才合并；关系、映射、方案和微课堂各有检查清单，缺项、重复、伪造依据判为失败。代价是模型调用量约翻倍：一轮方案生成执行优化、内容、独立审核、修复、复审五类任务，每份方案最多八次请求，超出后暂停并保留上一份可靠方案。

### 5.2 版本依赖与证据闭包

可追溯在湛知中由数据库结构实现。每份成果记录上游版本和事件截点，依赖为带角色的有向无环边，发布走条件更新，历史版本不删除。任何对象都能在库中回答依据哪次结果生成。导出时执行闭包：方案携带学情版本，班级携带全部成员版本，微课堂携带正文版本，缺一环即拒绝出包。4.6 中 799 条证据、缺失 0，为该闭包的结果。

该机制同时使降级状态可陈述。包内 4 份当前方案依赖历史学情，系统标记 `analysis_current=false` 并附 `basis_warnings`，不改为最新版本。

### 5.3 答案保护与 fail-closed

答案保护集合在六个通道复用：题目接口、提示接口、Agent 引导、微课堂引用、证据解析、缓存键。三级提示按层释放，累计内容同样检查；引导回复先做结构比对（同题、轻微改数字的克隆、连起来等价于完整解答），再做独立语义复核；独立检查下的帮助需先取得学生确认并写入账本。帮助事件只记一个账本，B 判断独立性时读取该账本。

fail-closed 在四个位置生效：模型未配置或超时时，保留确定性结果并标注降级；审核缺项或依据不可解析时，停止自动发布；微课堂复核不通过时，退回已审核模板；导出缺少必需版本时，返回 422 并列出缺项。

### 5.4 A/B/C/Agent 的协作边界

| 角色 | 负责 | 不负责 |
|---|---|---|
| A 课程知识 | 知识点、关系、题目与评分点对齐 | 判断学生掌握程度 |
| B 学情与评分 | 指标、诊断、评分、班级分析 | 自建推荐策略 |
| C 策略与方案 | 策略、任务组、提示、微课堂、审核发布 | 创造未登记题目 |
| Agent | 理解意图、查工具、组织解释、准备候选 | 直接写库、绕开审核、替 C 做判断 |

该分工使 Agent 越权也无法取得结论。修改方案只能生成候选，候选需通过 C 的完整审核和独立复核，发布需通过条件更新。教师在对话中的肯定回复只作为对话内容，实际确认必须落在确认卡上。学生端求助需先确认受助，确认后才释放引导，B 据此判断作答是否独立完成。

### 5.5 微课堂：六类组件、模型与规则双路径

微课堂的个性化输入有三项：学生错因、知识点缺失的前置、可用时间。C 按这些输入确定讲解目标和长度，再选择生成方式。模型路径更贴合个人错因；规则路径稳定、可复现、无成本。两条路径共用同一套组件 schema 和审核流程，界面一致，差异在正文生成方式和证据标注。

六类封闭组件使数学检查可实现：推导可逐步比对，正误对照可验证等价，数轴可精确比较端点和开闭。159 份微课堂中 153 份走规则、6 份走模型，差异来自预算限制；6 份模型正文全部通过八项复核。

## 6 使用平台、完成方式与数据范围

### 6.1 使用平台

系统为本地双端 Web 应用，单机启动，不需要容器和外部中间件。运行环境和依赖如下。

| 项目 | 配置 |
|---|---|
| 操作系统 | Windows 11（Linux 命令已在文档给出，未实机验证） |
| 运行时 | Python 3.12.16，Node.js 与 npm，版本以锁文件为准 |
| 后端 | FastAPI + Pydantic v2 + SQLAlchemy + Alembic，SQLite 单文件库 |
| 前端 | React + TypeScript + Vite，桌面优先，支持 1920 / 1440 / 1366 三档 |
| 浏览器 | Chromium 内核（Chrome / Edge） |
| 模型 | 远端 OpenAI 兼容服务，经统一模型服务调用，密钥只在后端 |

### 6.2 完成方式

开发按依赖分阶段推进，每个阶段单独留存证据。先实现共享契约与数据模型：字段取并集、保留旧接口兼容、迁移可重复执行；再按 A、B、C 的依赖顺序实现业务并分别测试，A 的产出作为 B 的输入，B 的产出作为 C 的输入，任一段未通过不向下游放行；然后接入 Agent 的受控工具循环，最后接入 Web 闭环。每个阶段的测试命令、实际输出、通过数和未通过项记录在仓库验收对照中，计划中的测试不记为已通过。

该做法的结果是各层完成度不一致：业务链路完成度高于交互层，后端高于前端，数据高于文档。第 8 章按实际完成度列出限制。

### 6.3 数据使用范围

赛方提供的六张模拟学情 CSV、八份教材切片和课程标准 PDF 仅在本机授权范围内使用。系统不使用真实学生个人信息；赛方原始数据不进入公开样例，不作为前端演示数据；演示模式只使用明确标记的合成数据，与真实模式共用页面但不共用数据源。模型调用只发送完成任务所需的最小文本片段，外发授权默认关闭，本轮由本机配置显式开启；页面图像和扫描件不外发。赛后按赛事要求删除本地赛料副本。
