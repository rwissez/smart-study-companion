## 0. 一句话与三条叙事原则

**一句话：** 湛知把课程要求、学生作答和教学安排，接到同一条可核对的数据链上。

**三条原则：**

1. **三项任务是一条链，不是三个功能。** 学科知识是诊断的依据，诊断是安排的依据，安排又在学生练完之后被重新判断。
2. **每个结论都能点开。** 结论 → 依据 → 原始作答，三级可点；不是只给一个分数或一句评语。
3. **不猜。** 规则负责算，模型负责说，智能体只经受控工具访问正式版本；写操作只生成候选，必须经审核或教师确认。证据不足就明确标出来。

## 1. 项目简介

### 1.1 标准版（约 300 字，可用于视频简介、报名文字或开场字幕）

湛知是面向教师与学生的本地智慧学伴，围绕七年级数学的三项核心任务展开：理解学科，把课程要求、教材和题库整理成可核对的知识清单；理解学生，把原始作答变成带证据的个人与班级学情；理解教学，把学情变成可执行、可审核、可调整的学习方案。教师端看班级与个人，学生端按计划学习，作答回流后再判断。

系统把“算”和“说”分开：统计、评分、策略与审核由规则完成，模型只负责语义理解和表达，智能体只能通过受控工具访问正式版本；写操作只生成候选，必须经审核或教师确认后发布。每个结论都能追到依据、原始作答和当时使用的版本；证据不足就明确标出，不猜数字，不把模拟数据说成教学成效。

### 1.2 一行版（片头、海报、封面）

> 湛知——让每一次学习，为下一次判断积累证据。

### 1.3 边界说明（必须保留，不要剪掉）

> 本视频运行在赛方提供的模拟数据上，用来说明系统如何分析、如何给依据、如何安排学习，不代表真实教学成效，也不把模拟学生说成真实学生。

### 镜 04｜00:43–01:08｜教师端·课程体系 `/teacher/curriculum`

**画面：** 三栏：左边“主题与指标”，中间“关系图”，右边“定义与来源”。滚过知识点列表 → 停在一个知识点 → 点开“出处”里的“查看原页”（如有）→ 鼠标划过关系图里的前置箭头。

### 镜 07｜01:36–02:01｜教师端·班级 `/teacher/classes`

### 镜 08｜02:01–02:43｜教师端·学生画像 `/teacher/students/{id}`（核心镜）

**画面（三级下钻，每级停 1 秒）：**

1. 学生画像“诊断发现”：表现标签“需要练习”、证据状态“证据不足”，下面三条“查看依据”按钮；
2. 点第一条依据 → 指标明细：数值、分子/分母、计算说明；
3. 点“相关引用”里的作答记录 → 原题、实际作答、评分点。

**口播：**

> 再点开其中一名学生。系统标出的表现是“需要练习”，证据状态却是“证据不足”。它没有直接下“基础差”的结论，而是把三条依据摆在这里。点开一条，先看到这个指标怎么算；再点相关引用，就是具体作答：第一条，得一分、丢两步；第二条，同类错误再次出现；第三条，还是同一步。原题、实际步骤、每个评分点，都在这里。单次失误不会成为结论；结论、依据、原始作答，三级都能点开。这就是湛知的依据查看方式。

**动作：** 三条依据按钮逐个划过，每条停 0.5 秒；点第一条依据 → 指标明细停 0.5 秒 → 点相关引用里的作答记录；等抽屉加载完再开口；鼠标在“原题 / 实际作答 / 评分点”三块各停 0.5 秒。

**兜底：** 选一条有 `solution_steps` 和 `rubric_scores` 的记录。若实际记录只有最终答案、没有过程，口播改为“原题、最终答案、评分点都在这里”，不要硬说“丢了两步”。若页面结论显示“概念理解需要巩固”，可以把第一句改为“系统把这条发现标成‘概念理解需要巩固’”，其余不变；以页面为准。

## 4. 典型案例讲解卡（答辩、补充材料、视频简介均可复用）

| 项目 | 内容 |
|---|---|
| 案例对象 | 脚本中以 S1 代称；录制时替换为页面实际学生编号（如 D01 或 S1） |
| 分析结果 | 表现标签“需要练习”，证据状态“证据不足”；三条依据下的作答记录都指向同一步：不等式两边除以负数，没有改变方向 |
| 依据链 | 诊断发现 → 三条“查看依据”（指标/计算）→ 相关引用（作答记录）→ 原题 / 实际步骤 / 评分点 |
| 学习建议 | 不直接加练，先给一组补观察题；提示分层释放，答案不直接出现；教师端写明调整条件 |
| 对照案例 | S2 同一知识点，收到变式题而不是重复原题；依据是各自的作答历史 |
| 边界 | 赛方模拟数据；单次失误不定论；证据不足不标成“未掌握”；不证明真实教学成效 |

**一句话讲清案例：**

> 系统没有因为几次同类错误就给学生贴“基础差”的标签，而是把错误、原题和评分点摆出来；因为有效样题还不够，先安排补观察，等证据够了再判断。这就是“结论有依据、建议可调整”。

## 7. 纯口播版（提词器用）

> 同样一道题做错，原因可能完全不同。这是湛知，一个面向七年级数学的智慧学伴。接下来五分钟，看它怎样完成三项核心任务：理解学科、理解学生、理解教学。
>
> 三项任务，一条数据链。理解学科：课程要求、教材、题目，变成可核对的知识清单。理解学生：看清每个学生丢在哪一步，结论带着依据。理解教学：给出安排，并在练完之后重新判断。下面看真实页面。
>
> 任务一，理解学科。先看这门课到底要教什么。
>
> 教师端的课程体系。左边是主题和知识点，中间是关系图，右边是定义与来源。点开一个知识点，能看到它依赖哪些前置知识；出处一栏列出教材文件、PDF 页码和核验状态。有页码的可以打开原页核对；没有核验的，系统不会假装已经核对。
>
> 也可以直接问。输入“一元一次方程，教材里哪里讲过”，系统先定位知识点，再读正式版本，回答给出章节、页码和核对状态；没有核验的页码会明确标出。查什么、答什么，由受控工具和正式版本决定。
>
> 任务二，理解学生。看一个具体案例。
>
> 先看班级。教师看到的不是平均分和排名，而是全班共同卡住的指标：不等式。共性问题下面直接挂着依据，点开一条，再进相关引用，就是具体作答——两边除以负数，没有改变方向。两个班都有学生卡在这里。这不是“题难”，而是一个可以继续追查的概念缺口。
>
> 再点开其中一名学生。系统标出的表现是“需要练习”，证据状态却是“证据不足”。它没有直接下“基础差”的结论，而是把三条依据摆在这里。点开一条，先看到这个指标怎么算；再点相关引用，就是具体作答：第一条，得一分、丢两步；第二条，同类错误再次出现；第三条，还是同一步。原题、实际步骤、每个评分点，都在这里。单次失误不会成为结论；结论、依据、原始作答，三级都能点开。这就是湛知的依据查看方式。
>
> 这套诊断跑在赛方提供的模拟数据上：40 名学生，806 条原始作答，清洗后 799 条作答事件。判定结果里最大的一块是“证据不足”，224 件。客观题没有解题过程，系统宁可标成待观察，也不硬下结论。不猜数字，是底线。
>
> 任务三，理解教学。看这名学生接下来收到什么。
>
> 换到学生身份。打开学习计划，先看到一段学伴的话：今天这几道题不是考试，是想看看你卡在哪一步。因为证据还不够，系统安排的不是加练，而是一组补观察的题：先看清真实水平，再决定下一步。每道题卡住了可以要提示，提示一层一层给，答案不会直接出现。教师端还能看到调整条件：观察到什么情况，下一步怎么变，都提前写清楚。
>
> 同一个知识点，学得稳的学生收到的是一道变式题，不是把原题再做一遍。巩固，但不重复刷。两种安排，依据是各自的作答历史，不是两套标准。
>
> 学生做完，作答回流：评分、更新诊断、复核方案，不合适就调整。独立做对和提示后做对分开记录，原始记录不改写。每一次学习，都在为下一次判断积累证据。
>
> 湛知。让每一次学习，为下一次判断积累证据。不猜数字，不藏依据，不确定就明说。

**口播约 990 字。** 按每分钟 220—240 字、配合页面停顿，落在 4:45—4:55；若试录超过 4:55，优先删镜 09 的“客观题没有解题过程”一句，不要删镜 08 或 11。
