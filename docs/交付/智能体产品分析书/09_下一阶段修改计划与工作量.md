# 09 下一阶段修改计划与工作量估算

## 这一节回答什么

每个产品化缺口，下一阶段要做什么、先做什么、大概多少人天、什么算做完。

## 估算前提

- 1 人天按 6 小时有效开发计。
- 试点阶段假设 1 名后端、1 名前端、0.5 名测试/产品。
- 工作量是范围估算，不是报价；需求变化、学校接口、模型供应商差异会显著影响。
- 当前业务代码处于冻结状态；以下计划是解冻后的下一阶段，不是现在直接改。

## 总体分三期

| 阶段 | 目标 | 周期 | 估算 |
|---|---|---|---|
| 0 期：比赛收口 | 视频、案例、演示稳定 | 1 周 | 6—10 人天 |
| 1 期：单校试点 | 一个班能安全用、能恢复 | 6—8 周 | 36—54 人天 |
| 2 期：产品化 | 多学校、多角色、可运维 | 3—5 个月 | 60—90 人天 |

## 0 期：比赛收口

这一期只做影响提交和演示的事，不碰架构。

| 任务 | 估算 | 验收 |
|---|---:|---|
| 录 5 分钟 MP4 | 1—2 人天 | 三项任务、三案例、班级对比、依据查看都出现 |
| 三案例定稿 | 1—2 人天 | D01、D14、D03 的规则输入和 AI 输出可核 |
| 演示路径锁定 | 1 人天 | 固定学生、节点、版本，现场不切错 |
| PPT 压到 10 分钟 | 1 人天 | 10 分钟讲完，留 5 分钟问答 |
| 上传参数和演示数据准备 | 0.5—1 人天 | 六表 + 八切片可进入，失败可重试 |
| 演示前全链路彩排 | 1—2 人天 | 导入、分析、导出、案例查看各一次 |

合计：6—10 人天。

这一期不建议顺手改架构。比赛前改账号、数据库、多租户，风险大于收益。

### 1 期合计

- 低值：6+7+7+4+9+19+8+6 = 66 人天
- 高值：11+12+12+7+15+31+13+9 = 110 人天

按 1.5—2 人并行，约 7—12 周。

这比 0 期大一个量级。比赛后如果只有一两个人，建议只做“信任 + 表达 + 数据边界”，账号和运维放到 2 期。

## 每个领域下一阶段的一句话计划

| 领域 | 下一阶段 |
|---|---|
| 智能体 | 先把上下文和发布状态修到可信，再谈自主性 |
| 教师端 | 先做上下文条和候选统一入口，再做批量 |
| 学生端 | 先做节点可见、对话适龄、求助锁题 |
| 输出 | 先做结论先行和角色分层，再谈个性化文风 |
| 数据 | 先补 10/20 人边界和多切片导入，再谈更大规模 |
| 工程 | 先做账号、授权、备份、监控，再谈多租户 |
| 安全 | 先做审计和外发登记，再谈合规认证 |
| 运营 | 先做培训、FAQ、反馈入口，再谈 SLA |

## 验收指标

### 比赛收口

- 视频 ≤5 分钟。
- 三案例齐全。
- 演示路径一次跑通。

### 试点

| 指标 | 目标 |
|---|---|
| 画像/方案/对话节点一致率 | 100% |
| 发布状态误报 | 0 |
| 跨班比较成功率 | 100% |
| 教师 30 秒能说出“先做什么” | ≥80% |
| 学生对话平均长度 | ≤300 字 |
| 10/20 人数据全流程 | 成功 |
| 六表 + 八切片进入 | 成功 |
| 备份恢复 | ≤30 分钟 |
| 任务失败可重试 | 100% |

### 产品化

- 多学校隔离通过安全测试。
- SSO/LMS 对接完成。
- 监控覆盖导入、分析、导出、模型调用。
- 成本可按学校/班级核算。
- 有 SLA 和客户成功流程。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 账号体系改动大 | 拖慢试点 | 先做最小登录 + 班级授权 |
| SQLite 迁移 | 数据风险 | 先在副本演练，再切主库 |
| 模型成本不可控 | 预算超支 | 任务级限额和缓存 |
| 教材版权 | 合规风险 | 只处理授权切片，登记来源 |
| 学校接口不标准 | 集成延期 | 先做文件导入，再做 API |
| 团队人手不足 | 计划延期 | 0 期和 1 期只做高优先级 |

## 最终建议

- 比赛前：只做 0 期，不改架构。
- 比赛后如果继续：先做 1 期的“信任、表达、数据边界”，用 3—4 周做出可试点的最小版本。
- 如果要做产品：2 期是另一场工程，不是比赛收尾。

不要在同一周里同时改上下文、账号、数据库和导出。先把用户信任修好，再谈规模化。
