# 02 智能体定义与能力边界

## 这一节回答什么

湛知到底算不算智能体；如果算，是哪一类；它现在的能力边界在哪里。

## 严格定义下的智能体

一个智能体通常要具备四件事：

1. 能感知环境：读取用户输入、数据、工具结果。
2. 能决定下一步：规划、选择工具、处理失败。
3. 能行动：调用工具或修改环境。
4. 有边界：知道什么时候不能做、什么时候要问人。

湛知四件都有，但程度不同。

## 湛知具备的部分

### 感知

- 读教师和学生的自然语言问题。
- 读正式学情、方案、知识、材料、证据。
- 通过工具读数据库和文件，而不是把整库塞给模型。

### 决策

- 有任务路由：学情、方案、知识、质量、导出准备等。
- 有受控多步骤编排：最多 6 步、有依赖、逐步状态。
- 有工具选择：查学情、查证据、查方案历史、准备方案候选。

### 行动

- 能生成方案候选。
- 能生成待确认记录。
- 能查询修订状态。
- 不能直接发布，不能绕过教师确认。

### 边界

- 学生只读。
- 写操作只到候选。
- 模型失败就退回规则或待复核。
- 发布走正式版本和确认流程。

## 湛知不具备的部分

- 不能自己拆任意复杂任务；多步骤主要是规则拆解，不是自由规划。
- 不能长期记住用户偏好；会话历史有，但跨会话的个性化记忆很弱。
- 不能主动巡班、主动提醒、主动发起任务；要用户先问。
- 不能自己发现“这个学生需要关注”并自动推送；提醒由规则和页面查询产生。
- 不能自己发布、撤销、改分；这些都需要教师。
- 不能在多个学校、多个租户间隔离运行；当前是本机单租户。

## 它更像哪一类智能体

更像“受控的教学工作流智能体”，而不是“通用自主智能体”。

可以这样理解：

- 它像一位助教，能查资料、做分析、起草方案、准备确认单；
- 它不是一位能独立上课、独立改方案、独立发布的老师；
- 它的价值在“把证据和流程串起来”，不在“替人做决定”。

这个定位和赛题并不冲突。赛题要的是“学习支持结果”，不是“自主性表演”。

## 智能体定义上的三个风险

### 风险一，把工作流说成自主智能体

如果答辩时说“它能自己规划、自己执行、自己发布”，评委一问就会露馅。

更稳的说法：

> 它是受控的教学智能体：能调用工具完成多步任务，但写操作必须经过教师确认，发布走正式版本。

### 风险二，把模型调用当成智能体能力

模型调用只是能力之一。真正的智能体能力是：

- 知道该查什么；
- 知道查不到时怎么办；
- 知道什么时候不能下结论；
- 知道把结果交给谁确认。

湛知在这些点上做得比“会聊天”更重要。

### 风险三，交互上让用户以为它是万能的

学生端对话如果回答得像教师报告，或者把 N01 的问题答成 N02，用户会觉得“它不懂我”。

这不是模型能力问题，是上下文和角色设计问题。

## 当前智能体能力的评分

| 能力 | 评分 | 说明 |
|---|---|---|
| 工具调用 | 4/5 | 查询、候选、状态都有；写工具仍受控 |
| 多步任务 | 3/5 | 常见两步可拆；复杂任务退回单步 |
| 上下文记忆 | 2.5/5 | 有会话历史，但节点/角色绑定不稳 |
| 主动行动 | 1/5 | 不主动巡班、不主动提醒 |
| 安全边界 | 4.5/5 | 学生只读、教师确认、fail-closed |
| 可解释性 | 4/5 | 证据链强；语言表达弱 |
| 产品化 | 2.5/5 | 本机可用，账号/多租户/运维不足 |

## 本维度结论

湛知可以被称为智能体，但必须加限定词：**受控的、教学场景的、工具型的智能体**。

它的竞争力不在“自主”，而在：

- 知道什么时候该查证据；
- 知道什么时候证据不够；
- 知道什么时候该请老师确认；
- 知道怎么把结果落成可执行任务。

这四件事，比“能不能自己规划十步”更接近真实教学。
