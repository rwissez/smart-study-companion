# 06 工程落地与独立评测

## 这一节回答什么

别人拿到这套代码，能不能跑；换一批数据，能不能处理；要进学校，还差什么。

## 现在是什么形态

湛知是一个本机运行的单体应用：

- 后端：Python/FastAPI
- 前端：React/TypeScript
- 数据库：SQLite
- 模型：外部 OpenAI 兼容服务，密钥在本机配置
- 数据：赛方六张 CSV + 教材 PDF
- 部署：Windows 启动器，手动或脚本启动

这个形态适合比赛演示、单机试点和教师个人使用。

它不是多租户 SaaS，也不是学校统一部署平台。

## 别人克隆后能不能用

代码可以跑，但不是“克隆完就全功能可用”。

必须准备：

- Python 3.12 和 uv
- Node.js 22 以上
- `uv sync --locked`
- 前端 `npm install`
- `.env` 配置文件
- 模型三要素和 API Key
- 数据库迁移 `alembic upgrade head`
- 六张 CSV 数据
- 可选教材 PDF

不会随仓库下载的东西：

- `.env`
- `data/`
- `data/model-settings.json`
- 赛方数据
- `outputs/`

不配模型时，规则路径能跑，但语义诊断、Agent 自然语言回答、部分微课堂会降级。

不迁移数据库时，空库会报 no such table；启动器已经补了迁移，但手动启动 uvicorn 不会自动迁移。

## 新数据能不能处理

从代码结构看，可以：

- 导入按六张逻辑表识别；
- 生产代码没有硬编码当前数据集编号；
- 新数据会创建新数据集/新 family；
- 15 名学生、252 条记录的临时库干跑成功。

干跑结果：

- 6.46 秒完成；
- 30 份学情、4 份班级、30 份方案、60 份微课堂；
- 导出 16 个文件、226,140 字节；
- 学生越权访问返回 403。

但要注意：

- 没有教材 PDF 时，只有 9 个指标级知识点、0 条关系；
- 没有模型时，诊断解释和微课堂模型生成会降级；
- 小样本下 125 条发现中 93 条证据不足；
- 学情 `strategy_signals` 仍为 0，B 还没填这个字段；
- 导出首次轮询偶发 404，属于任务行提交时序问题。

所以准确说法是：

> 能处理相同字段口径的新数据，能完成规则级全流程；不能保证任意数据都能得到完整知识图谱和无保留导出。

## 独立评测的风险

### 风险一，数据规模小，阈值可能偏

当前学情阈值部分基于 806 行数据校准。

15 人样本下，93/125 条发现证据不足。

独立评测 10—20 人时，如果题目覆盖更少，系统会更频繁地输出“证据不足”。

这不是错，但要让评委看懂“为什么不定论”。

### 风险二，没有教材 PDF 时知识覆盖骤降

独立评测只给六张 CSV 时，知识图谱会退化成指标级知识点，关系为 0。

这会影响 C 的知识点关联和微课堂引用。

### 风险三，模型成本与失败

模型调用有预算：

- 方案复核每任务 4 次；
- 微课堂每任务 6 次；
- 超预算走规则。

独立评测时如果模型不可用，系统会大量退化到规则，输出质量下降。

### 风险四，部署门槛

需要 Python、Node、uv、模型 Key、迁移、导入。

对老师来说，这不是“下载安装就能用”。

## 如果要进学校，还差什么

- 账号与身份体系
- 多学校/多班级隔离
- 权限与审计
- 数据备份与恢复演练
- 模型成本控制与限流
- 教材版权与数据合规
- 与学校 LMS/教务系统对接
- 教师培训与帮助中心
- 监控、告警、日志
- 版本升级与迁移策略

这些不是赛题硬性要求，但是产品落地的必要条件。

## 落地评分

| 项 | 评分 | 说明 |
|---|---|---|
| 本机可运行 | 4/5 | 启动器、迁移、文档都有 |
| 新数据导入 | 3.5/5 | 六表口径可跑；无 PDF/模型时退化明显 |
| 独立评测适应 | 3.5/5 | 15 人干跑通过；小样本阈值待验证 |
| 模型依赖 | 3/5 | 可降级，但质量差距明显 |
| 多用户/权限 | 2/5 | 只有 demo 会话，不是账号体系 |
| 运维 | 2/5 | SQLite、本地文件、无监控 |
| 规模化 | 1.5/5 | 不适合多校 SaaS |

## 本维度结论

湛知已经跨过“能演示”这道坎，正在接近“能试点”。

它还没有跨过“能规模化部署”这道坎。

比赛阶段不需要跨过去，但要诚实说清楚：

> 这是本机部署的教学智能体原型，适合单校试点；不是开箱即用的区域教育云平台。
