## 0. 演示口径：先说能说什么、不能说什么

这一节决定视频和 PPT 的可信度。录制前请全组统一口径，剪辑时不要剪掉限制说明。

### 0.1 可以说的

- 在赛方提供的模拟数据上，系统跑通了“统一导入 → A 课程知识 → B 学情 → C 方案与微课堂 → 导出预检”这条链路；本轮导入 40 名学生、2 个班、2 个观察节点（TODO-02）。
- 知识、学情、方案、微课堂、导出都读同一套正式版本；页面能打开证据、版本和限制。
- Agent 的回答来自受控工具读取的正式结果；工具进度是服务端执行事件，不是模型思考过程。
- 教师直编方案走“检查草稿 → 确认发布”两步，发布记录为教师确认（human_confirmed）。
- 学生端能真实完成微课堂阅读与在线作答，学习事件回流后再触发局部更新。
- 页面走真实接口（`VITE_DATA_SOURCE=api`），后端 `demo_mode=true` 只表示本地模拟教师/学生身份，不是预设样例数据。

### 0.2 不能说的

- 不能说“全部完成”“全部验收通过”。当前有明确未完成项：正式导出在本轮回归中被质量门阻断、诊断解释只覆盖部分学生、教材原文引用为空、难度全部未知。
- 不能说“真实教学效果提升”。赛方模拟数据只能证明结果、证据与建议的合理性，不能证明教学成效。
- 不能说“知识关系完整”。关系推断受 180 秒预算截断，6 批只完成 2 批，保留 11 条关系、拒绝 5 条（TODO-03）。
- 不能说“每条诊断都有模型解释”。本轮 364 条 findings 中只有 11 条带诊断明细（TODO-04）。
- 不能说“微课堂由模型现场生成”。本轮真实数据里微课堂全部由规则模板生成并审核，模型生成路径本轮未参与。
- 不能说“导出一次性自动完成”。导出前有预检，缺项会阻断；阻断时页面不会给生成按钮。
- 不能说“页面上的数字都是模型算的”。统计、评分、策略、排序都由规则与业务服务产出，模型只组织文字、做复核与建议。

### 0.3 当前限制与对应说法

| 限制 | 画面证据 | 一句话说法 |
|---|---|---|
| D14 两个节点的方案被模型复核判为 needs_review，本轮导出预检 `PLAN_MISSING` | 成果导出页的预检缺项表 | “正式导出被质量门拦住，原因和补救建议都写在页面上；导出范围是全体名册，不能只导其余 39 人。” |

## 1. 演示视频脚本（总长 7:50）

### 1.0 录前设定

- 分辨率 1920×1080，系统缩放 100%，浏览器缩放 100%，隐藏书签栏，关闭系统通知与聊天软件。
- 前端 `http://127.0.0.1:5173`，后端 `http://127.0.0.1:8000`，后端必须重启到含 `48afd0b` 的代码（见 §3.1）。
- 录制一次到底，鼠标移动放慢，点击后停 0.5 秒再说话；每个页面等数据加载完再开口。
- 字幕只加三类：段落标题、关键数字、限制说明。限制说明不要用灰色小字一带而过，要能看清。
- 旁白按每分钟约 230 字估算；每段标注的是旁白字数，不是硬性上限。
- 脚本假设 §3.4 已完成（D14 方案已发布、导出预检 `ready=true`）；若未完成，S6 按 §1.8 的兜底改为“质量门演示”。

### 1.2 S0 片头（0:00—0:15，旁白约 55 字）

**操作步骤**

1. 黑底或品牌绿底，居中显示“湛知”Logo 与副标题“有依据的师生智慧学伴”。
2. 依次浮出三个问题：“这门课到底要求什么？”“这个学生为什么丢分？”“下一步该怎么教？”
3. 三个问题收拢成一条线，切到身份页。

**旁白**

> 四十名学生，两个班，老师要回答三个问题：这门课到底要求什么，这个学生为什么丢分，下一步该怎么教。湛知把这三件事，接到同一条可核对的数据链上。

**预期画面**

- Logo 清晰，三个问题各停约 2 秒；最后一帧是身份页，避免黑屏跳变。
- 不出现版本号、内网地址、模型密钥。

**失败兜底**

- 若身份页加载慢，片头延长 3—5 秒，不要切到错误页。

### 1.3 S1 开场问题（0:15—1:05，旁白约 190 字）

**操作步骤**

1. 停在 `/identity`。画面包含左侧品牌区、“数据导入 → 学情分析 → 学习方案”示意图、右侧“选择身份”。
2. 在“数据集”下拉里选中演示数据集（TODO-01，当前名称可能显示为“当前数据集”）。
3. 点“教师”卡片，再点“以教师身份进入”。
4. 等“班级总览”加载完成，不急着点击。

**旁白**

> 传统做法里，课程知识靠人工整理，学情靠分数排名，学习方案靠经验，三件事各说各话，出了问题找不到依据。湛知把课程要求变成知识点和关系，把作答变成带证据的学情，再把学情变成可审核的学习方案。教师端四个入口，学生端三个入口，所有结论都从后端正式版本读取。

**预期画面**

- 身份页右侧显示“40 名学生 · 2 个班级 · 课程目录已建立”（TODO-02）。
- 进入后左侧导航为“班级总览、课程体系、数据管理、AI 对话”，右上角有“提醒”和数据集下拉。
- 不出现“演示数据”角标；如果出现，说明前端跑在 `demo` 数据源，必须切回 `api` 后重录。

**失败兜底**

- 身份页报“无法连接后端服务”：停录，按 §3.1 重启后端，不要对着错误页讲。

### 1.4 S2 教师端：班级总览与学生画像（1:05—2:40，旁白约 340 字）

**操作步骤**

1. 班级总览顶部确认“班级”为 DC01（21 人）、“节点”为“第 1 次观察”（内部 N01）（TODO-02）。
2. 鼠标依次划过三项数字：名册人数、有效观测学生、需关注；停一下，让观众看清“含无记录学生，作为分母使用”。
3. 指左侧“观察指标”雷达，展开“全部指标明细”，停 2 秒。
4. 指右侧“共性问题”“表现分布”“关注学生”，每块停 1 秒。
5. 点“班级比较”，看 DC01 与 DC02 的并列值与“可比性”说明；点“返回班级视图”。
6. 在“名册”里找到 D01，点该行进入“学生画像 · D01”。
7. 概览页指“观察指标”“诊断发现”“策略信号”，找一条带“查看依据 · 记录…”的发现。
8. 点“查看依据”，等证据抽屉打开：原题、实际作答、评分点、数据质量、限制；停 3 秒后关闭。
9. 鼠标扫过“进展”“作答记录”页签，不点开，回到“概览”。

**旁白**

> 这是教师端的班级总览。先选班级和观察节点，三项数字分别是名册人数、有有效观测的学生、需要关注的学生；分母是名册，不是当前页。左边雷达是观察指标的有效得分率，右边是共性问题、表现分布和关注学生，全部来自 B 的正式分析版本。切到班级比较，两个班的差值只在服务端判定可比时才显示，不可比就并列原值和原因。从名册点进 D01，看到个人雷达、诊断发现和策略信号。每条发现都带证据状态和限制；点查看依据，抽屉里是原题、实际作答、评分点、数据质量和版本定位。这里不把得分率当掌握率，也不把证据不足当成没学会。

**预期画面**

- 雷达带 0—100 刻度；缺失指标不画 0 点。
- 证据抽屉里的“实际作答”是学生原文；若视频要公开发布，按赛方数据使用范围决定是否打码，打码只遮姓名与手写原文，不遮评分点。
- “需关注”人数与“关注学生”列表一致（TODO-10）。

**失败兜底**

- 班级画像报“该班级在此节点尚无正式学情”：确认节点是否为“第 1 次观察”；不要临时切节点后硬讲。
- 证据抽屉打不开：改为点开“全部指标明细”，用分子/分母讲证据口径，并口播“抽屉这次没有加载，数据仍在正式版本里”。

### 1.5 S3 AI 对话：流式、工具进度、事实绑定（2:40—4:05，旁白约 330 字）

**操作步骤**

1. 在学生画像右上角点“就此学生提问”。确认地址带 `student=D01` 与节点参数，左侧显示“对象：学生 D01、节点已绑定”。
2. 指右上角“模型已配置”（绿色勾）；不要打开设置弹窗。
3. 在输入框输入：“D01 在「表示数量关系并代入求值」上为什么丢分？请只依据正式学情和作答证据回答。”按 Enter 发送。
4. 录下步骤时间线： “正在请求模型” → “正在调用：读取学生学情分析” → “正在调用：读取作答证据” → “模型已返回结果”；正文逐字出现，鼠标不要抢滚动。
5. 回答结束后，展开回答上方的“工具进度（N 步，来自服务端记录）”，逐条停 1 秒。
6. [可选，时间够再拍] 追问一句：“那下一步先练什么？”等回答出现建议，停 2 秒。
7. 指左侧“会话历史”里刚生成的会话标题，说明刷新后能恢复；不点刷新，避免打断。
8. 浏览器返回学生画像，重新打开刚才那条“查看依据”，把回答里的一个数字和抽屉里的分子/分母对上。

**旁白**

> 带着这名学生进入 AI 对话，学生和节点自动带过去，右上角是模型配置状态。问它：D01 为什么丢分，请只依据正式学情和作答证据回答。回答是流式出来的，上方是真实的工具执行进度：读取学生学情分析、读取作答证据，每一步都是服务端记录，不是模型的思考过程。回答里带数字的句子，必须能在这一轮工具结果里找到对应数字；引用编号必须来自这一轮结果。核对不上的句子会被删掉，文末写清限制。这就是我们的原则：能核对的留下，核对不了的明确标限制。追问下一步，它给的是基于同一套学情的建议，不会另建一份画像。

**预期画面**

- 步骤时间线逐条点亮，完成的步骤带勾；失败步骤会保留红色标记。
- 回答没有“非模型原生流”标签；若出现该标签，说明流式退化为分块，见兜底。
- 回答里可能出现“限制”段落，这是正常现象，不要剪掉。
- 不出现模型内部推理、提示词、密钥或技术参数。

**失败兜底**

- 模型超时或未配置：回答会标“规则摘要（未使用模型）”。口播：“模型本轮没有返回，系统用正式学情的规则摘要回答，数字仍来自同一套数据。”
- 出现“非模型原生流”标签：口播：“这次是分块回传，不是模型原生流式。”录完检查模型服务后补录这一小段。
- 工具步骤一直停在“正在调用”：等 10 秒仍不动就停录，查后端日志，不要解说“它正在思考”。

### 1.6 S4 学习方案与审核（4:05—5:25，旁白约 300 字）

**操作步骤**

1. 学生画像点“学习方案”页签。
2. 指任务组头部：目标、教师依据（`teacher_reason`）、必需活动 x/y、预计时长；指活动行的“微课堂/题目”标签。
3. 指“待审核候选（TODO-11，预期 0）”按钮，说明它是 Agent 生成候选的入口，当前没有候选，所以是灰的。
4. 点“编辑学习方案”。在“学生开场白”末尾加一句与当前知识点相关的话。
5. 在“本次修订理由（必填）”里填：“补充开场白，明确本节课聚焦的步骤，不改活动与顺序。”
6. 点“检查草稿（第一步）”，等右侧出现“检查通过，等待确认”、过期时间与警告条数。
7. 若有教学警告，勾选“我已阅读并确认这些教学警告”。
8. 点“确认发布（第二步）”，等“方案已发布”：审核状态“教师确认（human_confirmed）”、发布状态“已发布”。
9. 点“关闭并刷新”，回到方案页，确认任务组仍是新版本，历史修订里多一条记录。

**旁白**

> 回到学生画像的学习方案。每个任务组都写清楚目标、教师依据、必需活动和预计时长，教师依据里写着用的是哪条发现、哪几份材料。方案有三条发布路径：系统自动审核、教师直接编辑、Agent 候选。今天走教师直编：改一句学生开场白，填修订理由，先检查草稿。服务端做材料、泄答、负担和已完成活动保护检查，通过后只给预览；确认发布才写入正式版本，审核记录是教师确认。学生端刷新后读到新版本，旧版本留在历史里。待审核候选这个入口接的是 Agent 生成、还没确认的候选，今天没有，所以是灰的。

**预期画面**

- 底部三步提示“① 修改草稿 → ② 检查草稿（只生成预览，不会发布）→ ③ 确认发布”。
- 预览阶段没有发布按钮，只有“返回修改”和“确认发布（第二步）”。
- 发布后显示“新版本、教师确认、已发布、修订编号已记录”。
- “历史修订”列表新增一条，旧版本仍可查看。

**失败兜底**

- 检查被硬门拦下：页面会定位字段并说明原因。口播：“硬门拦下了这次修改，原因在页面上，这正是审核在起作用。”然后改为只读展示任务组，不强行发布。
- 预览过期或基线变更：按页面提示重新检查，不要在镜头前反复点“确认发布”。

### 1.7 S5 学生端微课堂（5:25—6:35，旁白约 260 字）

**操作步骤**

1. 左侧底部点“退出并重选身份”，回到 `/identity`。
2. 点“学生”，在名册里选 D01（班级以名册实际为准，TODO-10），点“以学生 D01 身份进入”。
3. 个人画像：指“学习表现”雷达与“学习重点”，点一条“查看依据”展示学生可见的证据范围，关闭。
4. 点“继续学习”，进入“学习计划”；指“必需活动 x/y”、任务组顺序与“微课堂”标签的活动。

### 3.7 失败兜底话术

| 现象 | 立即动作 | 口播 |
|---|---|---|
| 身份页连不上后端 | 停录，重启后端 | “后端会话还没就绪，我们先不录这一段。” |
| 班级/画像读取失败 | 查任务链与节点 | “这个节点没有正式学情，页面按真实状态提示，不补假数据。” |
| 模型超时或未配置 | 保留规则摘要回答 | “模型本轮没有返回，系统用正式学情的规则摘要回答，数字仍来自同一套数据。” |
| 流式退化为分块 | 录完补录 | “这次是分块回传，不是模型原生流式。” |
| 方案预览被硬门拦下 | 只读展示 | “硬门拦下了这次修改，原因在页面上，这正是审核在起作用。” |
| 预检报 D14 缺失 | 展示缺项与补救 | “正式导出被质量门拦住；导出范围是全体名册，不能只导其余 39 人。” |
| 导出返回 422 | 不重复点 | “服务端拒绝了不完整的正式包，缺项和补救建议都在这里。” |
| 微课堂组件不可读 | 换一份微课堂 | “这份内容没有通过运行时校验，页面不允许标记完成。” |
| 任何 5xx | 记录 request_id，停录 | “这次请求失败了，编号在这里；我们不在镜头前掩盖错误。” |

### 3.8 录制中禁止动作

- 不切数据集、不清库、不改代码、不重启服务、不临时补数据。
- 不打开 `.env`、`模型信息.txt`、数据库文件、`data/` 目录。
- 不展示模型密钥、完整提示词、内部英文代号堆叠。
- 不说“全部完成”“全部通过”“效果显著提升”。
- 不把合成截图、旧 ZIP、旧包数据说成本轮结果。
