# C工作指南

## 开工前必须执行的技术基线

先读11，等A0骨架合入main后开任务分支。实际目录src/study_companion/recommendation、prompts及tests/recommendation。实现search_materials、recommend_rules、validate_recommendations固定签名，使用A的StudentResult/Catalog模型和合成样例。不另建Agent框架或数据库；文本模型调用经过A的ModelProvider。模型API空白仍需完成规则建议、提示词和验证模块。验收命令uv run pytest tests/recommendation tests/contracts。

你的目标是让建议对应实际表现，并明确依据不足时下一步如何观察。B给事实和数值，你负责诊断解释与教学动作。

## 按顺序执行

对照PDF文件第4页（正文第3页），C对任务3完整负责：结合学习要求、分析和任务条件，提出内容/练习/活动、对应材料、理由、顺序和便于实施及教师调整的安排；证据不足时设计补充观察。交付建议JSON、建议—诊断—要求—材料关联、实施与观察条件及典型案例核对表。

双端表达由C维护：教师对话解释个体差异、班级共性、依据及调整；学生对话使用适合七年级的语言和不直接给答案的分步提示。共用B事实，不因表达变化改写统计。教师可调整材料、顺序、提示与说明，须填写理由并保留原版本；C定义允许修改及校验规则，A保存，D提供入口。普通对话不自动计作新的有效测验记录。

模型API留空时交付提示词、示例输入输出、规则建议和未配置状态，不虚构模型已接入或教学已产生效果。

1. 与B核对输入，明确表现和证据充足程度独立。阈值均写配置并注明启发式，不宣称得到真实掌握概率。
2. 与A确认题目、学习卡和教材定位。先按指标及教学范围做确定性检索，小材料库不必先建向量数据库。
3. 为三类情况写建议模板：具体步骤有困难、已有较好表现、证据不足。每类都含材料、理由、顺序、分步提示和观察点。
4. 将模板接入规则，再接可替换模型适配器。模型仅使用传入的事实和允许材料；输出经结构与引用验证后才可展示。
5. 建立引用检查：诊断引用属于当前学生及运行；材料存在且适合教学范围；建议必须引用finding_id。空泛“多练习”不能验收。
6. 对提示进行人工审核，逐步提供方向，避免直接泄露完整答案。教师端参考答案与学生提示分开字段。
7. 补充记录形成新运行时重新生成建议，保留前后依据；无补充证据不能宣称建议已产生学习效果。

## 建议最小内容

对应指标；关联诊断；学习目标；现有材料编号；为什么选它；执行顺序；不直接给答案的提示层级；观察什么；出现什么证据时升级、继续或转补充观察。推荐现有题目时标明学生是否已做过，重做应说明目的。

## 验收

按09交付材料检索和建议工具，输入必须是已验证的分析结果。模型参与解释和提示生成；引用与结构校验由程序执行。基础版建议工具内部不再启动自主子智能体，避免递归调用和难以追踪的成本。

至少完成三类不同需求的案例；每个案例经另一成员复核。模型超时、非法JSON、材料不存在、引用他人记录时，拒绝不合格输出或明确降级，不能静默展示。保留规则版本、生成方式与审核状态。

## 可交给Codex的起始任务

阅读00、01、02、08及C指南，使用B提供的结构化事实和A材料目录，实现recommendation模块与证据校验。不要重新计算统计，不猜测学生动机或未提供的解题过程。先交规则建议和三类测试，再接已获授权的模型配置。任何建议引用都必须在当前输入范围内；输出包含材料、理由、顺序、提示和调整条件。
