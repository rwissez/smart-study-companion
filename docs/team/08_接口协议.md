# 接口协议

实施补充：技术栈、数据库表、后台纯函数签名及首次导入会话流程以11为准。本文下述B.import_dataset等为概念描述，实际调用使用11的prepare_dataset/analyze_dataset等签名。教师首次bootstrap会话可暂不绑定dataset_id，以解决首次导入；学生仍必须绑定已有数据集和本人。HTTP字段由A转为Pydantic/OpenAPI并由各端共同验证。

版本1.0设计草案。A维护，B/C/D消费。下列为基础版必须实现的契约；实现时将字段落成共享可校验模型和测试样例。本文件不声称已有运行服务。

智能体工具协议和新增自然语言任务接口见09，作为本协议的补充；已有统计、建议和引用数据结构保持单一来源，工具不得另建一套字段。

## 通用约定

模型服务的供应商、API地址、模型名称和密钥默认未配置，可选接入；本文内部HTTP接口不留空。未配置模型且请求模型对话时返回503 MODEL_NOT_CONFIGURED；明确请求规则建议仍可工作。

## 双端协议补充

新增POST /api/v1/demo-sessions，输入role(teacher/student)、dataset_id及学生角色必填student_id，返回session_token和scope；仅本地模拟身份，不是生产认证。后续请求通过Authorization携带该会话，角色不得由每条消息任意覆盖。服务验证学生属于数据集，学生只能查询自己，教师可查询该数据集的班级与学生；越界返回403 FORBIDDEN。

新增GET /api/v1/datasets/{dataset_id}/classes返回班级items，每项class_id、roster_count；教师端使用。StudentResult追加class_id；画像直接由metrics、findings和limitations形成，不新增无依据的综合画像分。

学生角色禁止班级分析、其他学生证据、数据导入、运行创建及全量导出。材料响应删除reference_answer、reference_explanation、rubric_points和评分审核信息；对话工具上下文也使用裁剪后的材料及本人记录。即使后端模型可见的教师资料存在，也不得进入学生会话。

新增POST /api/v1/runs/{run_id}/students/{student_id}/recommendation-revisions，仅教师使用。输入recommendation_id、base_revision、reason及changes（仅activities、reason、goal、adjustment_conditions）；后端校验材料/证据/范围后生成新revision_id、revision、created_at，保留原版。版本冲突返回409。新增GET同路径返回该学生建议修订记录；学生建议响应只提供当前有效建议，不包含教师修改理由和审核记录。C定义规则，A存储，D交互。

UTF-8 JSON，字段snake_case；所有ID字符串；日期ISO 8601，时间含时区。比例为0—1，前端乘100显示百分比。缺失数值为null，不使用0替代。数组无元素用[]。分页默认50、上限200，page从1开始。所有路径ID需验证存在，不能限制为公开数据编号。

成功响应统一为：

```json
{
  "schema_version": "1.0",
  "request_id": "req-example",
  "data": {},
  "warnings": []
}
```

失败响应为：

```json
{
  "schema_version": "1.0",
  "request_id": "req-example",
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "输入字段不符合要求",
    "details": [{"field": "node_ids", "reason": "必须至少包含一个有效节点"}]
  }
}
```

400请求格式错误，404对象不存在，409版本/状态冲突，422业务校验失败，500内部错误，503模型或外部服务不可用。错误不返回密钥、堆栈或本地绝对路径。warnings每项为code、message及可选issue_id。

## 引用与基础对象

EvidenceRef：kind取record、metric、material、curriculum；id为引用对象ID。record/metric引用必须带run_id，material/curriculum引用必须带catalog_version；其他分支字段不使用。解析record时由run找到dataset，再找到该记录，禁止跨学生引用。班级metric允许引用班级内记录，并明确范围。

Material：material_id、material_type(question/card/textbook)、topic_ids数组、indicator_ids数组、content、source_locator、reference_answer、reference_explanation、max_score、rubric_points、reviewed_variant_tag。reviewed_variant_tag为A/C人工核对的题目变式分类，未标注为null，不由模型擅自赋值；用于证据覆盖检查。非题目字段可null。source_locator包含source_file相对路径、pdf_page可null、printed_page可null、verification_status(verified/unverified)。API不能直接暴露任意磁盘文件。

QualityIssue：issue_id、code、severity(info/warning/error)、record_ids、event_id可null、message、action(retain/exclude_score/quarantine_event/block_import)、rule_version。

Metric：metric_id、name、value(number或null)、numerator、denominator、unit(ratio/count/score)、scope、evidence_refs、excluded_event_count、limitations。scope包含student_id或class_id以及node_id、indicator_id可null；两种对象范围不可混用。

Finding：finding_id、indicator_id、description、evidence_status(sufficient/insufficient/conflicting)、performance(observed_strength/needs_practice/undetermined)、evidence_refs、limitations。无证据不能输出确定性强弱；performance不是掌握概率。

Recommendation：recommendation_id、indicator_id、finding_ids、goal、reason、activities、adjustment_conditions、review_status(draft/validated/needs_review)、generation_method(rule/model)。activities每项包含order正整数、material_id、purpose、hint_levels字符串数组、observation_points字符串数组、previously_attempted布尔值。adjustment_conditions每项为observable_condition、next_action，不凭空填写分数提升。

## 后台模块函数边界

```text
B.import_dataset(input_files, import_config) -> ImportResult
B.analyze(dataset_id, catalog_version, analysis_config) -> AnalysisBundle
C.recommend(analysis_bundle, catalog, recommendation_config) -> RecommendationBundle
C.validate_references(recommendation_bundle, analysis_bundle, catalog) -> ValidationResult
A.export_run(run_id) -> ExportManifest
```

所有配置显式传入并保存，不能依赖队员电脑上的隐含全局状态。AnalysisBundle包含run_id、dataset_id、catalog_version、rule_version、config、student_results、class_results和quality_summary。StudentResult含student_id、node_id、metrics、findings、limitations。ClassResult含class_id、node_id、roster_count、observed_student_count、metrics、findings、limitations。RecommendationBundle含run_id、dataset_id、catalog_version、student_id、node_id、recommendations、validation_issues。A负责持久化并通过HTTP提供这些结果。

## HTTP接口

| 方法与路径 | 输入 | data内容及状态 |
|---|---|---|
| GET /api/v1/health | 无 | status、schema_version，200 |
| GET /api/v1/catalog | 无 | catalog_version、topics、indicators，200 |
| GET /api/v1/materials/{material_id} | catalog_version查询参数 | Material，200 |
| POST /api/v1/datasets | multipart六个CSV文件 | dataset_id、status、quality_summary，201；结构不完整422 |
| GET /api/v1/datasets/{dataset_id}/quality | page、page_size | items为QualityIssue，total、page、page_size，200 |
| GET /api/v1/datasets/{dataset_id}/students | class_id可选，page、page_size | 学生items、total、page、page_size，200 |
| POST /api/v1/runs | 见下方 | run_id、status、dataset_id，202 |
| GET /api/v1/runs/{run_id} | 无 | status、阶段、版本、失败信息，200 |
| GET /api/v1/runs/{run_id}/students/{student_id} | node_id必填 | StudentResult，200 |
| GET /api/v1/runs/{run_id}/classes/{class_id} | node_id必填 | ClassResult，200 |
| POST /api/v1/runs/{run_id}/students/{student_id}/recommendations | node_id、mode(rule/model) | job_id、status，202 |
| GET /api/v1/jobs/{job_id} | 无 | status、result或error，200 |
| GET /api/v1/runs/{run_id}/evidence/{kind}/{id} | kind限record/metric | 对应证据与出处，200 |
| POST /api/v1/runs/{run_id}/exports | format固定zip | export_id、download_url、manifest，201 |
| GET /api/v1/exports/{export_id}/download | 无 | ZIP文件流，200；非JSON响应 |

导入multipart字段为requirements、materials、students、nodes、records、dictionary，分别对应六张CSV。只接收这些文件，不接受客户端任意本地路径。需要处理的行级异常允许导入并报告；无法建立主键/关联结构时阻止导入。ImportResult.status为ready或ready_with_issues。

创建运行请求示例：

```json
{
  "dataset_id": "ds-example",
  "catalog_version": "catalog-1",
  "node_ids": ["N01", "N02"],
  "rule_version": "rules-1",
  "config": {
    "min_valid_distinct_items": 3,
    "min_reviewed_item_variants": 2
  }
}
```

上面的证据阈值为待验证启发式，与01一致。不满足变式标注条件时返回证据不足，不能默认为足够。

运行及任务status统一为queued、running、succeeded、failed。前端每2秒查询一次，达到60秒提示“仍在处理”并允许停止前端等待；停止等待不意味着取消后台任务。结果未就绪返回409 RESULT_NOT_READY。模型调用设置有限超时和一次重试，失败明确返回错误或带generation_method=rule的降级结果。

POST导入、创建运行、生成建议及导出支持Idempotency-Key。服务器保存键、请求内容摘要和结果；同键同请求返回同一结果，同键不同请求返回409，防止双击重复任务。

## 学生结果示例

下面是接口示意，不是D01实际诊断；示例只表达没有可用证据的状态。

```json
{
  "student_id": "D01",
  "node_id": "N02",
  "metrics": [],
  "findings": [{
    "finding_id": "finding-example",
    "indicator_id": "T01I2",
    "description": "示例：当前输入不足以形成表现结论",
    "evidence_status": "insufficient",
    "performance": "undetermined",
    "evidence_refs": [],
    "limitations": ["本对象为契约示例，不是实际分析"]
  }],
  "limitations": ["请接入真实分析结果"]
}
```

所有运行相关JSON响应的data必须含run_id、dataset_id、catalog_version，与上面StudentResult字段同级；上例为StudentResult片段，不是完整HTTP响应。ClassResult采用同样方式。RecommendationBundle已经包含这些字段。前端必须验证当前所选run_id，不能仅依赖student_id缓存。

## 成果导出协议

ZIP根目录含manifest.json、README.md、field_dictionary.json、curriculum.json、materials_index.json、data_quality.json、student_analysis.json、class_analysis.json、recommendations.json、metrics.csv、examples/input.json、examples/output.json。

manifest记录schema_version、run_id、dataset_id、catalog_version、rule_version、created_at、生成方式、各文件SHA-256和限制。原始输入样例按赛事允许范围选取，并能复现对应输出；不默认打包全部教材PDF、密钥或开发日志。CSV一行一个metric，含对象类型/ID、节点、指标、分子、分母、值、单位，嵌套证据保留在JSON中。CSV与JSON结果应一致。

## 变更与验收

新增可选字段可保持1.x；删除字段、更改含义或枚举须升级主版本并由所有消费方同步。A维护唯一契约。B/C产生者和D消费者均运行契约验证：正常、无记录、异常评分、旧运行、模型失败、非法引用。导出包重读后引用必须全部可解析，缺失引用即验收失败。
