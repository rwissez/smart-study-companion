# 19 受控智能体与双闭环实施方案

版本0.1，2026-11-24。已获确认的架构方向：先实现一次请求内部的受控任务闭环，再实现跨学习活动的外部学习闭环。本文不改变既有 HTTP 契约、统计口径、角色权限或教师审核权。

## 一 现状判断

当前系统已有确定性业务能力：

- B：数据清洗、统计、质量问题和作答证据工具；
- C：材料检索、规则建议、引用校验和泄答校验；
- A：会话范围、模型适配接口、知识点图谱、Catalog 投影边界。

当前 `/chat` 在未配置模型时仍返回 `MODEL_NOT_CONFIGURED`；配置 `MODEL_PROVIDER=openai_compatible` 后，已接入真实 OpenAI 兼容 Provider、工具定义发送和 `tool_calls` 解析。AgentLoop、PromptRegistry、B 工具的角色注册和服务端上下文注入已经落地。

## 二 目标架构

```text
用户请求
  -> 服务端安全上下文（角色、数据集、运行、学生/班级、节点）
  -> AgentLoop：感知 -> 决策 -> 工具 -> 观察 -> 再决策
  -> B/C/knowledge 只读工具
  -> 证据与策略校验
  -> 候选解释/候选建议
  -> 教师审核与发布
```

LLM 可以判断缺什么证据、选择下一项只读工具、解释工具结果；程序决定它能看什么、能调用什么、统计结果是什么、候选是否可展示。模型不能修改分数、扩大数据范围、跳过引用校验或直接发布建议。

## 三 两个闭环

### 3.1 第一阶段：内部任务闭环

范围是一次请求内部：

```text
分析目标
 -> 查询分析
 -> 查询作答证据
 -> 查询知识关系/材料
 -> 观察结果
 -> 再决定是否继续查询
 -> 生成候选回答
 -> 程序校验
```

第一阶段只允许只读工具，最多8次工具调用，达到范围、时间或轮次上限就停止并说明原因。越权或未注册工具调用直接终止任务，不让模型反复尝试。

### 3.2 第二阶段：外部学习闭环

本轮已完成外部闭环的后端最小骨架：正式 `LearningObservation` 契约、`learning_observations` 表、学生提交事件和教师查询事件。事件仍是新的观察证据，不会原地修改 `AnswerEvent`、成绩或既有分析结果。前端逐步作答、事件驱动的重新分析和下一轮策略生成仍待后续实现。

完整闭环仍需要正式事件契约、数据库表和前端逐步作答界面：

```text
教师发布活动
 -> 学生逐步作答
 -> 记录提示层级、完成状态和作答过程
 -> B 重新形成分析事实
 -> Agent 读取新证据
 -> 生成下一轮候选策略
```

普通聊天不能直接作为有效测验记录，不能把一次对话错误描述升级成长期能力结论。

## 四 A/B/C 分工

### A：AgentLoop、PromptRegistry 与安全边界

- 提示词加载和版本记录，组合角色、任务、策略和结构化上下文；
- AgentTaskState，保存目标、已知事实、缺失信息、证据引用、下一步动作；
- ToolRegistry，提供当前会话允许的工具 schema；
- AgentLoop，执行工具调用、观察结果、更新状态、再规划和停止条件；
- 模型 Provider 适配器，发送工具定义并解析 `tool_calls`；
- 记录 tool trace，但不记录密钥、未必要的原始作答全文；
- 最终校验门和教师发布边界。

### B：事实与证据工具

- 保持统计逻辑只有一份，模型不得重算正式指标；
- 明确单次错误、多次一致错误、证据冲突的不同表述；
- 为作答证据提供评分点、过程片段、处置状态和限制；
- 后续提供 `get_previous_observations`，前提是第二阶段学习事件已经落库；
- 知识点与指标标注由人工核对，不把候选关系当作确定事实。

### C：策略与表达工具

- 将四类规则建议封装为可调用的 `select_strategy`；
- 返回允许策略、禁止策略、活动上限和提示上限；
- 提供材料检索和候选建议工具；
- 维护教师端、学生端、诊断和建议提示词；
- 所有模型草稿继续经过证据、材料、泄答、重复和负荷校验；
- 教师审核前，结果状态只能是候选或待审核。

## 五 第一阶段与 A-Agent-7 当前状态

第一阶段 B 工具多轮解释链路已通过协议级集成测试：

- Provider 接收工具 schema 并返回结构化 `ToolCall`；
- AgentLoop 将 assistant tool call 和 tool result 按 OpenAI 兼容格式写回，并递归规范化 Pydantic/dataclass 结果；
- 教师验收链路已验证：`get_student_analysis` -> `get_answer_evidence` -> 带指标/记录引用的最终回答；
- 未注册工具、越权工具、参数错误有明确失败轨迹；
- 单次请求工具调用不超过8次；
- MockTransport 验证 Provider、数据库上下文和 AgentLoop 多轮协同，但尚未替代授权模型实机验收。

A-Agent-7 已实现规则优先、模糊时一次无工具模型分类的任务路由，并给 16 类任务建立 TaskSpec 和版本化提示词。A-Agent-8 完成后，当前可执行任务还包括 `knowledge_lookup`、`prerequisite_query` 和教师只读 `relation_review`；其他任务仍按各自缺失的工具能力返回 `TASK_NOT_AVAILABLE`。知识工具由服务器绑定 dataset/catalog/KB 版本，学生结果仅含已核对知识与关系，教师候选工具无审核或发布写入能力。

目标采用显式 `target`，旧 `student_id` 保持兼容。学生/班级、节点和 run 由服务端校验并绑定；分类器不能选择目标或工具。`out_of_scope` 使用固定安全回复，不调用模型或业务工具。任务与角色 prompt 版本写入响应；模型分类路径追加 router prompt 版本。

仍待后续：`AgentTaskState` 程序化规划状态、C 材料/策略工具、最终输出校验门（A-Agent-9）、对话与轨迹持久化、完整总时限/预算保护、前端轨迹展示，以及观察事件触发新分析（A-Agent-10）。A-Agent-8 后端知识归属候选、manifest 绑定导入、本地教师审核、新版本发布、不可变快照和只读查询工具已验收（全量 238 passed）。跨资料合并决议、独立教材片段注册、按引用页重读和旧 JSON 显式迁入已补齐；模型没有审核发布权限，人工审核界面仍按原范围留后续，详细边界见 A-Agent-8 设计文档。
