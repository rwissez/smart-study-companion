# A实施方案与可完成性评估

版本0.1，2026-11-19。依据：桌面"赛题数据"文件夹中的官方PDF、参赛说明、典型案例说明、数据说明、全部CSV和课标/教材切片，以及本仓库00—12手册。文中数字均由本机脚本对公开数据直接统计，不是手册里的推测。与11统一实施规范冲突处，以团队讨论确认后的版本为准，本文只提出调整建议。

## 一 结论

1. 三项任务、数据范围和提交物在现有分工下**能够完成**，数据结构清晰，计算量极小（806行）。真正的风险不在算法，而在**A一个人承担的量**和**依赖串行**。
2. A当前的职责合计约相当于一个人的全部时间：报名事务（明天截止）、A0骨架、20张表的数据库、约20个接口、Agent循环、任务队列、课程目录（任务1，含人工核对页码）、导出、方案PDF/PPT统稿。11月25日前全做完不现实，需要分级并砍掉几项机制（第三节）。
3. 手册里有三处与真实数据对不上，必须先改（第二节）：证据充足规则几乎全判"不足"；两个数据异常手册没提到；catalog和dataset的绑定关系不合理。
4. 任务1是A最容易被低估的部分：课标是扫描图片、教材页码抽取后数字是反的、材料表对教材的标注和切片实际章节不完全一致，必须人工核对。

## 二 对赛题和数据的核对（影响设计的事实）

**赛题硬约束**：每校最多推荐5队；方案PDF≤20页；视频≤5分钟；资料评审80%、答辩20%；同分先比"学生学习情况分析质量"再比"建议质量"；独立评测数据（10—20名学生、100—400条记录）另给，字段口径相同，所以不能写死D01—D40或54题。官方原文：缺少记录不等于未掌握；赛事数据不得外传、赛后按要求删除；引入其他公开资料须登记来源。

**数据实况**（脚本统计）：

| 项 | 数值 |
|---|---|
| 作答行 / 作答事件 / 有两个修订版本的事件 | 806 / 799 / 7 |
| 选中（最高版本）事件状态 | 已评分790，待评分4，未作答5 |
| 被取代的历史版本 | 7行（5行已评分、2行待评分） |
| 应排除出得分统计的已评分记录 | 4条（见下），剔除后有效已评分786条，不是"806减7" |
| N01 / N02 实际有记录的学生 | 40 / 39（D17在N02无任何记录，全程只有4条N01记录） |
| 班级 | DC01 21人，DC02 19人 |

四条应隔离的记录：DR0361（D16，Q044，得分10/满分1）、DR0535（D26，Q034，得分4/满分3）、DR0133（Q015得分3，但评分点之和为2）、DR0515（D25在N01作答了Q038，而Q038不在N01可用题目里，且是N01尚未教的T03题）。D16的N02不等式得分率因此会算出142%，是手册没提到的陷阱。另有16条选填题最终作答与参考答案文本不一致却得1分（多为格式差异，如"x=9"对"9"），1条文本一致却得0分（DR0685），应只标记、不改分。

**两个节点的教学范围不同，这是分析口径的关键**：N01的27道可用题只覆盖T01全部、T02I1和1道T02I3，没有T02I2、没有T03；N02的45道题覆盖T01全部、T02I2、T02I3和T03，**不再出现T02I1**。T01在两个节点题目相同，有40个"同一学生同一题"在两节点都作答，是唯一可做限定比较的范围。

**证据充足规则（01号文档）会让结论几乎全部"不足"**：规则要求同一指标至少3道有效不同题。按此规则，360个"学生×指标"格子中只有123个（34%）达标，69个格子完全没有记录；而按"学生×主题"算，120格中111格（93%）达到3题。规则还要求覆盖至少2类人工标注的题目变式，但目前没有任何变式标注。结论：如果不做标注，所有指标都会判"不足"，任务2和3的亮点会消失。建议改为：主题层面做结论，指标层面只做描述并显示题数；变式标注由A在做任务1时一并完成（见4.3），或者取消该条件。

**课程标准页码**：课标PDF共189页，全是扫描图，无文字层，需要人工看图。我已看过文件页62和63（印刷页55、56）：三个主题的课标条目确实在这两页，课程要求表给的页码可用。但代数式条目⑧⑨延续到文件页63，所以CR01的"62／55"不完整，应写成62—63／55—56。

**教材切片**：只有B02（不等式章）、B05（代数式、整式）、B06（方程、方程组）三份与三个主题直接相关；B01、B03、B04、B07、B08分别是实数/相交线、统计、几何、有理数运算、相交线，不在范围内，其中B07（有理数运算）可作为T01I1"代入求值"的先修内容。教材切片文字层可抽取，印刷页码存在但抽取出的数字是倒的（如"96"实为69页，"521"实为125页），且材料表给B01、B02、B06的章节标注与切片里实际出现的章标题不完全一致（例如B06里同时出现第四、五、九、十章）。这是我的初步抽取结果，A必须逐份核对后再写入页码，不能照抄材料表。

**典型案例候选**（按实际记录选取，仍须人工复核）：D04（共11道解答题，其中7道为部分得分，覆盖T01—T03，且有一条修订）适合"部分得分"；D14（所有解答题满分，各主题得分率100%）适合"表现较好"；D17（只有4条N01记录，T02/T03零记录，但2道解答题均满分）适合"记录不足"。D01有待评分、未作答和修订，适合演示数据处理。D16有超满分异常，不宜作为案例。

## 三 分工与可完成性评估

按严重程度排序。

**严重：依赖串行导致B/C/D空等。** 11规定A0合入main后B/C/D才能开分支。A0包含完整contracts、数据库迁移、会话、Agent适配器、前后端启动，若耗时2—3天，其余三人这几天无法开工。建议拆分：
- **A0-a（今天内）**：只交`contracts` v0.1（第4.4节的最小Pydantic类型）加合成fixture，合入main。B、C的函数签名只依赖`RawTables`和这些类型，拿到就能开工；B甚至可以先用pandas在自己分支对真实数据写出统计雏形。
- **A0-b（11月20—21日）**：其余骨架（迁移、health、会话、启动脚本）。D先基于静态示例JSON做页面，不等后端。

**严重：A过载。** 建议下列削减，对赛题得分没有影响：

| 手册设计 | 建议 | 理由 |
|---|---|---|
| jobs表加worker线程加queue | 保留接口形状（202加job_id），但分析与建议**同步执行**，job返回时已是succeeded | 806行的分析是毫秒级；接口不变，D无需改动，A省掉队列、重启恢复和超时逻辑 |
| idempotency_keys表 | P2，最后做 | 本地单机演示，双击问题可由前端按钮禁用解决 |
| 20张表 | 先建datasets、source_rows、students、nodes、answer_events、quality_issues、analysis_runs、analysis_results、recommendations、recommendation_revisions、demo_sessions共11张，其余随功能增加 | conversations/messages/tool_calls依赖Agent，Agent晚于主流程 |
| 主Agent循环 | 排在主流程和导出之后，P1 | 官方评分不要求特定技术；固定流程加按钮已能完整覆盖三项任务和展示 |
| 报名、承诺书盖章 | 建议由B/C/D中一人接手跟进 | 明天截止，且需要指导教师、学院盖章，与编码冲突 |

**中等：模型API全部留空与赛题"智能体"要求之间的张力。** 官方要求"打造智慧学伴智能体"。目前设计在没有模型时只能用规则建议和脚本化测试，答辩时不能说成"大模型驱动"。同时赛题规定数据不得外传，直接调远程模型API存在合规问题。需要团队在11月22日前决定演示用的模型路线（本地模型、经确认允许的远程调用，或明确定位为"规则引擎加可替换模型接口"），否则评委看到的"智能体"只是界面。这是用户的决策，见第五节。

**中等：catalog与dataset的绑定。** 11的`catalogs.dataset_id`外键意味着每个数据集有自己的目录，但目录来源是上传包里的"课程要求"和"题目与材料"两张表，再叠加A人工核对的页码、联系和变式标注。建议改为：**目录 = 导入的两张CSV（按材料编号、指标编号）加一份由A维护的覆盖层文件**。覆盖层键为`material_id`/`indicator_id`，评测数据沿用相同编号时直接生效；遇到覆盖层里没有的新编号，降级为"未标注"，相关证据判不足，而不是报错。

**中等：数据合规。** 手册要求赛事资料不入库，这是对的。覆盖层文件应只含编号、关系、页码和简短标签，不含题干文本，也不含课标原文的大段摘录；需要由队长确认这样放进私有仓库是否可接受，不确定则放在被忽略的`data/catalogs`下，通过私聊分发。

**轻微**：①11说Agent每请求最多8次工具调用，这些参数是初值，可保留；②08里有`B.import_dataset`等旧签名，11已声明以新签名为准，建议删掉旧段落避免误导；③`reviewed_variant_tag`是单个标签，但一个材料可能需要多维标注，先保持单标签，有需要再扩展。

**可完成性判断**：

| 任务 | 负责 | 可完成性 | 主要风险 |
|---|---|---|---|
| 任务1 学习内容梳理 | A | 可完成，约1.5—2天人工核对 | 教材页码需逐份核对；变式标注54题 |
| 任务2 学情分析 | B | 可完成 | 口径细节多（修订、隔离、两节点范围）；证据规则需改 |
| 任务3 个性化建议 | C | 可完成 | 依赖B的事实输出和A的目录，C前期只能用合成数据 |
| 双端界面与成果包 | D | 可完成 | 等待契约和接口；工作量集中在最后三天 |
| 整合与统稿 | A | 吃紧 | 与任务1和后端同时进行 |

## 四 A的实施方案

### 4.1 代码边界

A拥有，且只有A可以改：`contracts/`、`db/`、`api/`、`curriculum/`、`agent/`、`jobs/`、`exports/`、`config.py`、`main.py`、`cli.py`、`migrations/`、根配置和依赖锁文件。A**不**写统计逻辑、不写建议生成逻辑、不写页面。

依赖方向（只允许从上往下导入，用测试强制）：

```text
api  ─┬→ agent ──→ tools ─┬→ analysis.service       (B)
      │                   └→ recommendation.service (C)
      ├→ db（仓储）
      ├→ curriculum
      └→ exports
analysis、recommendation → 只依赖 contracts，不导入 db、api、agent
contracts → 不依赖任何其他包
```

这条规则保证B/C的函数是纯函数，可以脱离服务单独测试。建议加一个`tests/contracts/test_import_boundaries.py`，扫描`analysis`和`recommendation`目录，发现导入`db`、`api`、`agent`即失败。

A对B、C、D的稳定承诺（接口一旦合入main，变更须走08的变更流程）：`RawTables`/`PreparedDataset`/`Catalog`/`StudentResult`/`ClassResult`/`RecommendationBundle`类型，`DomainError`，以及HTTP契约。

### 4.2 瘦身后的构建顺序

先让一条竖线跑通，再变宽：

1. **竖线**：上传六CSV → `prepare_dataset`（B）→ 落库 → `analyze_dataset`（B）→ 保存 → 查询单个学生 → `recommend_rules`（C）→ 返回。同步执行，一个学生。
2. **变宽**：全部学生、两个班、质量报告接口、证据查询、教师修订接口、学生角色裁剪。
3. **导出**：按08的ZIP结构生成成果包，D复核。
4. **Agent**：`ModelProvider`协议、未配置适配器、工具注册、调用记录、对话存储。

### 4.3 任务1：课程目录（A的第一个实质交付物）

产物是机器可读的目录加面向PDF/PPT的展示表，而不只是架构图。

**输入**：课程要求CSV（9条指标）、题目与材料CSV（54题加3张学习卡加8个教材条目）、课标PDF第62—63页、教材切片B02/B05/B06，B07作为先修参考。

**产出文件**（先落在`data/catalogs/catalog-1/`，覆盖层文件按第三节合规决定放哪里）：

| 文件 | 内容 |
|---|---|
| `curriculum.json` | 3个主题、9个指标、每个指标的课标条目（CR编号、课标文件页／印刷页、条目序号）、教材章节及印刷页范围 |
| `materials_index.json` | 54题加3学习卡加相关教材条目，每项含主题、指标、类型、出处定位（文件页、印刷页、`verification_status`） |
| `links.json` | 必要联系，每条含`from`、`to`、`relation`（`supports`/`prerequisite`）、`basis`（`standard`/`textbook`/`team_inference`）、说明 |
| `variant_tags.json` | 54题的变式分类（仅用于证据覆盖检查） |
| `catalog_review.md` | 逐条核对记录：谁核对、核对到哪一页、结论 |

**必要联系初稿**（均需A核对并标明依据，团队推断不得写成课标原文）：
- T02I1 → T03I1：等式性质到不等式性质，对比"乘除负数"的方向处理（`supports`，教材/团队推断）
- T01I1 → T02I3、T03I3：用代数式表示数量关系是列方程和列不等式的前提（`prerequisite`）
- T02I1 → T02I2：一元一次方程是消元法的目标形式（`prerequisite`）
- T03I1 → T03I2：先会解单个不等式再求交集（`prerequisite`）
- 有理数运算（B07）→ T01I1、T03I1：负数代入和负数乘除（`prerequisite`，仅在目录中标注，B07不纳入三个主题的材料库）
- 学习卡L01/L02/L03分别对应三个主题的全部指标

**变式标注规则**：54题按"题型加考查方式"分类，例如选择判断、直接计算、多步化简、情境建模；每个指标内至少要出现2类才算有变式覆盖。标注由A先做初稿，C核对教学含义。如果团队决定取消"≥2类变式"条件，可跳过这一项，节省约半天。

**核对清单（必须逐项打勾）**：
- 课标：文件页62、63已确认；补记CR01应为62—63／55—56
- 教材：B02、B05、B06逐份建立"文件页 → 印刷页 → 章节"对照，注意抽取的页码数字是反的，需对照页面图像确认
- 材料表中B01—B08的标注与实际内容逐项比对，不一致处以实际内容为准并记录
- 54题每题唯一指标、满分、评分点编号在材料表和作答记录中一致（我已核对满分一致，评分点未逐条核对）
- T01I3（仅2题）、T03I3（4题）、T02I3（4题）题量偏少，在目录中标注"可用题少，难以单独形成结论"

**验收**：B的`analyze_dataset`和C的`search_materials`直接读取该目录并通过测试；引用可打开到正确材料和页；覆盖三个主题。
