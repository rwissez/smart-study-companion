# 架构与数据设计

技术选型已固定于11统一实施规范；本文件解释业务与数据原则。实施使用11的完整目录、数据库表和模型签名，不再自行选择框架或存储方案。

## 目标与范围

建立可运行的本地双端原型，包含教师端和学生端，完成学习要求梳理、个体及群体分析、个性化建议，并可查看依据、导出成果、导入同字段口径的新数据。教师端支持班级分类、学生学习画像和教学对话；学生端查看自己的画像、学习建议和学习对话。基础版使用明确标记的模拟身份选择，不要求生产级账号体系；两端响应由后台按会话角色裁剪，不能仅靠前端隐藏。具体视觉与布局由D设计。

基础版不做注册、权限平台、云部署、大模型训练或真实教学成效证明。推荐确定性统计加可核对的建议生成；大模型负责受约束的解释和建议组织，不能改写统计或创造材料引用。规则降级输出须明确标识，不能冒充模型生成。

## 模块和调用

模型API供应商、地址、模型名和密钥默认未配置、可选接入，未配置时返回MODEL_NOT_CONFIGURED，不产生假模型回复；分析工具和已保存结果仍可工作。学生画像仅为模拟作答形成的学情摘要，包含表现、覆盖、证据与不确定项，不推断性格、智力、家庭或动机。

补充架构：React网页 → Python服务 → 单一主智能体/受控工作流 → 业务工具库 → 数据与材料。智能体是后台中的决策与解释层，Python/React是实现语言与界面层，两者不是互斥方案。下图表示工具库的业务依赖；智能体调用机制见09。

```text
CSV数据包 → B导入/校验 → 不可变数据快照 → B统计及表现事实
课标/教材 → A人工核对的课程目录 ─────────┤
                                         ↓
                             C诊断解释/材料匹配/建议校验
                                         ↓
                           A统一服务 → D界面与成果导出
```

A拥有主流程、共享数据模型和服务启动；B拥有清洗与统计；C拥有诊断解释、建议和引用核对；D拥有界面、展示和打包。共享模型放在 contracts，禁止各模块复制一套不同定义。

A同时负责主智能体、工具注册及调用记录；B将分析能力封装成工具；C将材料匹配与建议能力封装成工具，并与A共同维护教学提示。所有工具也可直接由固定流程调用。原始数据导入、版本选择、统计和最终校验必须执行，不能交给模型决定是否省略。

建议 Python 后台暴露 HTTP，React + TypeScript 消费接口。初版使用本地 SQLite 保存元信息及运行索引，CSV/JSON 保存不可变原始和派生文件；无需图数据库或向量数据库。模型适配器可替换，通过环境配置选择。具体框架版本由实施时统一锁定，不由各队员自行升级。

## 数据实体与关联

| 实体 | 主键 | 主要内容和关联 |
|---|---|---|
| DatasetSnapshot | dataset_id | 导入时间、文件校验值、来源说明、父快照 |
| Student | dataset_id + student_id | class_id、grade；不限制为D01—D40 |
| AssessmentNode | dataset_id + node_id | 日期、教学说明、可用题目集合 |
| Indicator | catalog_version + indicator_id | 主题、要求、课标及教材定位 |
| Material | catalog_version + material_id | 类型、题干、指标集合、评分点、出处 |
| RawRecord | dataset_id + record_id | 原始14字段及来源行号，不覆盖 |
| AnswerEvent | dataset_id + event_id | 关联学生/题目/节点，全部修订记录，选中记录 |
| QualityIssue | issue_id | 问题代码、范围、严重程度、处理动作、受影响记录 |
| AnalysisRun | run_id | 数据快照、目录版本、规则版本、配置、运行状态 |
| Metric/ Finding | metric_id / finding_id | 运行内唯一，数值或表现描述与证据引用 |
| Recommendation | recommendation_id | 所属运行、学生、诊断、材料、提示、调整条件 |

所有派生结果必须带 dataset_id、run_id。课程目录另有 catalog_version。缓存键至少包含这些版本及分析配置，不能把另一数据版本的建议展示给当前学生。

## 原字段映射

作答记录：记录编号→record_id，学生编号→student_id，材料编号→material_id，主题编号→topic_id，节点编号→node_id，作答事件编号→event_id，修订版本→revision，模拟提交时间→submitted_at，评分状态→grading_status，得分→score，满分→max_score，学生最终作答→final_answer，解答过程→solution_steps，评分点得分→rubric_scores。

模拟学生：模拟班级编号→class_id，年级→grade。课程要求：指标编号→indicator_id，观察指标→description。材料的多个指标按“、”拆分；评分点按字段定义解析，保存原文。时间保留原时区，数值缺失保存 null，不能转成0。

课标文件页与正文页是不同字段。教材切片页与原教材印刷页也分别记录；未验证的页码标为未验证，不猜页数。必要联系由A审阅建立，使用 supports 或 prerequisite 关系，并注明依据；不要把团队推断说成课标原文。

## 数据处理顺序

1. 验证六个CSV的表头、编码、数据类型和主外键；保留原文件及文件校验值。文件路径仅允许包内相对路径。
2. 检查重复记录编号。完全相同的重复行保留来源痕迹后去重；同编号不同内容为冲突，隔离相关记录并报告。
3. 按event_id检查学生、题目、节点一致性。同事件最高revision唯一时选中；同最高版本不同内容时隔离事件，不能凭时间猜测正确版本。
4. 最高版本待评分、未作答或异常时，保留其状态，不回退旧版作为当前得分。历史版本可查看，不重复计分。
5. 校验题目属于节点可用集合、主题与材料一致、满分与题目一致、得分在范围内；核对评分点合法性及总和。出现冲突保留官方原值并隔离受影响的分数统计，不能自动改分。
6. 已评分且校验通过的选中记录进入分数统计；待评分、未作答、隔离事件分别计数。缺少解答过程时不编造步骤诊断；非解答题过程为空属正常情况。
7. 生成每个事件的处置日志，汇总选中、历史、冲突、待评分、未作答、有效评分数量，验证数量可对账。

## 统计口径

| 指标 | 定义 | 边界 |
|---|---|---|
| 得分率 | 有效已评分记录得分和 / 对应满分和 | 分母0返回null |
| 满分题比例 | 有效记录中得满分的题数 / 有效已评分题数 | 不称为所有题目正确率 |
| 观测作答比例 | 选中事件中已评分或待评分事件数 / 全部选中事件数 | 仅反映已出现记录，非任务完成率 |
| 题库覆盖率 | 有效已评分不同题目数 / 节点该指标可用题目数 | 衡量观测覆盖，不意味着所有可用题均被布置 |
| 学生观测率 | 有该指标有效记录的学生数 / 班级名册人数 | 保留无记录学生 |

每项统计保存分子、分母、范围、记录引用和排除说明。班级得分率采用汇总得分/汇总满分，另可提供学生得分率均值，但需区分名称及有效人数。不得只统计有记录的人却声称覆盖全班。

两节点教学范围不同，不能直接将总分变化解释成进退步。基础版并列展示；仅在共同题目、共同指标且分母可解释时做限定比较。提交时间不能用于推断答题时长。

证据充足规则作为显式配置，初始候选为同指标至少3道有效不同题且覆盖至少2类经人工标注的题目变式；这是团队启发式，需用案例检验，不是经验证的掌握阈值。条件未满足标insufficient，不输出确定性掌握结论。表现和证据充足程度分开存储。

## 运行与复现

导入产生不可变dataset_id。分析产生run_id，记录规则版本、目录版本、配置、程序版本。补充数据形成新快照和新运行，旧运行可回看。规则统计同输入必须一致；模型结果保存模型标识、提示模板版本、实际输入引用、输出和校验状态，不能承诺文本每次完全相同。

模型输出先做结构验证、ID存在性验证、证据是否属于本学生本运行验证、教学范围验证，再交付。失败可重试一次；仍失败返回规则建议或needs_review，展示真实生成方式。

## 验证与交付

重点测试修订、重复冲突、超满分、无记录、未作答、待评分、引用越界和不同教学节点。人工复核三名典型学生以及班级汇总，保存核对结果；另用自建且明确标为测试的数据验证未知学生编号。自建数据不冒充官方独立评测或正式案例。

应用本地监听，原始数据不入代码仓库。模型远程调用前由A确认赛方允许的数据使用方式，未确认则使用本地规则演示；密钥仅放环境变量。正式演示提供可恢复的已保存运行结果，并明确是历史结果。
