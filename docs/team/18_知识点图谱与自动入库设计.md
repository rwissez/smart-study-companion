## 一 先统一用词（必读）

项目里"节点"已经被占用：`Node` / `node_id`（N01、N02）是**测验节点**（教学阶段）。你说的"节点是关键词、知识定义"与它重名，写进代码和文档会互相混淆。本文约定：

| 本文用词 | 含义 | 编号 | 与现有概念的关系 |
|---|---|---|---|
| **知识点（KP）** | 一个被定义或首次引入的概念/术语，如"不等式的基本性质" | `kp_id`，如 `KP-B02-0007` | **新增**，比指标更细 |
| 指标（Indicator） | 赛题的9个观察指标，评分与建议的单位 | `T01I1` 等 | 不变；一个指标对应多个知识点 |
| 测验节点（Node） | N01/N02 | `node_id` | 不变，与知识点无关 |
| 单元 | 教材的"章" | `unit` 字段 | 由知识点反查得到 |
| 段（Segment） | 教材里的一个小节/连续片段，是抽取知识点的最小处理单位 | `segment_id` | B 的 `split-textbook` 已经产出小节 |

你的流程用这套词表达：**输入资料 → 切段 → 每段抽取新出现的知识点 → 关键词定位到单元 → 单元内定位到章节页码 → 在知识点之间建关系 → 题目/学习卡标注到知识点**。

## 二 总体结构（只加不改）

```text
用户资料（PDF文字层 / 扫描PDF / 图片）
   │  S0 采集：逐页得到 PageRecord（文件页、印刷页、文字、OCR置信度）
   ▼
 S1 切段  ← 复用 B 的 split-textbook（章/节/页码矫正），不重写
   ▼
 S2 知识点抽取：每段只登记"新出现"的知识点（first_seen）
   ▼
 S3 关键词索引：term/别名 → kp → 段 → 章 → 页码   （查询入口）
   ▼
 S4 关系构建：从属 / 衍生 / 合并创造 / 特例   ← 智能体重点参与
   ▼
 S5 标注：题目、学习卡、评分点 → 知识点          ← 智能体重点参与
   ▼
 S6 投影：知识点图 → 现有 Catalog（Indicator/Material/CatalogLink）
         └─ 现有 B 分析、C 建议、API、前端完全不感知这一层
```

关键边界：S0–S5 都在新包 `src/study_companion/knowledge/` 内；S6 是唯一接缝，输出的就是 13 号文档规划的 `curriculum.json / materials_index.json / links.json`。即使知识点图谱没做完，旧流程照常运行，只是目录由手工表格生成。

## 三 数据模型（新包内部，不进 `contracts/`）

先放在 `knowledge/models.py` 自己的 Pydantic 类里，团队确认稳定后再决定是否并入 `contracts/`。字段刻意与现有 `SourceLocator`（`source_file / pdf_page / printed_page / verification_status`）保持同名同义，投影时零转换。

**KnowledgePoint**

| 字段 | 说明 |
|---|---|
| kp_id | 唯一编号 |
| name、aliases | 规范名和别名（同义说法、符号写法），查询用 |
| definition_locator | 定义出现的位置（文件、文件页、印刷页、章、节）。**只存位置和短摘，不存大段原文**（合规，见十） |
| first_seen_segment | 教材顺序里首次出现的段；"新出现"据此判定 |
| unit | 所属章（可由 first_seen_segment 推出，冗余存） |
| indicator_ids | 对应的指标，可空；带 basis 与状态 |
| extraction | rule / agent / human，附规则版本或模型标识 |
| verification_status | unverified / verified / rejected |

**KPRelation**（四种关系的统一存储）

| 字段 | 说明 |
|---|---|
| relation_id | 唯一编号 |
| type | `has_property` 从属 / `derives_from` 衍生 / `composed_of` 合并创造 / `special_case` 特例 |
| target_id | 关系的"结果端"（见第四节方向约定） |
| source_ids | 关系的"来源端"，列表；`composed_of` 必须 ≥2 个，其余恰好 1 个 |
| basis | standard / textbook / team_inference（沿用 08，团队推断不得写成课标） |
| evidence | 依据位置：段编号 + **该段原文中的一个子串**（用于程序核对） |
| proposer | human / rule / agent |
| verification_status | candidate / verified / rejected |
| review | 核对人、时间、查看的文件页、结论（对应表4"人工核对记录"） |

合并创造是"多对一"，所以来源端用列表，避免为它单独造一种表。

**Annotation**（S5）：`material_id → [kp_id]`，另可选 `rubric_point_id → kp_id`（为 B-L2 评分点级诊断提供"丢分对应哪个知识点"）。

## 四 四种关系的定义（已由你确认）

统一存储方向：`source_ids → target_id`。

| 关系（代码名） | 你的定义 | source → target | 例子（取自 B02 教材页，仅作说明） |
|---|---|---|---|
| 从属 `has_property` | 一个概念具有的性质，这些性质从属于该概念 | 概念 → 性质 | 不等式 → 不等式的性质1/2/3 |
| 衍生 `derives_from` | 同一知识点在不同条件下，某个性质发生了变化 | 原知识点 → 变化后的知识点 | 等式的性质 → 不等式的性质（乘负数时不等号方向改变）。这条是我按教材第6页"比较性质2和性质3"的写法理解的，**是否这样标由你定** |
| 合并创造 `composed_of` | 两个及以上知识点组合推导出新的性质或概念 | 多个来源 → 新概念/性质 | 若干个不等式 + 公共部分 → 不等式组的解集 |
| 特例 `special_case` | 特殊的现象、公理，无法用一般形式举例 | 相关一般概念 → 特例 | 由你在标注时确定，我没有找到足够确定的例子 |

程序强制的约束：`composed_of` 来源 ≥2；其余三种恰好 1 个来源；两端不能是同一个知识点；`has_property`、`derives_from` 不允许成环；同类型同端点不重复。

**我的理解与你的定义有一处需要确认**：你说的"从属"是"概念 → 它的性质"。我之前设想的是"小概念属于大概念"（分类），已按你的说法改。因此"不等式的解集"这类**定义出来的术语**不算"从属"，它们是独立的概念知识点，彼此的关系要靠衍生/合并创造表达。

## 五 S0–S3：自动入库（你来做的第一步）

**输入类型与处理方式**

| 输入 | 处理 | 现状 |
|---|---|---|
| 带文字层的 PDF（教材切片） | pypdf 抽文字；页脚倒序页码矫正沿用 B 的 `normalize_page_number` | 已有 |
| 扫描 PDF / 图片（课标189页全是扫描图，无文字层） | 本地离线 OCR（RapidOCR）；每页记录置信度，偏低的页标记待人工看图 | **已实现并实测**：课标文件页62、63识别平均置信度0.986、0.992，约5–8秒/页（见十二） |
| CSV（课程要求、题目与材料） | 走现有 `prepare_dataset` / 目录导入，不进本流程 | 已有 |

OCR 用可替换适配器（`PageExtractor` 协议，`PyPdfExtractor` 与 `RapidOcrExtractor` 各一个实现）；`pick_extractor` 按 PDF 有无文字层自动选择。RapidOCR 是纯本地推理，页面图像不外发，符合赛事资料不得外传的要求。它是**可选依赖**，目前没有写进 `pyproject.toml`，用 `uv run --with rapidocr-onnxruntime ...` 临时带上；要不要正式加入依赖和锁文件，由你决定。

**S2 抽取"新出现的知识点"**：按教材顺序逐段处理，维护"已登记术语集"。

1. 规则先行（可复核、可重复）：定义句式（"叫做""称为""我们把……叫做""记作"）、黑体/标题、小节标题、"定义""性质""定理"标记。命中的术语成为候选知识点。
2. "新"的判定：术语首次出现在某段 → 登记 `first_seen_segment`；之后各段只增补出现位置，不重复登记。
3. 模型可选（未配置也能跑）：补充规则漏掉的隐含定义、合并同义说法；输出只是候选，必须带原文子串，程序核对子串确实存在于该段。
4. 所有结果 `unverified`；字体映射错乱（B 已发现"狓=ｘ"）的字符保留原文，别名里补正规写法。

**S3 查询**（规模小，不上向量库，沿用 11 的约束）：

```text
locate(keyword)  → [{kp, unit(章), section, file_page, printed_page, verification_status}]
                   匹配顺序：规范名精确 → 别名 → 子串；多个命中全部返回，不猜
neighbors(kp, type?, depth)  → 相邻知识点及关系
prerequisite_closure(kp)     → 向上游追溯的全部来源（用于补救建议）
```

对应你说的"根据关键词定位到大体单元，再根据内部数据定位到章节页码"：`locate` 返回的 `unit → section → 页码` 就是这条链；页码若仍是 `unverified` 就如实带出，不猜页数。

## 六 S6：投影回现有目录（给你的通俗解释）

**问题**：项目现有的 B（分析）、C（建议）、API、前端，读的都是一张叫 `Catalog` 的表：指标、题目、教材条目、"A支持B/A是B的前置"。这些接口已经定了，你不让改。

**你的知识图谱是新的、更细的一层**（知识点和四种关系）。如果它只自己躺在文件里，B、C 用不上。

**投影就是一个翻译器**：把知识图谱里的内容，按固定规则翻译成 `Catalog` 能懂的格式，B/C 照旧读 `Catalog`，完全不知道背后有知识图谱。好比你用细致的地图（知识图谱）画一张简图（Catalog）给只认简图的人看。

| 知识图谱里的 | 翻译成 Catalog 里的 |
|---|---|
| 知识点的定义位置（文件页、印刷页、章、节） | 教材条目的出处 `source_locator`，核对状态原样带过去 |
| 知识点属于哪个指标 | 教材条目的 `indicator_ids` |
| 题目标注了哪些知识点 | 题目的指标，并与 CSV 里的材料表比对，不一致就列入核对清单，不覆盖 |
| 衍生（A→B） | A 是 B 的"前置"（`prerequisite`）：你已确认，学生不会原知识点就不能学习衍生知识 |
| 合并创造（A1…An→C） | 每个 Ai 是 C 的"前置"（`prerequisite`） |
| 特例（一般→特例） | 一般知识"支持"理解特例（`supports`）：你已确认，特例可以单独认识 |
| 从属（概念→性质） | 不翻译（是"属于"，不是"学习顺序"）；只用于归并到指标 |

以上方向已经确认并实现。只有你核对过（`verified`）的关系才会翻译进正式目录；未核对的候选保留在投影报告中，C 不会拿它们当建议依据。两端知识点都必须先标到指标，且必须跨指标，才能生成 `CatalogLink`；缺少标注或只在同一指标内的关系会被跳过并产生警告。

## 七 智能体能否仿照你的做法？——能，但有边界

结论：**S4 关系构建和 S5 标注适合交给智能体"提议"，不适合交给它"定案"**。理由是这两步是语义判断，规则覆盖不全；而 S0–S3 有明确规则，应保持确定性，智能体只做补漏。

**推荐的"人先示范、智能体仿照、程序核对"流程**（与 15 号文档 §五"程序定事实，模型写解释，程序核对"同构）：

1. **你先完整做一个单元**（建议选知识点之间关系种类最全的一章，例如 B02 不等式；选哪章由你定）：校正 S2 的输出、手工建四类关系、标注该单元的题目。这一份是**金标准**，同时承担三个用途：写判定细则的活例子、给智能体的少样本示例、事后的测试答案。
2. **把你的判断沉淀成细则**：第四节你给的四条定义加上你遇到的边界例子，写成 `prompts/kp_relation.md`（C 维护提示词，A 装配，沿用现有分工）。
3. **智能体对其他单元输出候选**：每条候选必须含 type、source_ids、target_id、`evidence`（该段原文子串）、一句理由。
4. **程序核对（强制，不可跳过）**：
   - 所有 kp 存在；类型合法；`composed_of` 来源 ≥2；
   - `evidence` 子串确实出现在引用的段内；
   - 无环（`has_property`/`derives_from`）、无重复；
   - 方向规则检查（来源知识点的定义页不应晚于结果端，除非教材明示后文回指，须标记待复核）——**这一项尚未实现**；
   - 不通过的候选直接丢弃并计数，不展示。
5. **用金标准量化**：保留你已标注的另一个单元做留出验证，统计智能体候选与你标注的一致率（按关系类型分别算）。一致率决定后续人工复核的抽查比例；**我没有跑过，不预设数字**。
6. **状态规则**：智能体产出永远是 `candidate`，只有人填写核对记录后才能变 `verified`；这样"团队推断"和"课标/教材明确"不会混淆。

`S5` 标注同理：智能体给每道题提议知识点，附题干里支撑的关键词；程序核对关键词出现在题干/评分点中且 kp 存在；你抽查。

模型未配置时：S0–S3 照常自动运行，S4/S5 退化为"规则候选 + 全人工"，进度变慢但不阻塞；不得把规则候选写成模型输出。模型接入受 15 号文档的合规与预算约束（文本外发须确认；批量离线跑并缓存，不在请求路径上实时调用）。

## 十 合规与可靠性

- 仓库只提交代码、编号、关系、页码和短标签；题干、教材原文、课标摘录、真实学生数据留在 `data/` 本地，与 13 号文档第三节一致。`definition_locator` 只存位置与短摘。
- 用户自传的图片/PDF 默认 `unverified`，系统只做抽取和结构校验，不判断真伪；OCR 低置信度页单独标记。
- 外发文本（云端 OCR、多模态、远程模型）一律走 15 号文档第二节的最小化与审批，未确认不得使用。
- 所有自动产物保留 `proposer`、规则版本/模型标识，便于答辩说明"哪些是人核对的，哪些是自动候选"。
