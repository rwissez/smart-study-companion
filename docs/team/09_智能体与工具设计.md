# 智能体与工具设计

实施选型已确定：按11用Python受控调用循环和ModelProvider协议实现，不再由各成员选择LangChain/LangGraph。实际代码目录以11为准，下面简写目录仅说明所有权。模型API默认未配置、可选接入；ScriptedProvider仅验证循环，真实模型接入属于后续验收。

## 推荐方案及取舍

推荐单一主智能体加业务工具库。Python后台承载智能体和工具，React网页承载教师交互。主智能体识别任务、选择允许工具、结合结果组织解释；程序保证统计、数据版本和引用验证的确定性。

三种实现路径：固定流程最快且容易复核，但自由追问能力有限；单主智能体加受控工具调用支持追问且便于追踪，推荐作为目标架构；多个自主智能体协作增加协调与调试工作，当前三项任务已有明确顺序，暂不采用。先实现固定流程作为可运行基础，再加入单主智能体，共享同一套工具，不重写业务逻辑。

智能体框架是可替换的编排实现，暂不绑定LangChain、LangGraph或某模型厂商。选型时依据已有依赖、模型接口和可维护性确认，不为使用框架而改变数据协议。第一版工具是后台普通函数，暂不建设独立MCP服务器或多服务平台。

## 一次任务怎么完成

教师选择数据版本和学生，输入“分析这名学生的不等式问题，并安排练习”。服务端绑定dataset_id、run_id、catalog_version和student_id，检查运行已完成。智能体请求该学生分析，必要时查看具体作答和质量问题，再请求材料检索，生成教学建议。程序执行结构、范围、引用和必要统计核对后保存结果，网页显示结论、工具调用摘要和可点击依据。

若分析运行尚未建立，先由服务固定流程创建并完成分析。自然语言未明确学生或班级时要求用户选择，不让模型猜目标。数据文件或学生作答中的指令只作为数据，不能成为工具执行命令。

## 工具目录

所有工具隐式接收服务端Context(run_id,dataset_id,catalog_version,allowed_student_ids)，模型不能修改这些字段。显式参数仅选择该范围中的对象或指标。

| 工具 | 负责人 | 显式参数 | 返回 |
|---|---|---|---|
| get_student_analysis | B | student_id、node_id | 08的StudentResult及版本 |
| get_class_analysis | B | class_id、node_id | 08的ClassResult及版本 |
| get_quality_issues | B | student_id可选、page | 当前范围质量问题 |
| get_answer_evidence | B | record_ids | 当前范围原始作答及处置说明 |
| search_materials | C，A提供目录 | indicator_ids、node_id、limit | Material列表，适用依据 |
| build_recommendations | C | student_id、node_id、finding_ids、material_ids | RecommendationBundle |

build_recommendations从服务器取已保存分析和候选材料，不接受模型重写的分数。其内部可调用一次受约束的文本生成，但不再启动子智能体。最终validate_references由服务强制执行，不作为模型可跳过的可选步骤。

工具返回统一ToolResult：call_id、tool_name、status(succeeded/failed)、data、error可null、evidence_refs。失败data为null，error包含code/message；服务检查参数和范围后才执行。

## 调用限制与留痕

每个请求最多8次工具调用，单工具失败最多重试1次且计入总次数；总处理时间默认120秒，模型请求超时45秒，这些是团队可调初值，不是平台限制。只读工具可安全重试；建议写入使用幂等键。达到上限则返回已验证部分及未完成说明，不伪造成功。

记录agent_request_id、job_id、run_id、模型标识、提示版本、工具名称、经处理的参数、起止时间、状态、证据ID。调用摘要是实际执行轨迹，不是模型隐藏推理。敏感凭据不进入日志，原始资料不无差别写入日志或外发。

建议任务失败时可回退固定规则，但generation_method必须是rule并附降级原因；纯规则流程演示不能称为已接入模型的工具调用智能体。

## 新增HTTP协议

模型API配置默认未配置，可选接入；未配置时返回08规定的MODEL_NOT_CONFIGURED，不产生模型回答。双端会话沿用08的demo-session：教师可选择班级或学生，学生target强制为会话绑定本人，提示词分别使用teacher/student表达配置。学生不能调用get_class_analysis或查询他人证据，服务端及工具执行层均检查范围。

对话请求增加conversation_id（首条可不传）；后台创建并绑定session、role、run_id、target、node_id，返回conversation_id供续聊。后续请求的范围不同则返回409并要求创建新会话，前端切换角色或对象后不复用旧对话。教师对话和学生对话的历史不可混用。对话内容不直接改写正式测验记录或画像统计。

本节为08的补充，沿用08的响应包络、错误和幂等约定。

POST /api/v1/agent/requests 输入message、run_id、target(type=student/class及id)、node_id；返回202，data包含agent_request_id、job_id。目标必须由界面明确选择，服务检查目标属于运行数据。

GET /api/v1/jobs/{job_id}沿用08。智能体任务成功的result含agent_request_id、run_id、dataset_id、catalog_version、answer、evidence_refs、recommendation_ids、tool_trace、limitations、generation_method(model/rule)。tool_trace每项含call_id、tool_name、status、duration_ms、evidence_refs，不包含密钥或原始隐藏推理。没有建议时recommendation_ids为空。

基础版不要求流式输出。按钮式生成和自然语言生成调用同一服务与工具，避免两条路径数值不同。

## 验收顺序

1. 不接模型，所有工具通过输入输出和范围校验；一个案例跑通固定流程。
2. 接入经授权的模型配置，验证能实际选择工具并使用工具返回结果。
3. 相同学生、节点和运行的智能体数值与B结果一致。
4. 无记录、评分异常、模型超时、无效材料和引用越界均有明确结果。
5. 换学生或数据版本不串结果，新增记录后重新运行能解释建议变化依据。
6. 三个代表案例逐条人工复核，前端可看到真实调用及引用。
