# 统一实施规范

版本1.0，2026-11-19。四个Codex共同执行的技术基线。本文件固定实现约定，00—10提供业务背景；实现目录、技术栈、函数签名和认证启动流程冲突时以本文件为准，赛题要求及用户最新指示优先。本文是实施规范，列出的文件、脚本和命令尚需A/D创建并验证，不代表现有项目已实现。

## 一 技术选型冻结

| 层 | 固定选型 | 所有权 |
|---|---|---|
| 后端语言 | Python 3.12，uv管理依赖，提交uv.lock | A |
| HTTP服务 | FastAPI + Uvicorn，Pydantic v2校验 | A |
| 数据库 | SQLite + SQLAlchemy 2.x，同步Session | A建表及仓储 |
| 数据库迁移 | Alembic，初始迁移纳入Git | A |
| 数据处理 | pandas，金额无关的计数/分数使用整数；比例最后计算 | B |
| 智能体 | Python自建受控工具调用循环，不引入LangChain/LangGraph | A |
| 模型接入 | 可替换ModelProvider；真实供应商/地址/模型名/密钥留空 | A |
| 前端 | React + TypeScript + Vite，npm，提交package-lock.json | D在A骨架分支协作 |
| 前端配套 | React Router、TanStack Query、Recharts、CSS Modules | D |
| 验证 | pytest + httpx；Vitest + Testing Library；Playwright关键路径 | 对应模块负责人 |

Node统一22.x且不低于22.12，A记录实际补丁版本；Python、Node补丁版本及全部库的实际解析版本在A0骨架验收时写入README并提交锁文件，此前不得声称版本组合已验证。初始化后队员运行uv sync --frozen和npm ci，不各自执行latest升级。D可以自由设计视觉，但不能擅自换React为Vue或增加另一套状态框架。

采用本地模块化单体：一个后端进程、一个SQLite数据库、一个前端工程。暂不使用Redis、Celery、Docker、向量数据库、微服务或独立MCP服务器。

## 三 数据库存储约定

主键ID用UUID字符串（原始学生/题目/节点编号保留）。时间为带时区ISO字符串；JSON用SQLAlchemy JSON列，SQLite实际存JSON文本。除注明可空外字段必填；ORM迁移显式非空、唯一键、外键。源数据冲突首先进入原始行表，不让数据库约束掩盖质量问题。

| 表 | 主要列 | 主键/约束 |
|---|---|---|
| datasets | id, created_at, parent_id可空, status, manifest_json | id；parent_id→datasets |
| source_rows | id, dataset_id, table_name, row_number, payload_json | id；dataset_id外键；唯一(dataset_id,table_name,row_number) |
| students | dataset_id, student_id, class_id, grade | 联合主键(dataset_id,student_id) |
| nodes | dataset_id, node_id, payload_json | 联合主键(dataset_id,node_id) |
| catalogs | version, dataset_id, content_hash, created_at | version；dataset_id外键 |
| indicators | catalog_version, indicator_id, payload_json | 联合主键；catalog外键 |
| materials | catalog_version, material_id, payload_json | 联合主键；catalog外键 |
| answer_events | dataset_id, event_id, student_id, node_id, material_id, selected_source_row_id可空, disposition | 联合主键；学生/节点联合外键；选中行外键 |
| quality_issues | id, dataset_id, event_id可空, payload_json | id；dataset外键 |
| analysis_runs | id, dataset_id, catalog_version, rule_version, config_json, status, created_at, error_json可空 | id；dataset/catalog外键 |
| analysis_results | run_id, subject_type, subject_id, node_id, payload_json | 四字段联合主键；run外键 |
| recommendations | id, run_id, student_id, node_id, current_revision, payload_json | id；run外键 |
| recommendation_revisions | id, recommendation_id, revision, author_session_id, reason, payload_json, created_at | 唯一(recommendation_id,revision) |
| demo_sessions | id, token_hash, role, dataset_id可空, student_id可空, expires_at | id；token_hash唯一 |
| conversations | id, session_id, run_id, target_type, target_id, node_id, created_at | id；session/run外键 |
| messages | id, conversation_id, sequence, role, payload_json, created_at | 唯一(conversation_id,sequence) |
| tool_calls | id, job_id, conversation_id, tool_name, args_json, result_json, status, duration_ms | id；job/conversation外键 |
| jobs | id, run_id可空, session_id, kind, status, request_json, result_json可空, error_json可空, created_at, updated_at | id |
| idempotency_keys | session_id, endpoint, key, request_hash, response_json | 前三字段联合主键 |
| exports | id, run_id, relative_path, manifest_json, created_at | id；run外键 |

analysis_results的payload保存08完整StudentResult/ClassResult。Metric/Finding ID在run内唯一；证据查询由仓储在该run结果中定位，不另建第二份数值源。answer_events的材料与目录关系通过dataset对应catalog验证，A服务保证catalog属于该dataset，避免把公开题库用于不兼容的新输入。

SQLite每个连接启用foreign_keys=ON，设置busy_timeout和WAL；每请求/后台任务使用独立Session，事务短小。模型请求前关闭读事务，不持锁等待网络。源文件只保存在本地raw目录，数据库保留来源、行号与原始值；同一快照不可覆盖。迁移由A独占修改，B/C通过仓储交接，不各自建立数据库。

## 四 模块签名固定

以下替代08中概念性的B.import_dataset等签名。A先在contracts中定义类型并提供合成fixture，再让B/C开始实现。函数不读环境变量、不持有HTTP请求、不直接写数据库。

```python
# analysis/service.py，B
def prepare_dataset(tables: RawTables, config: ImportConfig) -> PreparedDataset: ...
def analyze_dataset(data: PreparedDataset, catalog: Catalog,
                    context: RunContext, config: AnalysisConfig) -> AnalysisBundle: ...

# recommendation/service.py，C
def search_materials(catalog: Catalog, request: MaterialSearch) -> list[Material]: ...
def recommend_rules(analysis: StudentResult, catalog: Catalog,
                    context: RunContext, config: RecommendationConfig) -> RecommendationBundle: ...
def validate_recommendations(bundle: RecommendationBundle,
                            analysis: StudentResult, catalog: Catalog) -> ValidationResult: ...
```

RawTables：六张表各为list[dict[str,str|None]]，保留原中文列名和source_row_number。PreparedDataset：students、nodes、raw_records、selected_events、quality_issues、source_manifest。RunContext：run_id、dataset_id、catalog_version、rule_version。Catalog：version、topics、indicators、materials、links。A在contracts定义完整Pydantic类型，不能留下dict[str,Any]代替业务结果；原始source payload可用开放字典。

A服务处理上传、UTF-8/BOM读取、调用prepare_dataset、事务落库和快照文件。创建运行时从仓储恢复PreparedDataset/Catalog，调用analyze_dataset并保存。C只接收当前学生的StudentResult，不能拿全班数据后自行筛选。错误抛统一DomainError(code,message,details)，由A转成08错误包络。

工具包装器从服务端Context加载参数和结果，调用这些业务函数；D只通过HTTP访问。服务/工具/网页都不能复制一份统计实现。

## 五 智能体实际实现

ModelProvider采用Python Protocol：async generate(messages, tools, response_schema) -> ModelTurn。ModelTurn含text可空、tool_calls列表及usage可空。ToolCall含call_id、name、arguments。providers/unconfigured.py默认抛MODEL_NOT_CONFIGURED；tests中的ScriptedProvider只按预置顺序返回工具调用，用于验证循环，不用于正式界面冒充真实模型。

循环固定为：构造服务端上下文 → 装配角色提示和最近对话 → generate → 校验工具参数和范围 → 执行已注册工具 → 保存实际调用 → 回传工具结果 → 再generate → 最终结构/引用校验 → 持久化消息与结果。限制见09，重试也计入总时间和调用次数，禁止模型决定跳过最终验证。

学生与教师提示分开；学生材料和工具均经后台裁剪。C提供规则建议与生成提示；A将真实模型的结构化建议交给C验证。未提供模型API时，可完成工具库、循环、对话存储、错误显示及测试，但不能声称真实模型驱动的Agent已验收。

后台队列采用进程内queue.Queue和一个worker线程；jobs表先写queued再入队。worker拥有独立数据库Session，启动任务改running，结束改succeeded/failed。服务重启时未完成任务标failed PROCESS_RESTARTED，用户可重试，不假装自动恢复。Uvicorn仅单worker，演示时不开reload。此设计对应比赛本地单机负载，不承诺分布式任务能力。

## 六 双端初始化与启动边界

修正08中的首次导入闭环：POST /demo-sessions允许teacher不带dataset_id创建bootstrap会话，仅可列数据集/导入/选择已有数据集；选择后创建绑定dataset_id的新teacher会话。student必须带已存在dataset_id和student_id。新增GET /datasets提供本地数据集摘要；GET /datasets/{id}/runs提供运行摘要，供界面选择。

这些身份选择仅在DEMO_MODE=true且服务监听127.0.0.1时开放；学生可以通过演示选择器切换角色，所以它不是生产认证。会话中的学生数据限制和响应裁剪仍须测试，不能混用会话或泄露参考答案。

前端路由固定功能边界：/选择身份，/teacher/classes，/teacher/students/:studentId，/teacher/curriculum，/teacher/chat，/teacher/data，/student/home，/student/plan，/student/chat。D可自行调整视觉及内部组件，但保留这些入口职责。query key至少包含session、run、student/class、node；切换范围清理旧请求和对话。会话token仅存内存，刷新重新选择身份；对话持久化在后端。

开发端口后端127.0.0.1:8000、前端127.0.0.1:5173；Vite将/api代理给后端，前端只调用相对/api/v1路径。演示可由FastAPI托管frontend/dist并回退SPA路由，/api不参与SPA回退。

## 七 环境与命令合同

.env.example必须由A创建如下字段，模型四项保持空值：

```dotenv
APP_ENV=development
DEMO_MODE=true
DATABASE_URL=sqlite:///./data/app.sqlite3
DATA_ROOT=./data
OUTPUT_ROOT=./outputs
MODEL_PROVIDER=
MODEL_BASE_URL=
MODEL_NAME=
MODEL_API_KEY=
```

路径由config解析为仓库根目录下绝对路径，禁止依赖当前终端目录。根目录pyproject配置src包发现和dev依赖组，确保以下命令可用：

```powershell
# 首次依赖安装，A已提交锁文件后由队员执行
uv sync --frozen
Copy-Item .env.example .env
uv run alembic upgrade head
uv run python -m study_companion.cli seed-demo
uv run uvicorn study_companion.main:app --host 127.0.0.1 --port 8000

# 另一终端，仓库根目录
npm --prefix frontend ci
npm --prefix frontend run dev -- --host 127.0.0.1
```

Copy-Item仅首次且.env不存在时执行，不覆盖已有配置。seed-demo只加载tests/fixtures的合成小数据并明确标记，正式赛题通过上传导入；不能默默导入真实资料。数据库及模型配置不得发到GitHub。

```powershell
# A需要创建这些可执行检查入口
uv run pytest
uv run python -m study_companion.cli export-contracts
npm --prefix frontend run generate:api
npm --prefix frontend run typecheck
npm --prefix frontend run test -- --run
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

export-contracts无需启动HTTP，从app.openapi()和Pydantic模型生成文件；generate:api从该文件生成types.ts。CI重新生成后要求git diff --exit-code无差异，防止接口漂移。Playwright使用合成数据和启动好的服务，真实模型调用不进入CI。

## 八 开工顺序与并行门槛

A0（先合并）：项目骨架、锁文件、contracts类型与示例、数据库迁移、health、模拟会话、未配置provider、启动/测试入口。D在这个骨架分支提交前端初始化，A整合后统一合并。A0验收后B/C/D再从main各自开分支，不能四人从空目录各搭一套。

B1：prepare_dataset和修订/异常测试；C1：合成StudentResult到规则建议及验证；D1：按合成契约做双端页面；A1：服务编排与数据库仓储。之后整合B分析、C建议和真实界面，再做Agent工具循环及角色范围。

所有PR注明：实现本规范哪一项、改动路径、接口影响、运行的检查及输出。依赖锁文件、迁移和共享模型由A合并协调，D视觉样式无需A逐项审批。B/C不修改frontend，D不重写分析逻辑；发现契约缺口先提具体字段和示例再由A统一更新。
