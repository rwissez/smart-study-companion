## 1. 产品目标、边界与技术基线（G-01、G-07、E-01）

本产品是比赛用本地双端智慧学伴，完成理解学科、理解学生、理解教学三项赛题任务：课程要求与知识体系梳理；有依据的个人与班级学情分析；可执行、可调整的个性化学习方案。师生可通过 Agent 查询、解释与授权操作，学生可真实在线完成推荐题目形成反馈闭环。模拟学情仅能说明系统结果、证据与建议的合理性，不能证明真实教学成效。

采用模块化单体：一个 Python/FastAPI 后端、一个 SQLite/SQLAlchemy 数据库、一套 React/TypeScript/Vite 前端；数据处理沿用 pandas，Agent 沿用受控工具循环，模型采用可替换统一接口。保留原手册关于 uv/npm、锁文件、Pydantic、Alembic、测试、单机部署的适用规定。依赖具体版本以仓库锁文件核对为准；不擅自升级依赖、不引入微服务、独立图数据库、向量数据库或多智能体系统。当前不开发正式注册、复杂账号平台、分布式云部署、模型训练或无关教育平台功能。

## 2. 模块边界与唯一数据来源（G-02—05）

| 模块 | 输入/依赖 | 负责输出与行为 | 禁止职责越界 |
|---|---|---|---|
| 上传 | 教师授权材料 | 分类、原始文件、质量检查与调度 | 静默丢弃异常、伪造结果 |
| A | 课标、教材、题库、评分细则 | 正式知识体系、关系、题目和评分点关联及证据 | 推断学生掌握程度 |
| B | A 正式成果、有效作答及学习事件 | 学情统计、诊断、评分、进展、班级分析 | 自行另建推荐策略 |
| C | A、B 正式成果与学习历史 | 策略、题目、提示、审核、计划版本 | 创造未登记题目或改写 B 结论 |
| 数据库/仓储 | 各业务模块结构化成果 | 原始与正式数据、版本、日志、授权查询 | 覆盖历史、混合不同范围数据 |
| 导出 | 一致的正式成果及证据 | 可核对 ZIP | 重算另一份业务结果 |
| Agent | 授权上下文、业务工具 | 任务拆解、解释、授权修改与引用 | 绕过 C、权限或直接写库 |
| 公共模型服务 | 显式任务配置 | 统一供应商适配、结构化输出、故障报告 | 代替业务校验 |
| 公共流程调度 | 上传、学习事件、版本变更 | 按依赖触发、状态记录、异常处理 | 依赖聊天 Agent 决定固定流程 |
| Web 前端（D） | HTTP 接口 | 展示、操作、真实反馈 | 重复计算正式诊断、仅靠前端鉴权 |

A/B/C 可独立测试，核心业务逻辑与 HTTP、界面、数据库访问分离；服务负责装配上下文和持久化。共享模型为唯一字段定义来源，沿用现有契约和生成类型方式，禁止每个消费者各建一套字段。相同正式分析供页面、C、Agent、导出共同读取。工具不得维护另一套统计公式。保留原协议中字符串 ID、UTF-8 JSON、比例 0—1、缺失 null、带时区时间、引用范围、统一错误等语义；扩展和兼容细节由 01 定义。

## 3. 两条独立业务流程与状态（G-03、G-06；D-004、032—036、048、056—058、071）

### 3.1 首次处理与增量处理

1. 教师统一上传 → 程序识别材料及数据集范围，不确定时教师确认 → 保留原始文件及行记录 → 检查结构与数据质量。
2. 具备必要输入后程序调度 A → 发布可靠知识体系；依赖未解决异常的部分隔离。
3. B 使用 A 正式版本和有效数据生成初始个人及班级学情 → 持久化。
4. C 读取 A/B 正式版本生成个人学习方案 → 自动审核及有限修正 → 通过才正式发布，异常进入教师处理。
5. Web、Agent、导出读取对应正式版本。任务状态须反映实际执行情况。

上传可以包括 CSV、PDF 等系统明确支持的课程材料；具体支持格式、识别与兼容旧六 CSV 接口见 01。缺少前置输入时明确说明，禁止假成功。允许可靠独立部分继续处理，不允许消费尚未发布的候选成果。

### 3.2 学习反馈闭环

提交作答和提示事件 → 权限及任务范围检查 → 评分及证据检查 → 及时入库 → 一组任务完成（或异常提前触发）→ B 局部分析 → 更新班级受影响的汇总 → C 调整后续计划并审核发布。其他学生个人版本不变。已完成任务保留历史，正在作答题目不突然消失，未开始任务可调整。评分异常隔离，不作正式有效证据；不得将未评分当零分。

### 3.3 变更触发矩阵

| 变更 | A | B | C |
|---|---|---|---|
| 新教材 | 增量提取和关联 | 仅实际受影响时 | 仅实际受影响时 |
| 新题目 | 建立知识/评分点关联 | 通常不重算 | 更新材料候选范围 |
| 新课标 | 评估受影响目标和体系 | 受影响范围 | 受影响范围 |
| 修正已有题目或评分点关联 | 更新正式版本 | 受影响学生 | 依据新分析调整 |
| 修改前置关系 | 更新正式版本 | 无需默认重算 | 复查受影响计划 |
| 同义名称修改 | 更新必要展示信息 | 不因名称重算 | 不因名称重算 |
| 新学生学习事件 | 不运行 | 当前学生及相关班级，按触发条件 | 相应学生 |
| 教师调整学习计划 | 不运行 | 不因计划编辑重算 | 校验、版本、发布 |

具体影响识别、并发、事件去重、失败恢复由 01/06/08 规定。执行状态（等待/运行/成功/失败）、审核状态、发布状态独立；运行成功不是审核通过，审核通过不是任何版本均可发布。旧正式成果在新成果失败时可按明确适用范围保留并标记，不可假称已更新。固定流程无需聊天 Agent 可用。

### 3.4 Agent 交互流程

授权会话 → 识别任务与对象 → 装配上下文 → 自主拆解、选择工具 → 程序校验参数、查询范围和修改授权 → 执行 → 更新状态、收集证据 → 必要时继续调用 → 最终校验 → 回答或反馈已执行操作。复合任务可跨 A/B/C，不固定唯一调用顺序；所有写操作走业务服务。

## 4. A：课程知识体系（D-021—029、031—036）

- 输入课标主题与观察指标、教材、题库及评分细则。以主题/指标为基本框架，从教材补充有教学和诊断价值的细粒度知识点，不任意扩展课程范围。
- 复用文档读取及章节划分，模型逐章节提取知识点及原文证据；程序归一化、合并重复项，语义相似但名称不同的候选由模型结合来源判断，无法确认进入异常审核。保留别名与出处。
- 程序筛选同章节及有相关依据的跨章节候选，模型判断必要联系并给出证据，避免全量两两匹配。保留从属、衍生、合并创造、特例，新增明确的学习前置关系，与逻辑关系区分。
- 建立课程要求、题目、评分点到知识点的可靠关联，保留材料出处及定位。规则检查对象存在、重复、适用的循环依赖、引用真实性；独立模型复核语义、类型、合理性和证据充分性；有限修正后仍无法确定的异常交教师。
- 无法匹配时回查课标教材，补充有效遗漏知识后重试，仍不足标明关联不足；B 可依可靠课程指标分析，不做无依据细粒度判断。
- 可分批发布独立可靠成果，隔离异常及其依赖项。教师课程体系页查看正式成果、修改/通过/拒绝异常。历史版本保留，B/C 读取正式版本而非每次重跑 A。
- A 独立使用公共模型服务，不依赖对话 Agent。模型不可用时保留已有正式成果，暂停需要模型的新提取，不能冒充成功。

## 5. B：学情分析与评分（D-037—048）

- 原始记录不可覆盖。重复、冲突、修订、待评分、未作答、超范围分数及评分点异常按规则处置，保留出处及排除原因。原始数据、清洗结果、质量报告可核对；不可把缺失当零或未掌握。
- 双层分析：主题/观察指标用于整体评价及雷达图；知识点层用于细粒度诊断。综合有效得分/正确表现、评分点失分、提示依赖、可靠难度、有效作答覆盖等因素。不得仅凭分数或单次答对确定掌握。证据充分性与表现分开表达；证据不足或冲突必须明确。
- 规则输出结构化诊断、统计、分母分子、证据、限制及策略信号。模型组织易懂的文字，必要时辅助理解真实书面作答；不得改写数字、诊断依据或凭空推断错误原因。错误类型包括基础不足、步骤错误、提示依赖、迁移困难等，须有证据。
- 初始测验建立基线，近期有效证据适当提高权重，历史保留用于趋势。不同教学节点、难度、证据覆盖不可直接等同；比较需可比性检查。B 输出明显改善、有所改善尚未掌握、无明显改善或退步、证据不足四类变化及依据，C 决定后续策略。
- 班级输出整体情况、共性薄弱项、掌握程度分布、重点关注学生；保留无记录学生及有效人数、统计范围，不仅取平均。
- 在线作答评分：选择题规则核对；填空题规则匹配及等价表达检查；解答题模型按标准答案和评分细则分点评分。校验得分范围、分项总和、实际作答依据，有限重试；不可靠评分隔离。每题反馈与整组重分析区分。原赛事评分不由模型随意改写。
- 更新当前学生与相关班级，不重算无关学生。模型失效时保留确定性统计、规则诊断及模板表达，清楚标记降级。

## 6. C：学习策略、题目推荐与审核（D-001—004、014—016、020、043、045、049—055、065、068、071）

| 策略 | 适用方向 |
|---|---|
| 补充证据 | 证据不足，优先诊断性题目，不直接判定薄弱 |
| 补充前置知识 | 可靠证据表明基础或前置知识不足 |
| 错误纠正 | 具体错误类型和依据明确 |
| 巩固练习 | 初步掌握但不稳定 |
| 知识迁移 | 基础已掌握，需要综合应用 |
| 教师介入 | 多轮无改善、反复依赖高级提示仍不能独立完成等 |

规则决定策略、候选题、优先级、顺序与负担，允许组合策略。综合知识重要性、薄弱程度、证据、前置关系，按目标划分任务组，动态确定题量。题目与目标及难度匹配，考虑历史，优先未完成题，允许明确目的的错题重练，减少同组重复或过度相似题。只允许正式题库中的题目，包含教师编辑或 Agent 调整。模型辅助优化安排、文字建议、提示，不得绕过规则或虚构材料。

每题原则上三级提示：知识点、思路、关键步骤（不直接泄答）。使用层级和 Agent 额外帮助均记录供 B 使用。学生完成前只引导，完成后可查看授权讲解。

统一审核六项：学情依据、题目匹配、前置顺序、学习负担、提示有效且不泄答、材料存在且不重复。通过自动发布；可修正问题自动有限修正并复核；仍失败或确需判断交教师。系统自动生成/调整及教师通过 Agent 发起的修改须经 C 完整审核。教师在正式编辑界面直接修改时，仅强制执行身份权限、数据和版本、材料、历史、组件及答案保护硬检查，可知悉教学警告后直接发布，记录为人工确认。三条路径均留存版本、原因、历史和恢复记录。教师介入提醒带证据，不必停止学生全部学习。模型不可用时可靠规则建议可继续，无法可靠生成或审核的部分暂缓发布，标记实际生成方式。

## 7. Agent：任务、权限、证据与操作（D-001—002、005—014、017—020、059—060、064、070）

| 任务 | 教师 | 学生 |
|---|---|---|
| 学情查询与解释 | 允许 | 本人 |
| 班级学情分析 | 授权班级和可比较学生 | 禁止 |
| 课程知识与关系查询 | 允许 | 授权资料 |
| 学习方案查询与解释 | 允许 | 本人 |
| 学习方案修改 | 明确授权范围 | 禁止 |
| 知识讲解与解题引导 | 允许 | 允许，受答案保护 |
| 数据质量查询与解释 | 允许 | 禁止 |
| 学习进展与变化分析 | 允许 | 本人 |

- 任务范围之外拒绝执行；支持复合请求自主选择允许的工具。通用学科知识可以直接解释；具体学生、课程体系、诊断或推荐事实必须查询业务工具。不得推测缺失数据。Agent 不维护独立长期学生画像；对话历史维持当前上下文，长期事实从仓储查询。
- 提示词与程序双层约束，程序是强制边界。教师只能查授权班级；学生只查本人及允许资料；教师修改仅本次明确学生和内容。参考另一授权学生不等于获准修改该学生。明确单人操作可直接执行，含糊或批量请求先列对象和方案、确认后执行。多轮继承明确对象，但每次实际修改重新校验，切换对象不得沿用旧授权。学生不通过 Agent 直接修改或请求调整正式计划，靠作答反馈或线下教师处理。
- 班级学情、共性问题、证据解释、进展及授权学生比较沿用 B 正式成果。教师据此自行决定课堂策略。取消独立 class_strategy 任务及对应算法、工具、提示词、接口。批量个人计划可在固定名单和逐人差异经教师确认后按个人处理。
- Agent 将教师意图交 C；C 以 A/B 正式成果准备基础候选，Agent 每名学生最多提出一次合法优化反馈，C 决定选用、生成正式内容、按原发布路径完成审核和发布。教师可要求增加或调整微课堂。自动业务闭环无需等待 Agent。
- 工具受控注册、参数与范围检查；读取实际 A/B/C 结果，C 负责策略调整和验证。重要判断引用实际记录、统计、课程或材料，程序校验存在、版本、归属及权限，证据真实不代表语义必然正确。最终检查依据与结论，证据不足明确表达。
- 有限重试；数据缺失可寻找替代有效证据；关键步骤失败停止依赖步骤，保留独立成功部分并如实说明，不伪造操作完成。模型失败明确报告。
- 学生进行中的题目保护答案、评分细则及可直接泄答的信息；Agent 获得经授权的当前题目、已有作答、已展开提示，避免重复，提供动态引导；完成后按权限详细解释。学生可询问当前已发布微课堂。对独立尝试，先取得受助转换确认，再释放引导。三级提示与动态引导共用累积答案保护，实际帮助进入唯一学习事件账本。所有学生数据裁剪在后台执行，不能仅靠 UI。
- 前端展示真实工具进度（查询学情、查关系、调整、审核等），不展示模型内部推理、密钥、完整提示词或技术参数。轨迹持久化保存工具、结果、证据、错误；重要操作日志另记操作者、原始指令、对象、前后版本及审核结果。可撤销操作通过受控版本流程；普通问答不必记录同等详细写操作日志。
- 教师介入由 B/C 业务流程判断，Agent 解释，不持续后台监控。
