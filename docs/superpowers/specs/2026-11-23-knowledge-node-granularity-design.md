# 知识节点粒度与程序性能力设计

版本 0.1，2026-11-23。本文确定课程知识库第一版的节点粒度、节点类型、关系类型和人工审核标准。现有 `Catalog`、`Indicator`、`Material`、`CatalogLink` 以及 B/C 函数接口保持不变；本文定义的是它们之前的内部知识加工层。

## 一、目标

课程知识库需要同时表达：

1. 教材和课标中的核心概念、定义、性质与定理；
2. 学生需要独立掌握、能够练习和评价的程序性能力，例如解方程流程；
3. 知识点的关键词、来源片段、章节页码和相互关系；
4. 人工确认结果，以及智能体以后可以模仿的标注示例。

第一版不追求把每个术语、公式细则、操作动作和例题都建成节点。知识图谱必须保持可读、可审核、可用于分析和建议。

## 二、现有接口不变

- 现有 `Node` 继续表示 N01、N02 等测验或教学阶段，不能改为知识节点。
- 内部知识节点使用独立编号，例如 `K0001`。
- 内部节点最终映射到现有 `Indicator`、`Material` 和 `CatalogLink`。
- 内部丰富关系转换为现有 `CatalogLink.relation="prerequisite"` 或 `"supports"`；原始细分类别保留在内部关系记录和描述中。
- B 的 `prepare_dataset`、`analyze_dataset` 与 C 的 `recommend_rules`、`validate_recommendations` 签名不变。

## 三、层级

```text
主题/章节
  └─ 观察指标
       └─ 知识节点
            ├─ 关键词与别名
            ├─ 规则与公式细则
            ├─ 操作步骤
            ├─ 常见错误
            ├─ 例题与学习卡
            └─ 教材/课标来源片段
```

主题、指标和知识节点构成可检索结构。关键词、规则、步骤、错误和例题通常作为节点属性；只有满足独立能力标准的程序性流程才升级为节点。

## 四、节点类型

内部节点允许以下类型：

| 类型 | 含义 | 示例 |
|---|---|---|
| `concept` | 概念或对象 | 一元一次方程、不等式组 |
| `definition` | 可独立理解的定义 | 同类项的定义 |
| `principle` | 性质、定理或规则体系 | 等式的基本性质 |
| `procedure` | 可独立教学、练习和评价的完整流程 | 解一元一次方程的流程 |
| `strategy` | 跨多个步骤的解题或建模策略 | 用方程表示实际数量关系 |

单个机械动作不单独成为 `procedure` 节点。例如“移项”“去括号”“两边同除”通常是解方程流程的步骤或规则引用，除非教材和题目把它作为独立教学目标与独立评价对象。

## 五、节点准入标准

### 5.1 普通知识节点

候选内容至少满足以下四项中的三项：

1. 教材或课标有明确名称、定义或稳定描述；
2. 可以作为独立教学目标；
3. 能被一道或多道题独立观察；
4. 与其他节点存在明确的从属、前置、衍生、合并或特例关系。

### 5.2 程序性能力节点

解题流程、操作流程或策略满足以下全部条件时，可以成为独立节点：

1. 有明确目标状态，例如“把方程化为 `x=a`”；
2. 包含两个及以上有顺序或条件的关键步骤；
3. 学生可能出现流程性错误，而不只是某个概念不理解；
4. 可以通过评分点、解答过程或专项题目单独评价；
5. 能关联至少一个概念、性质或前置能力节点；
6. 教材、课标或团队审核记录中存在可定位依据。

“解方程流程”满足上述条件，因此作为 `procedure` 节点。其内部的移项、合并同类项、系数化为 1、检验等内容默认保存为 `procedure_steps`，不继续无限拆分。

## 六、降级为属性的内容

| 内容 | 保存位置 |
|---|---|
| 同义词、简称、教材不同表述 | `aliases` |
| 单个机械操作 | `procedure_steps` |
| 公式细则、条件限制 | `rules` |
| 常见错误和误解 | `misconceptions` |
| 具体题目、教材例题 | `materials` |
| 应用情境 | `application_tags` |
| 补充解释 | `notes` |

当候选节点没有独立评价方式、只在一个例题中出现、或只能重复父节点定义时，应合并或降级为属性。

## 七、数量限制

- 每个主题建议 3–8 个核心节点；
- 每个观察指标通常 1–3 个节点；
- 每个章节原则上不超过 10 个节点；
- 同一知识内容在多个教材片段中出现时只保留一个规范节点，其他片段作为来源证据；
- 超过上限时必须执行合并检查，优先把步骤、公式细则、例题和同义表述降级为属性；
- 第一版三个主题、九个指标建议控制在约 15–30 个节点。

程序性能力节点计入上述数量预算，不能以“能力”为名绕过粒度限制。

## 八、关系类型

内部关系允许：

| 类型 | 含义 |
|---|---|
| `part_of` | 知识从属 |
| `is_a` | 类型归属 |
| `prerequisite` | 前置能力 |
| `derives_from` | 由其他知识衍生 |
| `composes_to` | 多个知识或能力合并形成新能力 |
| `special_case_of` | 特例关系 |
| `supports` | 提供理解、练习或应用支持 |

`composes_to` 允许多个来源节点。例如“等式性质 + 合并同类项 + 去括号规则 → 解一元一次方程流程”。内部保存多来源关系；转换到现有接口时生成必要的 `prerequisite`/`supports` 链接。

## 九、候选节点记录

智能体或程序提出候选节点时至少输出：

- 标准名称与节点类型；
- 简短定义或能力目标；
- 关键词与别名；
- 所属主题和指标；
- 教材/课标文件、文件页、印刷页和证据片段；
- 可独立评价的题目或评分点；
- 前置节点和其他关系；
- 与已有节点的重复可能；
- 可信度及建议动作：保留、合并或降级为属性。

## 十、人工审核状态

候选节点只能处于以下状态：

- `candidate`：自动提取或待核对；
- `verified`：A 或指定审核人确认；
- `merged`：合并到已有节点；
- `attribute`：降级为父节点属性；
- `rejected`：没有依据或不属于本范围。

智能体不能自行把节点设为 `verified`。每次人工修改保留原候选、修改结果和审核说明，作为后续智能体模仿的示例。

## 十一、自动化边界

确定性程序负责 OCR、页码、版面切片、文件哈希、重复片段检测和结构校验。智能体负责候选知识点、别名、节点类型、关系和章节归属建议。A 负责节点粒度、来源证据、关系方向和 `verified` 状态的最终确认。

学生成绩、作答版本选择、分数统计和异常隔离继续由 B 的确定性逻辑处理，不由知识节点智能体决定。

## 十二、验收示例

以下内容应成为节点：

- 一元一次方程（`concept`）；
- 等式的基本性质（`principle`）；
- 解一元一次方程流程（`procedure`）；
- 用方程表示实际数量关系（`strategy`）。

以下内容默认不成为独立节点：

- “移项”作为解方程流程中的单步操作；
- 某一道具体例题；
- “方程求解”作为“解方程”的同义表述；
- 只在一个片段中出现、无定义且无法单独评价的术语。

审核一章时，若节点数量不超过 10、每个节点有来源依据、程序性能力有独立评价方式、重复概念已合并、所有关系有方向和依据，则通过第一版粒度验收。
